## 1. Bugs

### Critiques (P1)

*Aucun confirmé.*

Tous les hot paths sont protégés :
- `Parcel.obtain/recycle` dans `finally` (BetaProxyClient ×8, Phase4Verbs, Phase4Probes, ClusterMirrorManager, MirrorDaemon).
- `MotionEvent.obtain/recycle` dans `finally` (ClusterInputForwarder ET MirrorDaemon, fix P10/P11).
- Tous les Service/Activity ont `mDestroyed` (volatile) ou `isFinishing()/isDestroyed()`.
- Tous les `registerReceiver` ont leur `unregisterReceiver` symétrique sauf le cas process-scope documenté (P2-1).
- Tous les `Handler.postDelayed` ont leur `removeCallbacksAndMessages(null)` dans `onDestroy`.

### Majeurs (P2)

#### [P2-1] BetaProxyClient.java:582 — `registerReceiver` non apparié
- **Symptôme** : le receiver `ACTION_PROXY_CONNECTED` enregistré au premier `connect()` n'est jamais dé-enregistré. Réception multiple théorique si `connect()` est appelé plusieurs fois.
- **Repro** : impossible en pratique — le flag `sReceiverRegistered` gate la ré-inscription → pas de fuite réelle.
- **Fix** : ajouter doc-comment « process-scoped intentional » ; envisager un `unregister` dans une méthode `shutdown()` théorique. ~3 LoC.
- **Risque DL3 / DL5 / DL2** : zéro / zéro / zéro.

#### [P2-2] Platform.java — `isDiLink5(Context)` lit SharedPreferences à chaque appel
- **Symptôme** : appel I/O SP à chaque hop (`applyDl5LayerStackOverride`, `applyDl5DisplayIdOverride`, `isAutoDetectedDiLink5`, etc.). Le doc-comment dans la classe admet le besoin d'un cache.
- **Repro** : non observable visuellement (SP cached in-memory par Android) mais évitable.
- **Fix** : `private static volatile Boolean sCachedEffective` invalidé par `setOverride()`. ~10 LoC.
- **Risque DL3 / DL5 / DL2** : zéro / zéro / zéro (logique identique).

#### [P2-3] ClusterInputForwarder.java:146-159 — allocation par event tactile à 60 Hz
- **Symptôme** : `injectTouchAtMulti` alloue `PointerProperties[N]`, `PointerCoords[N]` + N `new PointerProperties()` + N `new PointerCoords()` à chaque event. À 60 Hz pendant l'utilisation tactile, ~360 obj/s en jeune génération.
- **Repro** : Profileur Allocation Tracker pendant scroll Waze sur cluster.
- **Fix** : ThreadLocal arrays pré-alloués (taille max `MAX_PTRS=10`). ~15 LoC, pattern miroir à appliquer côté `MirrorDaemon.dispatchInputEvent` aussi (symétrie app ↔ daemon).
- **Risque DL3 / DL5 / DL2** : zéro / zéro / zéro.

## 7. Résumé exécutif

Codebase **mature et défensive**.

- **0 bug critique** confirmé.
- **3 majeurs** strictement perf/hygiène, tous corrigibles en <30 LoC sans toucher au protocole binder ni à l'architecture.
- **8 mineurs**, dont 1 dette utilisateur visible (P3-7 i18n).
- **0 code mort** confirmé.
- **Patterns défensifs systématiques** : `mDestroyed` flag, `isFinishing/isDestroyed` guards, `Parcel/MotionEvent.recycle` en `finally`, `removeCallbacksAndMessages(null)` en onDestroy, `AtomicBoolean` guards reflection (`sHiddenApisUnlocked`), `static volatile` pour cross-thread state.

La parité i18n (P3-7) est la seule régression UX directement perceptible.

Les 3 majeurs (P2-1, P2-2, P2-3) sont des micro-optimisations à effet cumulatif sur les hot paths ; aucun ne casse de feature.
