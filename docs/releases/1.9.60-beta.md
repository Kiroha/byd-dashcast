# 1.9.60-beta — Read the OEM RCC selection through Android

The cluster can work while its host-side `qtandroidnative` process is invisible
to the Android daemon. Diagnostic → Cluster Full Screen now has a separate,
read-only OEM RCC selection query through the researched Java Binder service.
It verifies the installed OEM APK and reports callback registration, native
return and selection independently, without searching for the host Qt process.

This action fixes that unnecessary dependency for querying the service. The
existing theme load/restore experiments still require their full renderer
identity checks; this release does not yet unblock theme loading on the car.
Selection callbacks are broadcast without a request nonce, so a received result
is an observation rather than exclusive request correlation. Native renderer
identity and physical pixels remain unknown.

Cluster and Reporting also offer **Send a diagnostic report**, opening the
existing report wizard with cluster receipts and logs. The configured reporting
channel, user consent and file-sharing fallback are retained. No automatic send
is added. New controls and explanations are translated in all 13 locales.

Build 699; ProxyDaemon protocol 33 is required for the new query. Earlier theme
operations, strict mutation/recovery checks, journal and RCC assets remain
unchanged. No vehicle operation or deployment was performed during development.
The independent static callback-owner proofs, full REA Evidence IDs and exact
scope are documented in [the query contract](https://github.com/Kiroha/byd-dashcast/blob/v1.9.60-beta/docs/CLUSTER_READ_ONLY_RCC_QUERY.md).

Install this beta over the existing app, without uninstalling it, then reconnect
the updated ProxyDaemon (protocol 33). Open **Diag → Cluster Full Screen →
Consulter le RCC OEM (lecture seule)**, wait for the result, then use **Envoyer un
rapport de diagnostic** on that page. The same report shortcut is in Reporting.
The report assistant uses your configured channel or offers file sharing.
DashSat 0.9.9-dev remains compatible; 1.9.0 remains the stable release.

Local verification passed: **1,746 JVM tests across 283 suites**, with no
failures, errors or skipped tests; debug and signed release builds; debug/release
lint with **0 errors and 31 existing warnings** each. The optimized APK retains
the new helper's executable static `main(String[])`, and the native bootstrap
check passes. The packaged RCC assets are byte-identical to the preceding beta.
The new mapping is archived and all 69 prior mapping archives retain their hashes.
The staged APK passed the archive/credential-pattern, package/version and signer
checks. Physical cluster behavior and Telegram receipt on the car are untested.
