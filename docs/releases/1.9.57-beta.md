# DashCast 1.9.57-beta

**Test a native QML background across the cluster canvas.** Diag now includes
**Test full cluster theme — night + Full (experimental)**. On an admitted runtime,
the new carrier replaces three OEM background decorations with a dark native
background, cyan frame, four corner marks and **DASHCAST TEST**. The OEM instrument,
ADAS and warning code retains its existing layout and behavior; physical visibility
and legibility remain unvalidated. This is a composition experiment, not the finished
concept dashboard or proof of exclusive physical-screen control.

The graphics appear only in native power ON, Full navigation and night mode. Select
Full navigation and night mode manually before loading; the action does not force
either mode. Other modes retain the original decorations. While active, the dark
background deliberately covers the projected map behind it. Its frame follows OEM
root geometry, including existing scaling and offsets; the logical corners are not
proof of the physical panel's exact edges. Existing foreground layers can cover parts
of the drawing, and transitions can temporarily retain an older frame.

To test, keep the vehicle parked and the central display available:

1. Explicitly connect the updated ProxyDaemon, which must report **protocol 32**.
2. Select Full navigation and night mode, then press **Test full cluster theme — night + Full (experimental)** and confirm **Load test theme**.
3. Check the physical cluster. Use **I can see DASHCAST TEST, four cyan canvas corners and readable OEM instruments** only if you observe that result. The older passive-marker observation is separate.
4. Use **Restore original cluster selection**, then confirm the OEM display visually with **I can see the original OEM cluster again**.

The daemon also requests restoration after 30 seconds while it remains alive. This
does not guarantee physical recovery. ACKs, a selected-path query, timeout or carrier
removal do not establish restored pixels. **Reboot alone is not assured rollback**,
because BYD persists the RCC selection. Uncertain completion remains quarantined;
another load is blocked until recovery is resolved.

Both experiments share the existing worker, journal, helper and restoration lane.
The passive marker and its operations remain compatible with protocol 31; the new
theme and its observation use closed protocol-32 operations. Exact live renderer,
OEM Java bridge, mapped-resource and carrier identity checks remain mandatory against
the researched SX326 firmware **13.1.33.2602030.1**. A build label alone does not admit
a different runtime. Refusals now retain their preflight phase and failing artifact
evidence in the bounded historical report cache. This release adds no SX361 hash
allowance, arbitrary theme loader, permission bypass or automatic mode switch.
See the [full test procedure and limitations](https://github.com/Kiroha/byd-dashcast/blob/v1.9.57-beta/docs/CLUSTER_FULL_SURFACE_TEST.md).
