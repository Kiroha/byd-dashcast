# 1.9.82-beta — Guided full-screen map test with BYD instruments

**Install this signed release APK manually over DashCast, without uninstalling
or clearing application data. Check version 1.9.82-beta / build 722 in the app.**
The stable release remains 1.9.0. This build refreshes persistent daemons; the
full-screen test requires the connected ProxyDaemon to report protocol **47**.

## A new, visual Diag page

**Diag → Full-screen cluster** has been rebuilt from scratch as one guided page:

- A drawing of the cluster shows what you should see at each step: BYD display,
  theme loaded, full-screen map, or attention needed. A badge gives the state.
- Five steps — **Check → Load → App → Full screen → Finish** — with one large
  main button and at most two secondary buttons.
- Each step says what happens and what the cluster should show.
- Every action that changes the cluster opens a confirmation listing what will
  happen and what you should see. Two assertions must be ticked first: the car
  is stopped in P with the parking brake applied, and this is the intended
  cluster (DashCast still checks its exact version before any change).
- **Tell what I see** offers three illustrated answers: the map with BYD
  instruments, nothing changed, or black screen / "Simple mode" / abnormal
  display. Only the first one is recorded. The last one opens the return to the
  BYD display.
- The red **Back to the BYD display** button stays at the top of every Diag
  page. Technical details stay folded at the bottom of the page.

## The full-screen profile keeps the BYD instruments

The new carrier `fullscreen_instruments_21f7735c.rcc` (SHA-256
`f8c0d5df43b207258d470b389648ef400cf2bd179205af39dce4849749c468ba`) keeps the
factory roots and all 84 stock translation resources. It changes only three
decorative layers, and only in full projection mode on the 1920 × 720 cluster
with power ON and start-up completed:

- the BYD background and terrain images become transparent;
- the decorative head line and the backdrop behind the battery/range data are
  removed.

The selected application then fills the whole cluster, while **BYD telltales,
ADAS alerts and messages, speed and gear (P/R/N/D) stay drawn above it**. In any
other mode, or when a value is unknown, the BYD display is unchanged. Unlike the
1.9.81 profile (2c), no BYD instrument or alert is hidden. It is still a
stationary test profile, not a road-use theme.

Loading keeps the existing guards: the exact `21f7735c` installed cohort,
positive DiLink 3 / Android 10 detection, both assertions and a 1920 × 720 panel.
Small panels are refused.

## Older tests removed from the page

The corner marker, the read-only OEM query, the dashboard, full-app and minimal
(2c) full-screen loads, the native BYD projection test with bands and the
experimental-theme file check are no longer offered. Their buttons, texts and
interface code are gone. A session left by any of them is still recognised and
finished through **Back to the BYD display**: file move, single `fission-all`
restart, native-mode return and the final "Is the BYD display back?" question,
which can now be answered again from the page.

## Fix

In 1.9.81-beta, **Load full-screen theme** (2c) failed inside the app before
anything was sent to the daemon: operation 30 had no internal name. No vehicle
command was issued. Operations 30 and 31 are now covered.

## Test scope and limits

**The new profile has not been validated on a vehicle.** Test only while
stationary, in P, with the parking brake applied and a suitable test context,
with **Back to the BYD display** ready. No vehicle write or command was issued
while preparing this release.

DashSat pairing, guidance and video protocols are unchanged.

## Verification

- Generator tests pass (5/5): closed loadable identity and bounded size, all 84
  locale resources byte-identical, only the three decorative opacity lines
  changed, strict full-projection condition and matching review checksums.
- The Qt 5.15.2 bench compiles the added bindings under both factory import
  headers. Opacity reaches 0 only with power ON, full projection, 1920 × 720 and
  completed start-up; nine unknown or other states and a resized root keep the
  stock display.

  buttons; the load, start and observation confirmations (both assertions, the
  exact asset through operation 31, a single operation 20, operation 22 only for
  the map answer); the abnormal answer opening the return without any command;
  and the native return, restart and retirement recovery paths.

  belong to the known POSIX-only baseline (shell, file attributes, line
  endings). The complete suite and full lint were not rerun on a POSIX machine.
- The signed, optimized release build passed fatal lint, the WebRTC archive and
  native bootstrap gates and the release-asset scanner. The APK is
  non-debuggable, displays **1.9.82-beta / build 722** and carries DashCast's
  usual certificate (SHA-1
  `27:19:6E:38:6B:87:5E:76:AD:F7:00:E7:EA:84:E4:C6:EE:E3:3D:FA`), so the update
  installs over 1.9.81-beta.
