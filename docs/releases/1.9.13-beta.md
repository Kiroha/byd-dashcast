# DashCast 1.9.13-beta — Satellite connection and device identity

Code pairing could save a valid profile while the persistent guidance connection
never opened. The explicit empty WebSocket subprotocol list rejected ordinary
HTTP upgrades in both applications. This build accepts the normal no-subprotocol
upgrade; install **DashCast Satellite 0.4.0-dev** for the corresponding client fix.

**Vehicle APK: versionName `1.9.13-beta`, versionCode `652`.** Install over the
existing vehicle application without uninstalling. Existing pairing credentials
and the receiver certificate remain valid. Preserve the background pairing fix
and formatted native-guidance distances included in 1.9.12-beta.

## Connection and identification

- Show the same public **DashCast ID** in the vehicle and the companion's saved
  profile. TLS continues to verify the complete certificate fingerprint.
- Show the currently authenticated Satellite's device label, installation UUID
  and local address. While offline, explicitly label the previous connection and
  its date. Profile transfer alone does not establish a live connection.
- Optional `hello.device` metadata is additive to protocol v1. Older senders and
  malformed optional metadata appear as an unknown device. Names and UUIDs are
  sender-reported display information, not a separate authentication factor or
  proof of exclusive pairing. The existing revoke action clears history and
  invalidates the shared token; it does not revoke individual devices.
- A receiver that fails to become ready within twenty seconds reports unavailable.
  Linkage failures no longer disappear into an executor task while the screen
  remains at Starting. Startup logs contain fixed stage labels and exception
  classes only. Late TLS initialization cannot restore a failed or disabled start.

Device labels are localized in all thirteen receiver languages. The companion
also prioritizes the hotspot gateway, shows the attempted car address and last
connection issue, and provides Android restricted-settings instructions.

## Retest in the vehicle

1. Update both applications and keep the Tbox connected to the vehicle hotspot.
   Compare the saved DashCast ID with the ID on the vehicle's Satellite page.
2. In Satellite, enable notification access. If Android denies it as a restricted
   setting, open App info → ⋮ → Allow restricted settings, then enable notification
   access. The reported Tbox restriction has been lifted by the user; the actual
   notification-listener grant still needs confirmation.
3. Enable **Use satellite guidance** and the desired output in DashCast, press
   **Start** in Satellite and start a route. Verify authenticated connection,
   current device identity and fresh physical guidance independently.
4. Stop the route and reconnect Wi-Fi. Old guidance must clear and new valid
   guidance must resume. If receiver startup fails, its fixed startup-stage logs
   now distinguish failure from an indefinitely pending start.
