# DashCast 1.9.21-beta — Satellite roundabouts and parked music cleanup test

Keep Satellite guidance active for a recognized clockwise or counterclockwise roundabout
when its exit number is genuinely absent. Previously that source snapshot was unsupported
and stopped guidance. The receiver now negotiates generic roundabouts with DashSat, preserves
the observed circulation and existing traffic-side preference, and sends a generic native
cluster glyph without inventing an exit. Numbered exits retain their existing validation.
No unverified generic CAN/HUD glyph is introduced; DashCast attempts to clear previously
owned CAN guidance before switching to the generic native frame. Failed physical cleanup
remains uncertain and requires vehicle validation.

**Vehicle APK: versionName `1.9.21-beta`, versionCode `660`.** Install this release APK
manually over the existing DashCast application without uninstalling. The package, usual
platform signature, saved settings, pairing and pinned TLS identity are preserved.
**Use DashSat 0.9.0-dev on the Carlinkit/Tbox for the new generic-roundabout support.**
DashSat 0.8.0-dev remains compatible for its existing guidance and video behavior.
Both applications must be updated to use the new capability. No new pairing is required.
1.9.0 remains the stable release.

## Parked music cleanup test

The separate music bench in **Diag** now clears its test text and sends the documented
instrument music **STOP** state after its six-second test or cancellation. This tests
whether the waveform icon also disappears on the installed instrument firmware.
The operation stays bounded to the connection and acquisition owned by that test. A
failed text clear does not prevent its one STOP attempt while ownership remains current;
either command failing still reports cleanup failure. Diagnostics retain each command's
acceptance or failure instead of replacing a failed clear with “nothing to clear”.

Disable automatic cluster music before opening the bench, acknowledge that the vehicle is
parked, select a test format, and observe the title and waveform after cleanup. An accepted
SDK command is **not** confirmation that the title or icon disappeared visually.
Automatic MediaSession output keeps its established **PAUSED** cleanup until the STOP
probe is confirmed on the relevant firmware. This is an instrument display command, not
a command to stop or pause the Android music player.

The three title formats compare width only. They remain centered by the OEM theme.
**This release does not move the music title to the right or resolve overlap with guidance.**
Production music remains visible during guidance. Bench labels are updated in all 13
application languages. No route, notification, music title, token or pairing code is added
to the passive diagnostics.

## Validation and vehicle limits

Publication checks passed: **1,124 JVM tests across 198 suites**, release lint with **zero
issues**, debug and optimized release assembly, **16 receiver JavaScript tests**, **13 relay
tests**, and **35 release-scanner tests**. Guidance/pairing hashes and exact pinned fixture
parity match DashSat. APK identity, non-debuggable configuration, the usual signing certificate,
the trusted default-branch scanner and the release contract scanner pass. The matching R8
mapping is frozen with this APK.

The **exact frozen optimized APK** also passed Android 10 / API 29 ART and pinned-WSS checks
on an isolated stock emulator: AndroidKeyStore migration/signing, wrong-pin and wrong-token
rejection, authenticated connection/reconnection and owned-listener shutdown. These checks
establish Android runtime behavior, not the vehicle's OEM display behavior.

Generic roundabout rendering, transitions from numbered guidance and physical HUD cleanup
remain to be validated on the vehicle with DashSat 0.9.0-dev. The parked STOP probe's effect
on the waveform icon also remains unverified. Local checks do not establish OEM rendering,
hardware video decoding, latency or CPU/GPU savings.
