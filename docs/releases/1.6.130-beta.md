# DashCast 1.6.130-beta

Reliable automatic Layout ownership and DiLink 3 application launch recovery after 1.6.129-beta.

> This is a tester pre-release from `switch-kotlin`. It is not merged into `main` and is not the repository's Latest release.

## Highlights

- Automatic favourite Layout now has explicit priority over a standalone application's **Auto-launch at start** setting.
- A sole saved Layout containing bound applications is automatically repaired as the favourite when the user omitted that final step.
- Returning from Settings or Layout Manager immediately re-evaluates Layout auto-start; restarting DashCast is no longer required.
- DiLink 3 recovers from the `ActivityStack.getBounds()` FREEFORM-stack crash by removing the newly created zombie stack before a plain launch.
- The misleading "not installed or incompatible with multi-display" message has been replaced in all 13 locales with an accurate cluster-launch failure message.

## Full changelog since 1.6.129-beta

### Field evidence and root causes

- Analysed `INC-20260717-122902` and `INC-20260717-175749`, both captured on DiLink 3 / Android 10 with Waze configured for standalone auto-launch.
- Both reports showed the classic `ClusterService` pipeline starting Waze on display 1 and no `FissionOrchestrator` automatic Layout activation.
- The captured Layout Manager still showed an unsaved **New layout**, while the existing startup guard required all of the following before Layout was allowed to own startup:
  - Layouts/Fission mode enabled;
  - Automatic favourite Layout enabled;
  - a saved, resolvable favourite Layout.
- When the favourite was missing, stale, or not yet saved, DashCast silently treated Layout auto-start as disabled and allowed the standalone Waze auto-launch to start classic projection instead.
- Waze was installed and correctly resolved to `com.waze/.FreeMapAppActivity`; the old incompatibility Toast was factually incorrect.
- The classic DiLink 3 launch failed because system_server threw a `NullPointerException` from `ActivityStack.getBounds()` while creating a FREEFORM stack on display 1.
- `launchAndForce` removed the old empty split-screen stack before launching, but the failed FREEFORM attempt immediately created a new poisoned empty stack. The old flow then repeated the same FREEFORM attempt and finally tried a plain launch without removing that newly created zombie.

### Automatic Layout ownership and precedence

- Layout startup ownership now depends on the user's intent, not on whether every saved-layout prerequisite is already complete:
  - **Layouts mode ON + Automatic favourite Layout ON** means Layout owns startup;
  - the standalone **Auto-launch at start** package remains deferred and cannot create a competing classic projection;
  - when Automatic favourite Layout is OFF, the standalone package keeps its previous classic auto-launch behavior.
- The same ownership predicate is shared by `MainActivity`, `BootReceiver`, and `ClusterService`, preventing different entry points from choosing different startup modes.
- BootReceiver and MainActivity calls are serialized through the process-wide one-shot lock, so they cannot create two headless Layout orchestrators concurrently.
- The pending standalone auto-launch package is preserved rather than consumed while Layout owns startup. Disabling automatic Layout later can therefore restore the standalone behavior on a subsequent evaluation.

### Favourite Layout recovery and live re-evaluation

- Added a deterministic automatic Layout selection policy:
  - an explicit saved favourite containing at least one bound app always wins;
  - if the favourite is missing or stale and exactly one saved Layout contains bound apps, that Layout is selected and persisted as the repaired favourite;
  - if multiple usable Layouts exist, DashCast does not choose arbitrarily and still requires an explicit favourite;
  - unsaved or application-free Layouts cannot be launched automatically.
- `MainActivity.onResume()` now re-evaluates automatic Layout startup. Saving or favoriting a Layout and returning to the main screen starts it immediately without a process restart.
- When automatic Layout is requested but no unambiguous saved Layout can run, DashCast shows the existing translated "Save the layout before setting it as favourite" guidance instead of launching the wrong standalone package.
- Projection timeout, daemon failure, or Layout activation failure now re-arms the one-shot and gracefully cleans any partial slots, allowing a later retry.

### Headless vehicle-start behavior

- A fully headless Layout launch at vehicle startup still intentionally requires the general **Automatically start projection on startup (Auto-Boot)** preference.
- With Auto-Boot enabled, Layouts mode enabled, Automatic favourite Layout enabled, and a saved usable favourite, BootReceiver activates projection and launches all bound apps without opening DashCast.
- **Pre-create slots on startup** remains optional. It prepares Virtual Displays but does not decide startup ownership and is not required for automatic app launch.
- The vehicle ROM must still permit DashCast to receive its boot/autostart entry point.

### DiLink 3 FREEFORM-stack recovery

- Added exact classification for the BYD framework failure observed in both incidents:
  - `ActivityStack.getBounds()` null dereference;
  - or `ActivityStack.onConfigurationChanged` plus `NullPointerException`.
- Once that failure is conclusive, DashCast skips the duplicate bare-MAIN launch with the same `--windowingMode 5` option.
- Before the plain fullscreen fallback, DashCast now executes `cleanFissionStacks(displayId)` again to remove the zombie created by the failed FREEFORM attempt.
- The required recovery order is now:
  1. detect the FREEFORM framework failure;
  2. clean the poisoned display stack;
  3. launch the resolved application without `--windowingMode`;
  4. poll for the resulting task;
  5. continue the existing placement, resize, focus, and watchdog sequence.
- The same clean-before-plain recovery applies when an `am start` transcript looks accepted but no task appears.

### Accurate user-facing failure reporting

- Renamed the misleading `toast_app_incompatible` resource to `toast_app_launch_failed`.
- Updated normal and split launch call sites.
- Updated all 13 supported resource sets: French base plus Arabic, Belarusian, German, English, Spanish, Italian, Kazakh, Polish, Russian, Turkish, Ukrainian, and Uzbek.
- A genuine terminal failure now reports that the cluster launch failed and directs the tester to the Log; it no longer claims the installed application is missing or incompatible.

### Regression coverage

- Added `LayoutAutoStartPolicyTest` coverage for:
  - Layout ownership before favourite readiness;
  - explicit favourite selection;
  - sole usable Layout repair;
  - ambiguous multiple Layouts;
  - unsaved, empty, or unbound Layouts.
- Added `TaskLaunchRecoveryTest` coverage for:
  - the exact WindowManager NPE transcript from the incidents;
  - successful `am start` classification;
  - mandatory `clean -> plain launch -> task poll` ordering.

### Compatibility and rollback

- Minimum Android version remains API 28; target SDK behavior remains unchanged.
- No permission, dependency, manifest entry, Binder transaction, or proxy protocol version changed.
- Standalone auto-launch behavior is preserved when Automatic favourite Layout is disabled.
- Pre-create-slot behavior is unchanged.
- Functional commits:

  - `8835003` — `fix(cluster): recover DL3 launch after freeform stack NPE`.

## Suggested tester checks

- Save a Layout with Waze and NewPipe bound to zones, mark it as favourite, and enable Layouts mode plus Automatic favourite Layout.
- Leave Waze's standalone **Auto-launch at start** enabled and confirm that the Layout still wins without a classic-projection conflict.
- Enable general Auto-Boot, restart the vehicle, and verify that the favourite Layout and all bound apps appear without opening DashCast.
- Disable general Auto-Boot, open DashCast manually, and verify that the same Layout starts on app launch.
- Save exactly one usable Layout without explicitly marking it favourite, return to Main, and verify automatic favourite repair and launch.
- Leave a Layout unsaved and verify that DashCast asks for it to be saved instead of starting standalone Waze.
- Launch Waze through the classic path on the affected DiLink 3 ROM and verify that the FREEFORM NPE recovers through a clean plain launch rather than leaving a black cluster.
- Repeat Layout startup with pre-created slots enabled and disabled.
