## Local Maps guidance

The giino01 field report showed that left/right images reached the cluster, while
other image-only maneuvers were dropped before OEM delivery. Analysis of the
supplied Maps Morphe APK `26.33.02.961351034` identified the SVGs and reflections
used to build navigation notifications. They provide references without requiring
a separate vehicle capture for every maneuver.

- Recognize **38 audited image forms**, including straight guidance, U-turns,
  slight/sharp turns, merges, arrivals and roundabouts in both circulation
  directions. Preserve the existing field-validated left/right matcher.
- Compare the highlighted path separately from the dim roundabout ring, and
  include both in notification deduplication. This distinguishes maneuvers whose
  outer silhouette alone is insufficient.
- A roundabout image identifies direction, **not its exit number**. Use an
  ordinal from 1 to 10 only when the same notification explicitly supplies it.
  Otherwise send an unnumbered roundabout; do not reuse a previous exit number.
  Concrete text maneuvers keep priority, and unknown or ambiguous images remain
  subject to the conservative matcher. Some shapes share a coarse existing
  maneuver variant rather than encoding an exact exit angle.
- Preserve independent HUD/cluster choices, route expiry, the background listener
  and the existing OEM output paths. The APK is used for offline reference
  generation; DashCast does not load it at runtime.

This corpus is based on the supplied Maps 26.33 APK. Other Maps versions and
unrecognized image forms are not guaranteed. **The new image matcher is in the
vehicle application; Satellite 0.2.0-dev still does not extract image-only
maneuvers or implement video capture.**

## Satellite connection and guidance indicators

Open **Settings → Navigation guidance → Satellite device**.

- Connection: gray **Receiver disabled**, a startup state while binding, orange
  **Waiting for satellite**, green **Satellite connected** after successful
  authentication only, or red **Receiver unavailable** after a startup failure.
  An enabled switch, saved profile or unauthenticated socket never means connected.
- Guidance: **Disabled**, **Waiting**, **Active** after valid recent data, or
  **Expired** when it exceeds the protocol deadline. Connection alone does not
  mean guidance is available, and receipt does not prove physical OEM rendering.
- Refresh automatically while the page is visible and immediately on return,
  including disconnect, source loss, expiry and revocation. Receiver work continues
  independently in the background.
- Each state has an icon and accessible label, respects the day/night theme and
  is translated into all **13 app languages**. Indicators expose no token,
  pairing code, notification content or route text.

## Pair with DashCast Satellite 0.2.0-dev

1. Connect the Carlinkit/Tbox to the vehicle hotspot so both devices share the
   local network.
2. In DashCast's **Satellite device** page, enable the receiver and select
   **Pair a device**. Note the temporary six-digit code.
3. Switch to [Satellite 0.2.0-dev](https://github.com/Kiroha/dashcast-satellite/releases/tag/v0.2.0-dev)
   on the external device, choose **Pair with DashCast**, enter the code and
   confirm. The two-minute window survives switching between the interfaces.
   Generate a new code if it expires; use the advanced local car IP option if
   gateway detection fails.
4. Grant notification access to Satellite, select Maps or ABRP, enable satellite
   guidance and the desired outputs in DashCast, then start Satellite and a route.

For a SEAL without HUD, select **Instrument cluster** and disable **HUD**. Pairing
alone does not enable guidance or outputs. The existing pairing and pinned WSS
protocol are unchanged.

## Validation and vehicle checks

**Validation in the vehicle remains pending.** Offline tests do not certify
physical HUD/cluster glyphs, pairing through the vehicle hotspot, or ignition
recovery. Test the new maneuvers without first running a diagnostic HUD bench,
check clearing when the route stops, and capture a bug report during any failure.
Also check authenticated connection, guidance availability/expiry and reconnect
states on the Satellite page.

The final build passes **949 JVM tests in 180 suites**, with no failures, errors
or skipped tests; **10 JavaScript receiver scenarios** and **35 release-scanner
tests** also pass. Release lint reports **0 errors and 0 warnings**. Debug and
release assembly succeed. All 12 new status/accessibility labels are present in
the 13 app languages, and Welcome/Settings use the new application metadata.

Tests exercise independently rendered Maps fixtures and Android-resampled
bitmaps, unknown/ambiguous images, the production listener/router/native cluster
frames, explicit roundabout exits, existing left/right behavior, authenticated
connection transitions, revocation, expiry and immediate page return. The signed
release APK passes the trusted default-branch scanner for package/version,
non-debuggable manifest, the existing platform certificate and credential
patterns. Graphify is updated; existing parser warnings remain. Matching R8
mapping and checksums accompany the frozen build.
