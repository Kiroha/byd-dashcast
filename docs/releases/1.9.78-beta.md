# 1.9.78-beta — Android 13 task verification with legacy launch compatibility

**Install the signed release APK over DashCast without uninstalling or clearing
application data. This prerelease is version 1.9.78-beta / build 718.** The stable
release remains 1.9.0. ProxyDaemon protocol 44 is unchanged; the increased build
number refreshes persistent daemons. Verify that the running daemon reports
build **718** when testing this correction.

## Confirm the task before retrying

An Android 13 report showed a successful navigation launch on the cluster's
virtual display while DashCast's reflected task lookup returned no task. The
application was then stopped and restarted unnecessarily, followed by an
application-side fallback that Android refused. The report does not identify the
exact internal cause of that reflected lookup failure.

On **Android 13 / API 33 only**, a non-positive lookup can now be corroborated
with one bounded, read-only activity dump. A match requires an exact package,
task, display and user-0 identity in complete recognized output. Ambiguous,
contradictory, truncated or failed observations remain unknown. A successful
shell response alone is never accepted as proof of placement.

The post-launch check and final client verification use the same confirmation
path. Cheap task polling and the watchdog do not repeatedly capture dumps. An
unknown placement no longer authorizes the late destructive retry or the
application-side fallback. Cancellation and current-request checks remain active
before later placement actions. Additional eviction landing probes stop when
their shared waiting budget is exhausted; the initial safety lookup is retained.

## Preserve the DiLink 3 path

The new dump corroboration is **not enabled on APIs 28–32**. Their existing typed
task query continues to supply found, absent or unknown results without a new
dump. The original explicit cross-display placement sequence remains available
for a uniquely identified task; its final destination must still be verified.

An explicit failed start on the legacy path performs one immediate typed lookup
before the plain-launch fallback, preserving the earlier recovery timing rather
than adding the Android 13 polling delay. A genuine unknown result cannot
authorize another destructive launch on any platform.

The existing SX361 empty-primary recovery retains its exact firmware, user,
display, capability, current-request and original-primary checks. Regression
tests exercise the legacy absence, plain framework failure and confirmed
recovery path without invoking the new strict dump parser. Multiple or unreadable
task identities are not converted into an arbitrary successful match.

## Compatibility and recovery limits

This prerelease retains the 1.9.77-beta read-only OEM consultation, recovery
journals, historical quarantine and retired experimental-profile restrictions.
It introduces no new vehicle command, privilege, ADAS masking rule or transport.

Host tests do not prove physical cluster rendering or compatibility with every
DiLink 3 or Android 13 firmware. Stationary vehicle validation remains necessary,
including navigation launch, explicit Stop, restoration of the OEM display,
ACC sleep/wake and the supported SX361 recovery case. Do not uninstall, clear
data or delete recovery state to bypass a guard. No vehicle commands were
executed during development or release preparation.
