# DashCast 1.9.48-beta

Fix a Satellite video crash that closes the preview when WebRTC submits an encoded image to the
hardware decoder. The pinned native SDK deliberately passes null for optional `DecodeInfo`.
The Kotlin wrapper previously required a non-null value and threw before reaching its error handler;
the exception crossed JNI and aborted the app. The wrapper now accepts the optional value and forwards
it unchanged to the SDK decoder.

Hardware-only H.264 selection, borrowed texture delivery, source/session fences, decoder error
handling and release ownership remain unchanged. No software decoder, codec fallback, system WebView
update, protocol change or new permission is introduced. The previous cluster slot recovery and
bounded diagnostic collection are retained.

Regression checks call the real Java `VideoDecoder` interface with null metadata after successful
initialization, verify image and non-null metadata identity, and exercise terminal errors, thrown
decoder exceptions, stale/uninitialized/released guards and late callbacks. Optimized release and
independent runtime validation are recorded separately.

Install this APK over the existing DashCast application without uninstalling. **DashSat 0.9.9-dev
remains compatible and does not need an update for this fix.** While parked, start a fresh sharing
session on the Tbox, return to DashCast and open the preview. Actual hardware frame rendering,
latency, CPU/GPU use, thermal behavior and Overdrive coexistence still require vehicle validation.
The crash diagnosis establishes an invalid JNI boundary contract, not those performance results.

**1.9.0 remains stable.**
