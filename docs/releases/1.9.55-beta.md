# DashCast 1.9.55-beta

**Try a real OEM QML root reload from Diag.** The new **Change physical cluster — passive
TEST marker (experimental)** action attempts to load a firmware-bound RCC carrier through
the explicitly connected ProxyDaemon and the existing OEM Java/native service path. The
carrier retains the original root QML code and all stock translation resources, adding
only a passive **DASHCAST TEST** marker. Physical visibility, warning presentation and
compatibility have not been validated on a car. Stock content can hide the marker, so its
absence is inconclusive. This release does not implement the supplied concept dashboard
or establish total/exclusive control of the cluster.

Use this experiment only while parked, with Diag visible. Connect the current daemon
first, then select **Change physical cluster — passive TEST marker (experimental)** and
confirm the parked assertion. Before loading, the test checks exact live renderer and
OEM Java bridge identities against the researched SX326 firmware **13.1.33.2602030.1**.
Unknown, inaccessible or mismatching runtime evidence refuses the attempt. The assertion
does not detect vehicle movement, and compilation is not proof of OEM admission.

**Restore original cluster selection** remains at the top of Diag. The daemon also
requests default selection after 30 seconds while it remains alive, including if the app
closes. This is a request, not guaranteed physical recovery or an independent hardware
watchdog. Native results, selection responses and the tester's visual observations are
reported separately. A lost response or unresolved helper leaves the session uncertain
and blocks another test rather than replaying a load or overwriting another custom
selection. Confirm the original instruments visually after restoration.

**Reboot alone is not assured rollback:** BYD persists the selected RCC path. Removing
the owned carrier does not unmap an already registered resource. An unresolved recovery
requires investigation before another experiment. See the [experiment procedure and
limitations](https://github.com/Kiroha/byd-dashcast/blob/v1.9.55-beta/docs/CLUSTER_LIVE_MARKER_TEST.md).

The separate **Verify experimental theme (local only)** action validates the small
bundled fixture and reports app permission metadata. It does not load the physical
cluster. Existing projection, SurfaceDaemon and Satellite behavior are unchanged.

**Install the release APK manually over the existing DashCast application without
uninstalling.** The application displays **1.9.55-beta · build 694**. Normal startup
refreshes older persistent daemons to **proxy protocol 31**; explicitly connect the current
daemon before using the experiment. **DashSat 0.9.9-dev remains compatible and does not
need an update. 1.9.0 remains stable.**

Local validation passed: **1,679 JVM tests / 275 suites**, with no failures, errors or
skipped tests; the signed R8 release build; native WebRTC bootstrap declaration checks;
and release lint with **0 errors and 28 warnings**. Eight of those warnings concern the
new English diagnostic labels. The 44 release-tool fixtures and two independent carrier
preservation checks passed. The matching R8 mapping is archived outside the build
directory, and all 64 previous mapping archives retain their verified SHA-256 hashes.

The final APK passed the release archive/secret scanner, package/version checks and
verification of the expected platform signing certificate. Its optimized DEX passed
ART/TLS checks on an Android 10 / API 29 x86_64 software emulator, including authenticated
pinned WSS and reconnection. The new helper's named entry point also loaded on ART and
rejected invalid arguments before OEM admission. Native initialization and **56 optimized-wrapper assertions**
passed using the same pinned SDK's x86_64 library in a temporary test host. The publishable
APK was not modified. These checks do not validate its shipped ARM native libraries,
hardware decoding, OEM service admission or physical cluster behavior.
