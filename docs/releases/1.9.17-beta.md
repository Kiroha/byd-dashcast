# DashCast 1.9.17-beta — Satellite TLS and local media recovery

This pre-release fixes the encrypted Satellite connection on Android 10 and
recovers failed local media observation without restarting the navigation listener.
It includes the separately committed AndroidKeyStore correction and the latest
media recovery/report diagnostics change.

**Vehicle APK: versionName `1.9.17-beta`, versionCode `656`.** Install over the
existing DashCast app, **without uninstalling**, to preserve settings and the
pairing token. Publication continues from `feat/hud-2.0`;
**1.9.0 remains the stable release**.

## Satellite connection on Android 10

The supplied DiLink 3 / Android 10 / API 29 reports showed successful receiver
startup followed by a TLS signing failure: `Incompatible digest` from
AndroidKeyStore. The old installation key did not permit the raw signing operation
used by API 29 Conscrypt. A ready listener and successful pairing alone could not
establish a working encrypted control connection.

- Prepare a new, immutable v2 signing identity with the required digest and
  padding authorizations, keeping the original v1 key intact. No decryption
  purpose, certificate-trust exception or token rotation is added.
- Check the actual provider signing operation and certificate/private-key match
  before publishing a pairing fingerprint or preparing TLS.
- Present only the advertised certificate, even while the old and new aliases
  coexist. An unusable existing v2 identity fails closed; it is not silently
  regenerated or replaced by a different certificate.
- Keep a migration notice until a new authenticated Satellite connection succeeds.
  Previous connection history remains historical information.

**If DashCast was using the old v1 identity, its certificate and receiver ID change.
Pair DashSat again using DashCast's Pair a device button.** Install this update
without uninstalling either app. A device already associated with a working v2
identity does not need a second certificate migration.

Compatible with **[DashSat 0.6.0-dev](https://github.com/Kiroha/dashcast-satellite/releases/tag/v0.6.0-dev)**.
Six-digit pairing and guidance **protocol v1 remain unchanged**; no new companion
release is required for this receiver correction. Connect the Tbox to the vehicle
hotspot and enable the receiver and **Use satellite guidance** in DashCast.
Notification access must be granted on DashSat. Authenticated WSS control,
observable fresh guidance and video remain separate states.

The Android 29 ART startup optimization fix, IPv4 hotspot selection, bounded
connection retries and pairing countdown behavior are retained. **Continue on
Tbox** hides the pairing dialog while retaining its original two-minute deadline;
**Cancel** ends that pairing window.

## Local media recovery and diagnostics

Local cluster music remains **off by default** and covers Android MediaSessions
on the vehicle tablet. Carlinkit media remains unsupported; its sessions are on
a separate Android system. Existing navigation selection, expiry and output
destinations are independent of music.

- After observation fails, release music ownership and clear acquired output
  before retrying collection at 1, 2, 5, 15 and then 30 second intervals while
  the feature is enabled and the notification listener is connected.
- Reset backoff after successful collection, including an empty list. Cancel
  retries on disable, disconnect or destruction and reject stale callbacks.
- Keep diagnostic-bench ownership separate. Recovery does not restart guidance,
  reconnect the daemon, retry SDK commands or replay cached media metadata.
- Include a passive **CLUSTER MEDIA** snapshot in bug reports: observation and
  authorization states, bounded counts, recovery status and classified output
  results. Preserve the initial rejection independently of cleanup.
- Exclude titles, artists, package/session identities, notification contents and
  exception messages from those diagnostics. Reading a report snapshot performs
  no session query, Binder transaction or restart.

## Validation and limits

The final version is checked with the full JVM suite, release lint, the signed R8
release build, relay/scanner tests and the trusted release-asset scanner. Lint's
machine-readable severity counts are inspected independently of task exit status.

The stock Android 29 regression uses the **exact minified APK and matching R8
mapping**, the real platform AndroidKeyStore and the production TLS identity.
It checks legacy signing rejection, v2 migration with a stable fingerprint,
wrong/legacy certificate pin rejection, wrong-token rejection, pinned WSS
`hello`/`welcome`, reconnection and listener shutdown. This validates the Android
29 runtime regression; it does not establish compatibility with the car's
hardware-backed provider or prove physical vehicle output.

**Actual vehicle validation remains pending.** With the vehicle parked, retest
pairing after v1 migration, authenticated connection, fresh navigation, source loss
and Wi-Fi reconnect on the Tbox Ultra 1 / Android 15. Record the vehicle's exact
model, ROM/firmware and effective grants. The available failure reports identify
DiLink 3 / BYD AUTO / Android 10 / API 29; instrument firmware and hardware-backed
KeyStore behavior are not established by the emulator.

For local media, check session loss/recovery, notification-access revoke/regrant,
disable and restart, track changes and simultaneous guidance. SDK acceptance is
not proof of visible rendering. Check OEM radio, Bluetooth and CarPlay priority
and recovery after disabling; reselect the intended OEM source if necessary.
This release adds no privilege or vehicle-control transport and does not bypass
OEM restrictions, alerts or telltales.
