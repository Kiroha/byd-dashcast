# 1.9.73-beta — Start the cluster test before requiring its projection display

**Install the signed release APK manually over DashCast, without uninstalling or
clearing app data. The application displays 1.9.73-beta / build 713.** This version
refreshes persistent daemons and uses ProxyDaemon protocol 43. Satellite pairing,
guidance and video protocols are unchanged; no companion update is required.

## Fix for the 15:40 "cluster not detected" report

The 1.9.72 diagnostic required an existing Android projection display before its
Prepare action. The reported car only had its central display at that point, so
the diagnostic refused locally before selecting or loading the new RCC.

Preparation now verifies the current daemon, exact API 29 / positive DiLink3
installed cohort and factory RCC selection first. If the projection display is
absent, it temporarily opens the original BYD projection with `16 → 3 s → 35`,
without forcing a screen size or selecting our RCC. It then waits for a fresh,
complete display snapshot. Only the single ON 1920 × 720 OEM target with observed
system ownership admits the custom RCC and the later `31 → 16 → 35` opening.
Unknown, small, private, foreign-owned, ambiguous or incomplete results refuse
those operations; the central display is never used as a fallback.

The bounded reader distinguishes an absent projection display from an unreadable
or incompatible one. Dump timeouts and partial output are rejected even with a
zero exit code. Cancellation and restoration retire future probes. The selected
application still starts only after **Open**, with fresh target and pinned-daemon
checks. The native RCC, QML, instruments, ADAS and all 78 active warning lamps
are unchanged from 1.9.72.

## Test flow

With the vehicle immobilized, open **Diag → DashCast dashboard**:

1. Read the state and compatibility.
2. Prepare; acknowledge that this can temporarily open the original BYD projection.
3. Wait for preparation to finish, then choose the application.
4. Open and inspect the actual cluster. Confirm the display only if it is visible.
5. Use the fixed **Restore BYD RCC resources** control to finish and inspect the
   native instruments and warnings before confirming their return.

The new activation/wait/refusal/recovery states and protocol 43 guidance are
translated in all 13 supported languages. The parking checkbox is an assertion,
not movement detection. This is still a manual experimental profile restricted
to the observed `21f7735c` / `02dfc7f5` cohort and 1920 × 720 target.

## Restoration and compatibility limits

Bootstrap-only recovery remains available even if no custom RCC was selected.
It sends only `18 → 0`, checks the factory selection freshly and requires the
user's observation before completing recovery. An unconfirmed
helper or close cannot be hidden by a successful factory reply. Factory RCC
recovery remains independent of local application teardown and native-close
failure. If a previously admitted full-profile close loses its display before
its last 31, size forcing is refused and the unresolved native debt remains.

**Close projection alone keeps the RCC selected and is not full restoration.**
The diagnostic does not auto-start at boot, resume an old opening or expire an
established manual session. Complete vehicle and sleep/power-cycle validation
remains outstanding. Command receipts do not prove physical rendering.

Existing 1.9.72 journals remain readable by this version. **Rollback to older
APKs remains unsupported for the retained diagnostic journal**, including after
CLEAN. The old build 711 recovery package is not compatible with this profile.
Restore and visually verify the factory display before any replacement, but do
not treat this as proof of downgrade compatibility. Do not clear data or delete
a journal/carrier to bypass recovery.

## Validation boundary

Host and stock Android 10 emulator checks do not establish OEM QML/plugin behavior,
ARM decoding, live vehicle-data freshness or physical restoration. The corrected
cold-start path must still be validated on the parked car. No vehicle commands
were executed during development or release preparation.
