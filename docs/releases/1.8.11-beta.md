# DashCast 1.8.11-beta

Fixes a gap in the BYD APK Extraction tool: it now also captures the DiLink 5.0 / 5.1 container service.

> This is a tester pre-release from `switch-kotlin`. It is not merged into `main` and must not be marked as the repository's Latest release — `1.7.0` remains the stable one.

**Diagnostics-only.** Nothing in projection, Layout, mirror, HUD, hotspot or the daemon changes. This only widens what the extraction tool collects.

## Why

A DiLink 5.0 extraction showed the tool was missing its most important target on that platform. DiLink 5.0 — the DiLink 5 model where cluster projection *works* — uses a **different** container service from DiLink 3 and DiLink 5.1: it is `com.byd.containerservice`, not `com.xdja.containerservice`. When 1.8.10 narrowed the app selection (dropping the over-broad "byd" match), it also stopped collecting this one, because its name matched none of the remaining cluster terms.

That is exactly the wrong package to miss: DiLink 5.0 is the working DiLink 5 platform, so its container service is the key point of comparison for understanding why the cluster stays blank on DiLink 5.1.

## What changed

- The container service is now collected under **both** its names — `com.xdja.containerservice` (DiLink 3 / 5.1) and `com.byd.containerservice` (DiLink 5.0) — as named, first-priority targets.
- The keyword sweep now matches "container" (which covers the older "autocontainer"), so any container-service package or library is caught wherever it is installed.

## Compatibility

- Minimum Android remains API 28; target SDK 29; compile SDK 33.
- No production path touched; no daemon protocol change; no user-facing string changed.
