# DashCast 1.6.128-beta

Resource, lifecycle, IPC, and concurrency hardening after the 1.6.127 audit.

> This is a tester pre-release from `switch-kotlin`. It is not merged into `main` and is not the repository's Latest release.

## Highlights

- Cluster boot adoption is now display-aware and conservative when task location cannot be proven.
- Proxy startup is single-flight, and shell execution is bounded in time, output size, queued work, and descendant lifetime.
- Mirror and VirtualDisplay resources are tied to client Binder death and cleaned up deterministically.
- HUD navigation uses latest-value coalescing and grouped CAN writes with substantially fewer Binder round-trips.
- Vosk, WakeWord, LLM, MediaPlayer, Activity, and service teardown paths are hardened against late callbacks and native-resource races.

## Full changelog since 1.6.127-beta

### Cluster projection and boot adoption

- Replaced the boot-time package-presence boolean with a typed task-location query that distinguishes:
  - task on the expected cluster display;
  - task on another display;
  - task absent;
  - location unknown because the daemon or framework query failed.
- Added proxy protocol v18 for the additive task-location transaction. Existing transaction numbers and legacy task-ID APIs remain unchanged.
- Prevented an unknown lookup result from destructively relaunching an active navigation task.
- Added generation tracking so late task-location callbacks cannot override a newer app selection, a new service instance, or a changed cluster display.
- Preserved pending boot adoption across Activity recreation and service reconnects, while ignoring duplicate taps during a lookup.
- Fixed recovered boot launches being counted twice in app usage statistics.
- Added lifecycle tokens to `ClusterService` async work. Queued work owned by a destroyed service can no longer move, resize, launch, or mutate DPI/task state after teardown.
- Preserved the existing move -> freeform -> resize and DPI -> settle -> launch ordering.

### Proxy daemon and shell execution

- Made `ProxyClient.connect()` process-wide single-flight:
  - one caller owns receiver setup, daemon bootstrap, Binder wait, handshake, and metrics;
  - concurrent boot, keeper, watchdog, and Activity callers join the same result;
  - follower timeouts do not start a competing daemon bootstrap.
- Made generic daemon shell execution truly bounded:
  - one deadline covers process startup, command execution, and pipe draining;
  - captured output is capped at 256 KiB while stdout/stderr continue to drain;
  - the serial gateway backlog is capped at 64 operations;
  - queue saturation is reported instead of retaining unlimited stale commands;
  - legacy ADB fallback remains inside the same bounded worker instead of escaping to another unbounded queue.
- Shell commands now run in a dedicated process group when `setsid` is available. Timeout cleanup kills the complete descendant group, preventing background children from surviving while keeping stdout open.
- Preserved the legacy `ERR timeout 30s` result for default shell timeouts and the existing command stdout/newline semantics.

### Graphics and native resource ownership

- Closed every temporary `SurfaceControl.Transaction` deterministically, including reflection and apply failure paths.
- Released daemon/client `Surface` wrappers created from Binder Parcels after SurfaceFlinger or DisplayManager acquired their own producer reference.
- Kept the legacy Fission Surface field wire-compatible while releasing the unused client wrapper immediately.
- Added an app-owned Binder lease to the transient cluster mirror. If the app process dies, `MirrorDaemon` now destroys the orphan SurfaceControl display automatically.
- Decoupled mirror teardown from Fission slot teardown. `MIRROR_STOP` no longer destroys intentionally persistent pre-created layout slots.
- Added client-death leases to generic proxy-created VirtualDisplays. Explicit release, client death, replacement, and release-all paths close each display and death recipient exactly once.
- Kept old-client/new-daemon and new-client/old-daemon compatibility through additive optional Binder fields.

### HUD navigation and Binder traffic

- Replaced per-notification runnable enqueueing with a latest-value dispatcher:
  - at most one drain task is scheduled;
  - intermediate burst frames are coalesced;
  - notification removal cancels pending guidance before serializing the HUD close.
- `MapNotificationListenerService.onDestroy()` now drops queued updates, waits behind any active update, closes the HUD, and then performs a graceful executor shutdown. It no longer uses `shutdownNow()` and cannot cancel its own final close.
- Added proxy protocol v19 for ordered CAN batches.
- Batched only the write groups that were already atomic in the previous high-level API, preserving error isolation between guidance, road name, ETA, activation, and teardown groups.
- Reduced Binder round-trips for current daemons:
  - navigation activation: 2 -> 1;
  - simple guidance: 3 -> 1;
  - secondary guidance: 2 -> 1;
  - remaining-route data: 4 -> 1;
  - navigation stop and register clearing: 9 -> 1.
- Daemons older than protocol v19 execute the exact previous calls in the exact previous order.
- A partially applied CAN batch is never automatically replayed after a Binder transport failure.

### Voice and native ML lifecycle

- Vosk model ownership is now race-safe:
  - a model constructed after release is closed immediately;
  - release while a Recognizer is active defers model close until after `Recognizer.close()`;
  - model publication/release races close each native model exactly once;
  - no pending listen or success Toast is emitted after release.
- WakeWord now uses an explicit worker lifecycle state machine:
  - a native inference that outlives the 3-second stop join retains ownership of its sessions;
  - no replacement worker starts until the old worker exits and releases ONNX sessions;
  - repeated starts while stopping queue at most one restart;
  - a later stop cancels that queued restart;
  - ONNX sessions are closed only by the worker that owns them, after native inference returns.
- LLM operations now carry a terminal lifecycle token. Release prevents late command dispatch, regex fallback, TTS requests, playback, and Toasts.
- MediaPlayer, temporary MP3 files, and AudioFocus are grouped in a release-once playback session. Replacement, completion, error, setup failure, prepared-after-release, and Activity release paths cannot double-release or leave cabin audio ducked.
- Voice level and wake-score broadcasts now allocate an immutable Intent snapshot for every asynchronous `LocalBroadcastManager` delivery. Later samples can no longer overwrite queued extras.

### Privacy, Activity lifecycle, and accessibility

- Replaced the global truncated package-name SHA-256 marker with a per-install HMAC-SHA-256 marker.
- The random 256-bit marker key is stored in the app's private no-backup directory. Reports from one installation remain correlatable without enabling a global package-name dictionary lookup.
- Added terminal teardown to the activation timeout and inset auto-apply helpers:
  - delayed Handler callbacks are removed;
  - resize workers are interrupted;
  - no new shell/Binder resize is submitted after Activity destruction.
- Recycled every `AccessibilityWindowInfo` snapshot after extracting its independently owned node, reducing wrapper churn on API 28/29.

### Compatibility and rollback

- Minimum Android version remains API 28; target SDK behavior remains unchanged.
- Proxy protocol changes are additive (v18 task location, v19 CAN batches).
- Legacy daemon and legacy CAN paths remain available where required.
- Every confirmed fix between 1.6.127 and 1.6.128 was committed separately so it can be reverted independently.
- R8/minification and scheduler-priority tuning remain disabled because they require a separate on-car compatibility matrix.

## Suggested tester checks

- Headless boot auto-launch, then open DashCast and adopt the already-running cluster app.
- Move or kill the boot-launched task before opening DashCast and verify a clean relaunch rather than a blank mirror.
- Kill/restart the app process while the mirror or a temporary VirtualDisplay is active.
- Start/stop navigation repeatedly and verify the HUD always clears its last arrow.
- Rapidly toggle WakeWord and voice-command features while model loading or TTS playback is active.
- Verify Fission pre-created layout slots survive normal mirror stop/start operations.
