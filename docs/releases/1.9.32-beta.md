# DashCast 1.9.32-beta

DIAG now exposes a single export button: **Export complet accessible — firmware + APK**. It starts a new broad collection or resumes the previous one. Older targeted export buttons and choices are no longer shown; their engines remain available internally for compatibility and regression checks. It inventories both existing app and ProxyDaemon identities under `/system`, `/system_ext`, `/product`, `/vendor`, `/odm` and `/oem`, and strict mounted APEX module directories. Every accessible regular firmware file is considered regardless of extension, including empty files. Positive PackageManager base/split APK paths are included in the same session, without recursively scanning `/data` or private application data. The internal APK, SYSTEM, P15 and fixed context engines retain their previous scope.

This is a broad file collection, not a physical image of the whole vehicle. Protected files, other mount namespaces, unmounted partitions, kernel devices and private data remain outside coverage. Child directory symlinks are not followed; allowed file/root aliases are checked against their canonical targets and deduplicated. Missing roots, denied metadata, changes and limits remain explicit in the external manifest. The collection is live and non-atomic. Original payloads are never executed or loaded. The existing daemon connection can use its normal bootstrap; no new permission, OEM Binder call, transport, daemon protocol or vehicle setting is introduced. Only app-local ZIPs, the inventory journal/metadata, and generated bounded name snapshots in this collector’s own shell temporary directory are written. Firmware payloads remain read only.

The inventory and volume intent journal live on disk, with limits of 200,000 sources/directories, 64 MiB of inventory database storage and 2,048 retained incidents plus an omitted count. Shell discovery scans each direct directory once into a NUL-delimited name snapshot (at most 16 MiB, under the existing 30-second daemon command limit), consumes it in bounded chunks, then probes metadata in batches of 16 encoded names. It never builds a whole-directory glob array or reruns the directory listing for each page. Interrupted directories are rescanned when resuming because live directory ordinals are unstable. A timed-out or truncated subtree remains partial. Snapshots are removed before another one is created; failed cleanup records an incident and blocks further shell snapshots. A process death can leave that session’s UUID directory behind; no wildcard cleanup of other sessions is performed. The foreground progress panel shows phases, sources, bytes, elapsed time and waiting. Keep DashCast visible while parked; this does not guarantee survival of process death or vehicle sleep. A late synchronous Binder call retains the diagnostic gate until its physical return. Cancellation is deferred through the current read/command; there is no retry pool or background read prefetch.

ZIP volumes are independently readable, use compression level zero, target 1 GiB and cap source entries at 2,048. One larger source can exceed the byte target without truncation. A 512 MiB free-space reserve is checked periodically. Finished volumes and partial results remain local. To resume, choose **Reprendre la collecte précédente — vérifier les ZIP et continuer** from the same export button: DashCast first checks profile/schema and ROM/identity context, then streams every recorded finalized ZIP entry through size/SHA-256 validation. Only validated successful entries are skipped. A damaged/missing ZIP causes its sources to be recopied in a new volume; earlier files are never overwritten. `.part` files never count as finalized. A crash between volume rename and journal checkpoint is reconciled from the durable intent. Incompatible context requires a new session.

After completion, use **FIRMWARE LARGE export files → List / share files**. Transfer **every finalized `firmware-*.zip` and the separate session `manifest.json`**, preserving the directory and older exports. The in-volume `manifest-volume.json` describes only its own contents. Keep partial manifests too; `.part` files are incomplete. Sharing remains manual and there is no automatic upload.

APP reads pin a regular-file descriptor with `O_NOFOLLOW` and check `fstat`. The existing SHELL chunk protocol cannot pin one descriptor across chunks or expose read errno: canonical/type/size/inode/mode/timestamps are rechecked before each chunk and after EOF, but the short race between metadata checks and each path-based read remains. A zero-length file requires a successful read-open probe; a denied/unknown read is not an empty success. Shell read throughput has not been measured on the vehicle.

Validation: **162 JVM tests across 14 DIAG suites** passed, with no failures, errors or skips, including 28 new collector/policy/UI scenarios. The fixtures exercise real persisted SQLite/Robolectric reopening, ZIP corruption/duplicate/missing entries (including metadata-only corruption with valid ZIP CRC), cancellation, crash between rename and checkpoint, changed context, storage reserve, inventory rollback/budget, terminal-newline names and the actual single export menu. Final lint/release artifact checks are recorded separately by the independent verifier. JVM/Robolectric/desktop checks cannot establish compatibility or risk-free operation on a particular vehicle ROM. VersionCode 671; minSdk 28, targetSdk 29, compileSdk 36 unchanged.
