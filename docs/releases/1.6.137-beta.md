# DashCast 1.6.137-beta

Timeout-safe local ADB and bounded D50F recovery after 1.6.136-beta.

> This is a tester pre-release from `switch-kotlin`. It is not merged into `main` and must not be marked as the repository's Latest release.

## Highlights

- Upgrades the embedded ADB client from dadb 1.2.7 to dadb 2.0.0.
- Prevents a TCP-open but protocol-silent local adbd from permanently occupying every ADB worker.
- Distinguishes a closed port, missing listener, unauthorized key, and unresponsive ADB protocol.
- Bounds proxy bootstrap retries while preserving authorization and cold-start windows.
- Keeps a healthy ProxyDaemon Binder usable even when local ADB has a classified outage.
- Keeps Bug Wizard, Bug Report, and SysInfo responsive and informative when ADB is unavailable.
- Selects the actual D50F PRESENTATION display instead of assuming cluster display 1.
- Adds 17 focused regression tests across transport, timeout, proxy, routing, and display policies.

## Full changelog since 1.6.136-beta

### dadb 2.0.0 transport foundation

- Replaces `dev.mobile:dadb:1.2.7` with `dev.mobile:dadb:2.0.0`.
- DashCast continues to use only the source-compatible dadb APIs: `create`, `supportsFeature`, `shell`, `close`, `AdbKeyPair`, and `AdbShellResponse`.
- The breaking dadb 2.0 operation-result APIs for install, push, pull, root, and uninstall are not used by DashCast.
- dadb 2.0 adds bounded socket reads and writes, typed transport exceptions, reader wake-up after a failed connection, and sequential stream IDs that cannot collide with a live stream.
- Socket keepalive is enabled for the local ADB connection.
- The dependency resolves with the existing Okio 2.10.0 and Kotlin runtime, and the Java 17 bytecode passes Android desugaring and D8 for the app's API 28 minimum.

### Explicit progress timeout policy

- The existing raw TCP reachability probe remains bounded to 1.5 seconds.
- Normal shell operations use a 60-second idle timeout.
- The first real command in a process receives at least 15 seconds because dadb creates its connection lazily and that command may perform the ADB authentication handshake.
- A newly generated DashCast ADB key receives 30 seconds for the system authorization dialog.
- A proven-healthy proxy bootstrap retains the historical 8-second caller budget used before this migration, avoiding a more aggressive DiLink 3/4 cutoff.
- Small diagnostic probes use 7 seconds.
- The complete Android 13 bug-report dump uses 120 seconds.
- These are progress/idle deadlines, not total-operation caps: a long command remains valid while ADB packets continue to arrive.
- A real integration test now connects dadb to a deliberately silent TCP peer and proves that the worker exits within its configured deadline instead of hanging indefinitely.

### Forced handshake and typed transport health

- `Dadb.create()` is lazy, so DashCast now calls `supportsFeature("shell_v2")` before returning a connection. This forces the `A_CNXN` / `A_AUTH` exchange inside the existing authorization retry loop.
- A successful shell operation is required before the transport is recorded as healthy.
- Typed dadb failures are mapped to four stable states:
  - `PORT_CLOSED`: localhost port 5555 actively refused the connection;
  - `NO_LISTENER`: the TCP connection timed out or was filtered;
  - `KEY_UNAUTHORIZED`: adbd rejected or has not approved DashCast's RSA key;
  - `ADB_UNRESPONSIVE`: TCP accepted the connection, but the ADB handshake or command stream stopped answering.
- The D50F incident matches `ADB_UNRESPONSIVE`: raw TCP reachability no longer masquerades as protocol health.
- A successful command clears the sticky outage diagnosis and resets authorization state.

### Bounded proxy bootstrap and recovery

- The outer proxy bootstrap wait grows from 8 to 16 seconds so it can contain the preserved 15-second first-command authorization window and callback delivery.
- A failed or timed-out ADB command receives only a 2-second Binder grace in case the detached ProxyDaemon started immediately before the socket failure.
- Normal cold ProxyDaemon startup still receives 15 seconds for `ActivityThread.systemMain()` and its connection broadcast.
- A live daemon rebroadcast still receives its established 5-second window.
- `KEY_UNAUTHORIZED` is eligible for a real recheck after 2 seconds so accepting the system dialog recovers quickly.
- Closed, missing, or unresponsive transport is rechecked at most once per 60 seconds, preventing the former keeper bootstrap storm.
- The first classified failure now arms the cooldown timestamp immediately; the next 10-second keeper heartbeat cannot launch a second full failed attempt.
- Timeout failures are counted as proxy timeouts rather than generic failures.

### Live-Binder-safe ShellGateway routing

- Local ADB health and ProxyDaemon Binder health are now treated as independent signals after the daemon has started.
- A live ProxyDaemon Binder remains eligible for typed verbs and generic `runShell` even if a separate local-ADB operation has been classified as unavailable.
- The transport circuit-breaker is applied only when execution would actually enter the legacy local-ADB fallback.
- If neither the Binder nor local ADB is usable, the command is still rejected before entering the bounded shell queue, preserving the previous queue-storm protection.
- Routing is evaluated again inside the worker so a Binder that arrives while a command is queued can be used, while a Binder that dies before execution cannot force a known-dead ADB fallback.
- Proxy failure callbacks remain exactly-once, and the existing DiLink 2 resize ban and display-0 hard guard remain ahead of every route.

### D50F Bug Wizard and Bug Report recovery

- Bug Wizard no longer launches a shell app-detection command when the ADB transport is already classified unavailable.
- The wizard reports the transport failure immediately instead of waiting for an outer latch around a permanently blocked worker.
- Cluster display selection is now a tested policy:
  - prefer a non-default PRESENTATION display;
  - preserve legacy display 1 where it is the valid cluster;
  - select D50F display 2 when it is the PRESENTATION surface;
  - fall back to a single non-default display only when no PRESENTATION display exists.
- BugReportCapture immediately creates the guaranteed journal-only report on its background worker when ADB is unavailable.
- The report dialog and UI thread no longer wait for shell dumps that cannot start.
- Existing full shell dumps and screenshot/report behavior remain unchanged when the transport is healthy.

### SysInfo and localized diagnostics

- SysInfo now includes the protocol-level transport state and actionable diagnosis instead of reporting only that TCP port 5555 is open.
- One-time user warnings distinguish unauthorized, unresponsive, and unreachable local ADB.
- Three new transport messages are available in the French base resources and every alternate locale: English, German, Spanish, Italian, Russian, Ukrainian, Belarusian, Kazakh, Uzbek, Turkish, Arabic, and Polish.
- Internal technical logs retain the typed state names so field reports can be classified without translating log text back into implementation states.

### Focused regression coverage

- `AdbTransportFailureTest` covers typed authentication, timeout, refused, missing-listener, and wrapped failures.
- `DadbSocketTimeoutTest` proves a silent ADB peer cannot retain a worker forever.
- `AdbTimeoutPolicyTest` covers first-operation authorization headroom, operation-specific deadlines, and the historical 8-second bootstrap budget.
- `ProxyBootstrapPolicyTest` covers transport-failure Binder grace, rebroadcast, and cold-spawn windows.
- `ProxyTransportRetryPolicyTest` covers fast authorization recovery and dead-transport storm protection.
- `ShellGatewayRoutingPolicyTest` proves a classified ADB failure does not hide a live Binder, prevents known-dead local fallback, and preserves healthy legacy behavior.
- `ClusterDisplaySelectionTest` covers D50F display 2, legacy display 1, PRESENTATION priority, and fallback selection.
- The full JVM matrix grows from 96 tests in the last fully documented pre-release to 113 tests in 36 suites.

## Compatibility and preserved behavior

- Minimum Android version remains API 28; target SDK remains 29; compile SDK remains 33.
- No permission, manifest component, daemon protocol, Binder transaction, AutoContainer transaction code, projection activation sequence, mirror rendering path, tactile-input path, task-move/resize verb, or HUD behavior changed.
- The persisted ADB key files and one-time authorization flow are retained.
- The 8-second proven-transport bootstrap deadline matches the historical caller budget rather than imposing the initially considered 6-second cutoff.
- DiLink 2 still blocks every display-resize command before either the proxy or local shell can touch its single display 0.
- DiLink 3/4 retain their established 15-second cold daemon broadcast allowance and can continue using a healthy Binder through a transient local-ADB outage.
- DiLink 5 and D50F retain their existing AutoContainer service-name probing and production projection sequences.
- The D50F `1000/18 -> wait 6 s -> 16/35` sequence remains diagnostic-only and is not enabled in production.
- An independent adversarial review found no remaining code defect in the Binder/ADB routing and exactly-once callback paths.

## Known limitation

This release cannot force an OEM adbd process to execute commands when it accepts TCP but remains protocol-silent. It prevents DashCast from hanging and supplies truthful recovery diagnostics, but D50F physical projection can still require restarting or reauthorizing Android debugging/adbd. A visible Android display 2 or a screenshot is not proof that the physical instrument panel switched; that still requires an on-car observation.

See [the complete D50F self-ADB incident analysis](../D50F_ADB_BOOTSTRAP_INCIDENT_2026-07-18.md) for evidence, failure timing, recovery ownership, and the required field check.
