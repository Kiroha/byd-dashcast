# DashCast 1.9.5-beta — OTA fix: manual installation required

**Manual installation required. Download the APK and install it manually over your
existing DashCast installation. Do not use the in-app OTA updater for this upgrade.**
The older updater stops before installation and cannot receive its own correction
through that failing path. **Do not uninstall DashCast first**: installing over the
existing app preserves settings, consent and diagnostic pairing.

Pre-release from `feat/hud-2.0`, versionCode **644**. **1.9.0 remains the stable release.**

## Manual installation

1. Download **`DashCast-v1.9.5-beta-release.apk`** from this release's Assets.
2. With the vehicle parked, transfer the APK to the head unit and open it using its
   file manager, or download and open it directly on the head unit.
3. Confirm installation over the existing DashCast app, then open DashCast and
   verify that it reports **1.9.5-beta**.

If using ADB, install over the existing app with:

```sh
adb install -r DashCast-v1.9.5-beta-release.apk
```

After this manual upgrade, future OTA updates use the corrected certificate check.
End-to-end OTA installation of a subsequent, newer build still needs vehicle
verification.

## What is fixed

A DiLink 3 / Android 10 report showed the update from 1.9.3-beta to 1.9.4-beta
downloading, then stopping with **`APK signer mismatch`** before the installer ran.
Both published APKs have the same signing certificate.

The cause was an incomplete flag request when parsing the downloaded APK. Android 10
requires `GET_SIGNATURES` to collect archive certificates, alongside
`GET_SIGNING_CERTIFICATES` to return the modern signing information. DashCast now
requests both. Missing certificates also have a distinct diagnostic error instead
of being reported as a signer mismatch.

SHA-256 verification, package and version checks, the non-debuggable requirement,
and exact current signer matching remain enforced. The regression tests accept a
matching signer and reject changed download bytes, a different signer, and missing
certificates. [Detailed incident analysis](https://github.com/Kiroha/byd-dashcast/blob/v1.9.5-beta/docs/incidents/INC-20261005-230720-OTA-CERTIFICATES.md).
