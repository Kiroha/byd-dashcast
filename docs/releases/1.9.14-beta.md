# DashCast 1.9.14-beta — Satellite pairing diagnostics and IPv4 hotspot

The Satellite pairing dialog could show **Preparing code** and disappear immediately
when address/profile preparation, listener binding or receiver startup failed.
This build retains an actionable failure in the dialog with **Try again**, instead
of silently closing it. Failure labels cover all thirteen application languages.

**Vehicle APK: versionName `1.9.14-beta`, versionCode `653`.** Install over the existing
vehicle app without uninstalling. Use **DashCast Satellite 0.5.0-dev** on the Tbox for
the matching IPv4 hotspot recovery. Certificate identity and shared pairing token
remain compatible with existing profiles; application versions evolve independently
from guidance protocol v1. This is a prepared test build, not evidence of vehicle acceptance.

- Export only numeric local IPv4 candidates. Do not transfer vehicle-side IPv6
  link-local addresses with interface scopes that cannot identify a peer on the Tbox.
- Distinguish missing IPv4, certificate/profile preparation, pairing-listener and
  receiver failures. Support diagnostics contain fixed stages and exception classes
  only. Codes, tokens, notifications and route content remain excluded.
- Keep failed preparation in memory until explicit retry, cancellation or the
  original two-minute expiry. Disable **Continue on Tbox** until a listener is ready.
  **Try again** explicitly starts a fresh window. CarPlay transitions preserve a
  pending or ready code and do not renew its deadline.
- Associate pairing windows with receiver generations, so an old receiver teardown
  or late listener callback cannot erase a replacement retry. A foreground start
  denied before service creation reports a visible receiver failure immediately.
- Satellite 0.5.0-dev uses the selected LAN's current IPv4 gateway even if an old
  profile advertised another address. Full certificate pinning and LAN socket
  binding remain mandatory; a different receiver certificate cannot authenticate.

Retest both APKs while the Tbox is connected to the vehicle's TetherFuseNet hotspot.
Open **Pair device** in DashCast. If a failure remains, report the displayed category.
If a code appears, switch to the Tbox, enter it and check authenticated connection
separately from source guidance. Enable **Use satellite guidance**, start an actual
route, then test route stop and Wi-Fi reconnection.

Tests reproduced silent preparation dismissal, legacy-profile gateway omission and
an IPv6 connection attempt before the fixes. Automated coverage includes the actual
Pair device click, no-address/certificate/bind/foreground failures, pending CarPlay
preparation, original deadlines and old-generation cleanup. Physical pairing,
AndroidKeyStore behavior, guidance output and reconnection remain to validate on the
user's vehicle; the exact original preparation error is not known without device evidence.

Independent verification passes **989 JVM tests in 185 suites** without failures, errors
or skipped tests. Release lint reports zero issues and signed release assembly succeeds.
Satellite 0.5.0-dev passes **138 tests in 22 suites**, debug lint, debug assembly and its
pinned protocol/fixture checks. Both repository graphs are updated with AST extraction.
