# DashCast 1.8.16-beta

HUD bench follow-ups now that `sendInfo2` cluster arrows are confirmed on-car: a "cluster" result option, and an icon-sweep to map the cluster's glyphs.

> This is a tester pre-release from `switch-kotlin`. It is not merged into `main` and must not be marked as the repository's Latest release — `1.7.0` remains the stable one.

**Diagnostics-only.** Nothing in projection, Layout, mirror, hotspot or the production HUD/CAN path changes.

## Why

The `sendInfo2(4, NaviInfo)` bench (Tool ④) is now confirmed to work on-car: a DiLink 3 owner (SX326) and a DiLink 5.0 car (SW155) both see turn arrows appear on the instrument **cluster**. Two things were missing to build on that:

- The result picker only mentioned the windshield HUD, so a driver **without** a HUD who saw cluster arrows had no way to record a success — the owner's own run was logged as "other — godzilla".
- The 1for2 cluster's turn-icon numbering is **not** identical to AMap's (an earlier test drew a left-ish arrow for AMap "right"), so before wiring real navigation content we need to learn which id draws which glyph.

## What changed

- **Result picker.** Adds **"arrow on the CLUSTER (behind the steering wheel)"**, re-labels the existing option **"arrow on the HUD (windshield)"**, and rewords the title to ask **where** (cluster or windshield). A HUD-less tester now records a proper YES for a cluster arrow. One new string, three updated, across all thirteen locales.
- **Icon-sweep bench.** A new button under Tool ④ sends AMap `NEW_ICON` ids `0..28` via `sendInfo2`, each for ~3 seconds, with the id written into the road-name field ("ICON n"). A single cluster photo then maps id → glyph, so straight/left/right can be confirmed on-glass. Its capture is uploaded under a distinct `hud_iconsweep_` name so it does not affect the `sendInfo2` YES/NO tally.

Internally, the bench now derives its zip name from a `benchKind` field (`canbench` / `sendinfo2` / `iconsweep`).

## Compatibility

- Minimum Android remains API 28; target SDK 29; compile SDK 33.
- No production path touched; no daemon protocol change. Only the diagnostics bench and its result-picker strings change.

## Suggested tester use

- **DiLink 3 / DiLink 5.0 owners:** open `Diagnostics` → `HUD bench (DL3)`. First fully close the car's own navigation.
  - Run **Tool ④ (sendInfo2)** and, in the result picker, pick **"arrow on the CLUSTER"** if the arrow appears on the panel behind the wheel (or the windshield option if you have a HUD and it shows there).
  - Run the **icon-sweep** and **photograph the cluster at each `ICON n`** (the id is shown as the road name). Send the photos — they let us map which id draws straight/left/right.
