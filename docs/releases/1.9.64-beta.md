# 1.9.64-beta — RCC recovery and clearer cluster diagnostics

Fixes the build-702 regression identified in the 15:51, 15:54 and 15:55 reports.
BYD returned our exact RCC selection path with source 1; the diagnostic wrongly
required source 0, rejected its own file during recovery, and left projection
tests blocked. REA confirms that the source and IVI selection path describe
independent fields. Exact UI, owned path and supported source checks remain.

Existing blocked session: install **build 703**, reconnect the daemon
(**protocol 36**), then, while parked, open **Diag → Cluster : projection et RCC →
Restaurer les ressources RCC BYD**. Inspect the cluster and answer the automatic
restoration popup. Complete recovery before starting another test.

The native button is now **Tester la projection BYD (avec bandeaux)**. It keeps
the top and bottom BYD bars; RCC tests are separate controls. A blocked native
request opens a popup naming the restoration action and records the refusal.
The category, labels and explanations are localized in all 13 languages.

Recovery now handles the existing build-702 journal through an explicit ordered
IVI recovery proof, retaining historical uncertainty. Closing the block requires
a fresh default response, visual OEM confirmation and verified cleanup. No
automatic replay, generic debt clearing or change to the strict renderer route.

See the [RCC diagnostic contract](https://github.com/Kiroha/byd-dashcast/blob/v1.9.64-beta/docs/CLUSTER_ANDROID_IVI_RCC_TEST.md)
for the report timeline, REA evidence and recovery limits.

Independent verification passed: **1,821 JVM tests / 291 suites**, zero failures,
errors or skips; debug and signed release builds; debug/release lint with
0 errors and 29 warnings each. This includes the build-702 recovery lifecycle,
actual source-1 response, blocked-request popup and French navigation labels.
The existing popup test's concurrent log iteration was corrected without changing
its assertions. Optimized helper entry points, JNI bootstrap and release-asset
scanning passed. All three RCC files and 73 previous mapping archives are unchanged.
