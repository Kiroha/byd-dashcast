# DashCast 1.9.36-beta

Makes an internal-storage export refusal diagnosable even when it happens before the session
directory exists. DIAG shows the first failing phase and short cause, with the requested path on
the following line. Initial preflight refusal is distinguished from a failure after the destination
was initially attested. Later cleanup errors do not replace that first evidence.

The existing consented bug-report flow includes a recent RAM-only diagnostic, bounded to 96 KiB:
already-read storage UUID/volume/block metadata, metadata errors, storage decisions and the relevant
SHELL/APP output mount observations. It performs no additional collection or upload, includes no
source-file payload, and is cleared by a new collection or process restart. This improves evidence;
it does not claim to solve the vehicle-specific unknown-storage refusal without the missing metadata.

The collector continues to refuse SD, USB, adopted and unknown storage. A defensive backing-path
check also prevents pseudo/device interfaces under `/dev`, `/proc` or `/sys` from establishing
internal sdcardfs/esdfs or loop backing. ProxyDaemon source access, read-only metadata operations,
strict file reads, deferred cancellation and immutable finished ZIP handling are unchanged.

Use while stationary with DIAG visible. If preflight still refuses the destination, send a bug
report in the same app process before starting another collection so the first evidence is retained.
Desktop checks do not establish compatibility on the vehicle.
