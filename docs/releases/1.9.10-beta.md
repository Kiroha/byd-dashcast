# DashCast 1.9.10-beta — Six-digit Satellite pairing

Pair DashCast Satellite by entering a temporary six-digit code, without transferring
a JSON file or using a camera. **Compatible with DashCast Satellite 0.2.0-dev.**

**Vehicle APK: versionName `1.9.10-beta`, versionCode `649`.** This pre-release
uses the existing `feat/hud-2.0` publication branch, integrates
[PR #93](https://github.com/Kiroha/byd-dashcast/pull/93) and preserves receiver commit
[`f09d84ae`](https://github.com/Kiroha/byd-dashcast/commit/f09d84aea9cb28633727062b6797bc711c0d3c1e).
It also retains the Maps-image, Android 10 listener and satellite-receiver changes
already published in 1.9.9-beta. **1.9.0 remains the stable release.**

**Validation on the car remains pending.** Offline checks do not confirm real
pairing, hotspot routing, wake-up recovery or physical HUD/cluster rendering.

## Install the two applications

- **Vehicle:** install `DashCast-v1.9.10-beta-release.apk` manually over the existing
  DashCast application while parked. **Do not uninstall first:** retain settings
  and pairing credentials. This APK replaces both 1.9.9-beta and the version-648
  code-pairing preview attached to the Satellite release. Welcome and Settings
  display the new version through the application's updated version metadata.
- **Carlinkit/Tbox:** install the separate
  [DashCast Satellite 0.2.0-dev](https://github.com/Kiroha/dashcast-satellite/releases/tag/v0.2.0-dev)
  test application (`DashCast-Satellite-v0.2.0-dev-debug.apk`). It belongs on the
  external device; the vehicle APK provided here is a non-debuggable release build
  with DashCast's existing platform certificate.

## Pair using the same vehicle screen

1. Start the vehicle hotspot and connect the Carlinkit/Tbox to it. Both devices
   must share the local network.
2. In DashCast, open **Settings → Satellite**, enable the satellite receiver and
   select **Pair a device**. Remember the six digits shown with a countdown.
3. Switch to the Tbox interface. In Satellite 0.2.0-dev, select **Pair with
   DashCast**, enter the six-digit code and confirm pairing. The original code
   remains valid for **two minutes** while switching between the two interfaces.
4. Satellite receives, validates and saves the pairing profile automatically. If
   gateway detection fails, use **Advanced: enter the car IP address** with a local
   vehicle address shown by DashCast. If the code expires, return to DashCast and
   generate a new code.
5. Grant notification access to Satellite, select Maps or ABRP there, and explicitly
   enable satellite guidance and the desired outputs in DashCast. Then select
   **Start** in Satellite and launch an itinerary on the external device.

For a **SEAL without HUD**, enable navigation guidance and **Instrument cluster**,
and disable **HUD**. Pairing alone does not change the guidance source, activate
outputs, replace an active sender or start capture. The receiver is disabled by
default; existing receiver/source selections survive an update. Advanced pairing
profile transfer remains available for older companions.

## Pairing changes

- The foreground receiver owns the temporary pairing window independently of the
  settings screen. Leaving DashCast for the Tbox preserves the same code and
  deadline; returning can show the remaining countdown.
- Each window creates a new code held only in memory. The code is not sent over
  the network. Mutual J-PAKE confirmation precedes an AES-GCM-protected pairing
  profile containing the normal receiver address, certificate pin and token.
- Five cryptographic attempts are allowed per window. Request sizes, workers and
  socket lifetimes are bounded. Cancellation, expiry, receiver disable, token
  revocation, service destruction or authenticated WSS closes the window. A process
  restart does not restore a code.
- The optional local pairing endpoint uses TCP port **47833**. Normal guidance
  continues over certificate-pinned WSS protocol v1 on **47832**. Guidance and
  video contracts are unchanged. New pairing text covers all **13 app languages**.

## Validation and remaining vehicle checks

The receiver passes **919 JVM tests in 176 suites**, with no failures, errors or
skips; **10 JavaScript viewer scenarios** pass. Release lint reports **0 errors
and warnings**. Tests cover mutual confirmation, wrong codes, replay/tampering,
strict frames, expiry, attempt limits, real local sockets, cancellation and screen
switching. The receiver pairing fixtures match the published Satellite 0.2.0-dev
contract. The signed release APK is checked for the exact package/version,
non-debuggable manifest, platform certificate and credential patterns before
publication; matching R8 mapping and SHA-256 checksums accompany it.

**Still to test on the car:** pairing while switching to the Carlinkit Tbox Ultra 1
/ Android 15, TetherFuseNet gateway detection, a wrong code followed by retry, code
expiry, the pinned WSS connection after pairing, Maps/ABRP guidance and clearing,
and recovery after the normal ignition-off/on cycle. Capture a bug report while
the failing route is active, before running a diagnostic HUD bench.

Satellite 0.2.0-dev is a guidance test build: it does not yet extract image-only
maneuvers or implement video capture. DashCast's existing local Maps image matcher
still covers only the captured left-turn shape and its reflection; other image
shapes need real captures. Code pairing does not unlock a secondary Android display
or establish video projection support on additional vehicles.
