# DashCast 1.8.18-beta

Navigation now drives **both** surfaces: the windshield HUD over CAN, and the instrument **cluster** through the OEM channel — so cars without a HUD finally get turn arrows.

> This is a tester pre-release from `switch-kotlin`. It is not merged into `main` and must not be marked as the repository's Latest release — `1.7.0` remains the stable one.

⚠️ **Unlike the recent releases, this one changes the production navigation path**, not just diagnostics. If you navigate with Google Maps on a DiLink 3, this release changes what you see.

## Why

The `sendInfo2(4, NaviInfo)` channel proved itself on-car: two DiLink 3 cars (SX326) and a DiLink 5.0 render turn arrows on the **instrument cluster** through it. Until now that was only a bench tool. Meanwhile the windshield-HUD path over CAN has been live since 1.6.111 — but the windshield HUD only exists on some cars, so everyone else got nothing.

Both are now wired to the same source.

## What changed

### Turn arrows on the instrument cluster (new)

A parsed Google Maps notification now feeds **two** outputs:

- **CAN** → the windshield HUD (unchanged, video-confirmed since July).
- **`sendInfo2(4, NaviInfo)`** → the instrument cluster, through the OEM AutoContainer channel: the container is switched into navigation mode with `sendInfo(5,0,"")`, then a `NaviInfo` FlatBuffer is pushed per guidance frame — the same call the factory navigation app makes.

Cars **without** a windshield HUD get their arrows from the cluster path alone. The cluster push is best-effort and fully guarded: it can never break the CAN path or the notification pipeline, and it re-sends the nav-mode enable by itself so it does not depend on the CAN activation succeeding.

### A real bug fixed: every straight and right turn was drawing a LEFT arrow

The AMap broadcast path sent icon `2` for **every** maneuver and `12` for the destination. A 29-photo on-car sweep of the cluster decoded the actual namespace: **`2` is turn-left** and **`12` is a roundabout**. So a "continue straight" or "turn right" instruction was drawing a **left arrow**, and arriving drew a roundabout.

Both paths now share one verified table — `2` = left, `3` = right, `9` = straight (all three confirmed directly on the sweep photos), plus slight/sharp turns, U-turns, service area, toll booth, checkered-flag destination, tunnel and roundabouts.

### Icon-sweep bench fixed

The sweep reused a result picker hardcoded to "NO/PARTIAL — other", so **every** sweep was filed as a failure regardless of what happened. It now has its own picker (photographed / nothing / free text), and its instruction points testers at the **cluster** — which is the display this channel drives, not the windshield. Three new strings across all thirteen locales.

## Compatibility

- Minimum Android remains API 28; target SDK 29; compile SDK 33.
- No daemon protocol change.
- The feature stays gated to DiLink 3 exactly as before (`isDiLink3Hud`); DiLink 5.1 and AAOS are untouched. The cluster channel is also known to work on DiLink 5.0, but extending the gate there is a separate change and is **not** in this release.
- The CAN/windshield behaviour is unchanged apart from the corrected icon values.

## Validation

- `assembleDebug`, `assembleRelease` (R8/minify): successful; no `MissingTranslation` across the thirteen locales.
- Icon table cross-checked id by id against the decoded sweep; the three safety-relevant directions (left / right / straight) were verified against the photos rather than taken from an automated reading.
- Checked that correcting the broadcast icon cannot double-remap: the OEM applies its CAN remap only on its CAN path, never on the FlatBuffer, so the corrected value improves both sides.
- On-car verification of the live cluster arrows during a real Google Maps route is **pending** — that is what this release is for.

## Suggested tester use

**This is the one to drive with.** On a DiLink 3, with DashCast running:

- Start a real route in **Google Maps** and drive it.
- Watch the **instrument cluster** (the panel behind the wheel): the turn arrow, the distance and the next street should appear and count down. **If your car has no windshield HUD, this is new — it never worked before.**
- If your car **does** have a windshield HUD, check both: the HUD should behave as before, and the cluster should now show the same guidance.
- Check the directions are **right**: a right turn must draw a right arrow, "continue straight" a straight arrow. Before this release they were all drawing left arrows on the cluster path.
- Report through the navrail 🐞 button **while the route is running**.
