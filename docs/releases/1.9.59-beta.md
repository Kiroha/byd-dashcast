# DashCast 1.9.59-beta

**Cluster renderer discovery refusals now retain the actual observation.**
The previous `found 0` message hid failed `/proc` enumeration, denied process-name
reads and processes disappearing during the scan. The status and existing report
history now distinguish these cases, including the first bounded error label,
read counters and entry/PID/time limits. No command arguments after `argv0` or
arbitrary exception messages are retained.
The `vanished` count is a missing-process-file observation (ENOENT/ESRCH), not
proof of process exit or absence outside the daemon's visible process view.

Discovery reads are bounded and native file descriptors are explicitly closed on
success, read failure, limits and timeout. Incomplete enumeration refuses the
test even when one renderer name was observed. A unique name still has to pass
all existing process-generation, namespace, mapped-file, executable and hash
checks. There is no UID, namespace, alias, path or permission fallback.

For the existing failure, use **Diag → Exports & OEM collection → Relevés locaux
OEM → Contexte cluster — bibliothèque et processus**, then share its ZIP. This
existing targeted collector is useful even when partial or denied. The old
receipt does not prove renderer absence or RCC rejection: renderer discovery
precedes carrier staging and native RCC requests.

**Install over the existing application without uninstalling**, then reconnect
the updated ProxyDaemon using its existing controls. The application displays
**1.9.59-beta · build 698**. ProxyDaemon protocol **32**, both bundled RCCs and the
load/restore protocol remain unchanged. **DashSat 0.9.9-dev remains compatible;
1.9.0 remains stable.**

This release improves diagnostics. It does not establish the runtime cause of
the reported failure, successful RCC loading, physical full-screen control or
vehicle restoration. No vehicle test was performed.

Local validation passed: **1,727 JVM tests across 281 suites**, including the
36 focused discovery/cache/lifecycle tests, debug and signed R8 release builds,
and debug/release lint with **0 errors and 31 warnings**. Robolectric/API-29 tests
exercise the production file-access adapter with instrumented OS calls and
explicit `Os.close` on
success, EOF, read error, processing error, size/PID limits and timeout. Other
regressions cover incomplete enumeration, bounded first-NUL parsing, unchanged
basename matching, refusal before renderer pinning/staging/helper creation, and
the complete diagnostic detail surviving historical-cache reload.

The release APK passed the archive/secret, package/version and signer checks,
plus optimized native-bootstrap entry-point checks. All three packaged RCC
assets remain byte-identical to 1.9.58-beta. The new R8 mapping is archived outside
the build directory; all 68 previous mapping archives retain their verified hashes.
