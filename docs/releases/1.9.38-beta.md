# DashCast 1.9.38-beta (677)

The full export could finish within seconds without producing any files: the known mount points could not discover a readable descendant when Android denied enumeration of its parent. The received manifest confirms these partial inventories and zero files; `find` stderr was lost, so the precise system-level cause was not established.

- The inventory keeps all permitted mounts and adds known Android entry points, the current user's storage locations, and APK paths reported by PackageManager through the SHELL daemon. Paths and their parents pass the same storage checks before metadata access or reading. A known APK can be read even when its parent directory denies enumeration.
- Incomplete inventories remain marked as incomplete. A resume retries them once per run while preserving files already verified. Sessions from the previous version are inventoried once to apply these new entries.
- The existing bug report retains the final summary, counters, and bounded incidents. `find` errors are captured without contaminating filenames and are limited to 2 KiB before transport. An empty collection is explicitly shown as empty.

Collection remains limited to readable regular files from attested internal storage, through the ADB/SHELL daemon with UID 2000. SD, USB, adopted storage, interfaces, and collector-owned trees remain excluded. Source files are read only; archives and metadata are written to internal storage. System mounts whose physical origin cannot be established remain excluded; no OEM security setting, permission, or property is changed.

Reading an unknown descendant under a non-listable parent remains impossible without a prior reference. Missing or inaccessible seed paths remain reported as unestablished. This is not a complete physical image, and the collection is not atomic. On-vehicle validation of this version remains to be done with the vehicle parked and DIAG visible.
