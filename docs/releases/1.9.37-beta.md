# DashCast 1.9.37-beta

Addresses three storage-classification failures observed during internal-storage export on DiLink 3.
Equivalent mount records now share one physical identity while every original mountinfo record is
retained. Conflicting device/root/type/source records at the same mountpoint remain unknown.

An excluded storage path now excludes its backing region and aliases, rather than automatically
excluding every other subtree on the same userdata filesystem. Proven USB/SD/adopted devices and
exact public/adopted StorageManager device IDs still exclude the entire corresponding device.
The collector continues to check requested and canonical paths before inventory and reads.

When sysfs block metadata is denied, a new closed metadata operation can attest only the boot
userdata block. It requires all of: successful internal-primary and private/emulated StorageManager
getters, the fixed `/dev/block/bootdevice/by-name/userdata` mount source, a canonical platform
controller matching the exact declared UFS boot controller, and block-device type/rdev identity
matching the observed userdata mount. Contradictory external evidence wins. The operation performs
canonical-path/stat metadata checks; it never opens or reads a block-device payload.

The new operation requires separately negotiated capability 4 on the pinned daemon Binder. Existing
metadata operations, transaction numbers, protocol 26 and strict file reads remain compatible.
Sysfs refusals now retain the failing stage/path in the bounded, consented bug-report diagnostic.
The fallback does not attest device-mapper system/vendor filesystems whose dependencies remain
unknown; those gaps stay explicit in the manifest. New probe permissions and actual operation on
the vehicle still require validation. No protection, permission, mount or OEM setting is changed.

Use **DIAG → Export complet accessible → Nouvelle collecte du stockage interne**, while stationary
with DIAG visible. If preflight still refuses, send a bug report in the same app process before
starting another collection. A changed provenance/context can refuse an older inventory's resume;
existing archives remain intact. Copy every final ZIP and the external manifest.json after export.
