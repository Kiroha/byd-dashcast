# DashCast 1.8.2-beta

The cluster fills the panel again. A projected app was losing **40% of the screen** to black borders by default, and nobody had changed a setting.

> This is a tester pre-release from `switch-kotlin`. It is not merged into `main` and must not be marked as the repository's Latest release — `1.7.0` remains the stable one.

## What you will see

Projected apps now use the **whole** cluster. Previously an app was drawn at 1600×522 on a 1920×720 panel, with black bands on all four sides and its bottom row of controls cut off.

The Overscan margins card is gone from Settings, and so are the per-app width/height sliders in the cluster control panel. Resizing an app is now done in one place: the **Adjust** button opens the rectangle editor, where you drag the frame to the size you want and it is saved for that app.

**On first launch after updating, all saved sizes are cleared and every app goes back to full screen.** That is deliberate — see below.

## The defect

A tester reported "informazioni mancanti": the app on the cluster was cut off. The report's own cluster screenshot measured it precisely — content at 1600×522 inside a 1920×720 panel, offset by 160/100, i.e. **exactly double** the 80/50 margin that was configured.

Double, because the margin was applied twice by two different mechanisms that were never meant to stack:

1. `applyClusterFreeformBounds` set the task's **launch bounds** to `Rect(80,50,1840,670)` — the task was already shrunk to 1760×620 before the app drew anything;
2. a display-level **`wm overscan 80,50,80,50`** then shrank the app's content *again*, inside that already-smaller task.

So this was never an over-aggressive setting. It was double counting — and 80/50 were the **built-in defaults**, so every unit behaved this way out of the box, with the driver having changed nothing.

## Why the feature was removed rather than re-tuned

Halving the default would have hidden the bug rather than fixed it, and the global margins had become redundant: per-app resizing with a saved size already covers the real need, including a panel whose bezel genuinely crops the edges — you compensate on the apps you actually project.

Removed: the 80/50 default, the whole Settings card (sliders, ± buttons, visual mode, safe-zone mockup), the automatic application on cluster connect, and the symmetric per-app inset sliders that fed the same doubled path and defaulted to the same global value.

Kept: the hand-drawn rectangle, now the single mechanism that shrinks anything. No rectangle means the app fills the panel.

## Two cleanups that had to happen

Neither piece of state clears itself, so reverting cleanly needs both:

- **Saved values are wiped once, on first launch.** The global margins, the per-app inset values and the saved rectangles all go. Values tuned against the doubled geometry describe a panel that no longer exists, and the global would otherwise stay applied with no UI left to reach it.
- **`wm overscan reset` is issued on every cluster connect.** That state lives in WindowManager, not in DashCast's preferences: a unit updating from a build that had set 80,50 would keep the inset forever, and with the Settings card removed there would be no way to clear it.

Both target the **resolved** cluster display id, never a hardcoded `1` — a fission VirtualDisplay has been observed coming up as display 3 — and never display 0. The stop-projection path was hardcoded to `-d 1` and is fixed to match; on a unit where the cluster is not display 1 it was resetting the wrong display and leaving the cluster's own inset in place.

## Compatibility and preserved behavior

- Minimum Android remains API 28; target SDK remains 29; compile SDK remains 33.
- **No daemon protocol change.** Projection, mirroring, touch injection, Layout mode, CAN/HUD and OTA are untouched.
- **DiLink 5 is unaffected and always was**: `wm overscan` was removed from Android at API 30, so those units never had the defect and have nothing to clear.
- Three independent guards still prevent any `wm` sizing command from reaching display 0 (the head unit): the per-call-site `> 0` check, `ShellGateway`'s hard block on `-d 0`, and the DiLink 2 resize guard.
- 195 unused strings dropped across all thirteen locales, along with the orphaned styles, drawables and layout of the removed card.

## Suggested tester checks

- **Project any app on the cluster:** it should now fill the panel edge to edge, with no black borders.
- **Adjust button:** with an app projected, open the cluster control panel and tap Adjust — the rectangle editor should open for that app. Drag, save, then relaunch the app and confirm the size is restored.
- **If your cluster bezel physically crops the edges:** draw a rectangle once per app you project; there is no longer a global margin.
- Confirm nothing else regressed: Layout mode, mirror video and touch, boot auto-start, OTA, HUD arrows, hotspot, and voice.
