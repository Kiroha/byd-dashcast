# DashCast 1.9.34-beta

The single **DIAG → Export complet accessible** action now discovers mounted filesystems through
ProxyDaemon (ADB shell UID 2000) and inventories all readable ordinary files, regardless of extension.
It includes readable data/user storage as well as firmware and APKs. This profile uses the daemon
exclusively for discovery, metadata and source reads; it does not fall back to application reads.
The introduction explains that archives can contain personal data and identifiers. ZIPs remain local
and are shared manually.

Each observed mount and its original bounded mountinfo record is retained, with admitted/excluded
status. Pseudo-filesystems, devices, sockets, unknown/non-local filesystem types (including FUSE without recognised Android storage provenance) and DashCast's own
exports, caches and bootstrap/snapshot files are excluded, including recognised bind/storage aliases.
Directory symlinks are not traversed. Bind-mounted regular files are supported. Payloads are deduplicated
by device/inode plus observed metadata; directory aliases also require equivalent submount topology.
Distinct FUSE views cannot always be proven equivalent and may retain duplicate payloads.

ProxyDaemon protocol 26 adds a separate negotiated strict file-read capability. Each bounded chunk
opens with O_RDONLY, O_NOFOLLOW and O_NONBLOCK, verifies the regular FD and expected device/inode,
mode, length and second-precision timestamps before and after reading, then closes the FD. Empty files
and EOF still require a successful open. Old file transactions and their numbering remain unchanged.
An absent/older/incompatible daemon fails explicitly without an APP source scan. No permissions,
SELinux rules, OEM settings or collected executables are changed or executed.

The existing disk inventory, serial cancellation, 512 MiB storage reserve, independent approximately
1 GiB ZIP volumes and SHA-256 verification on resume remain. Limits (200,000 sources/directories,
64 MiB inventory, 4,096 mounts/volumes, bounded snapshots and issue details) are explicit partial coverage,
not proof of the entire physical disk. Reads are live and non-atomic, including volatile tmpfs/rootfs
files; O_NONBLOCK is not an I/O deadline. Protected files remain protected. The old 1.9.32/1.9.33 profile
cannot be resumed as this larger profile; its archives are preserved and a new collection is required.

Use with the vehicle stationary and DIAG visible. Copy every final ZIP and the external manifest.json,
even for a partial result. Desktop checks do not establish vehicle runtime compatibility or duration. The temporary snapshot filesystem also requires a 512 MiB reserve plus the bounded snapshot budget.

Includes the satellite first-frame diagnostics from 1.9.33-beta.
