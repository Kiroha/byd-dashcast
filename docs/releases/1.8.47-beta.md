# DashCast 1.8.47-beta

This pre-release replaces `1.8.46-beta`, which was withdrawn after its published asset was found
to be a platform-signed **debug** APK. The source fixes in 1.8.46 were retained and re-audited;
this release adds fifteen independently confirmed fixes, each in its own commit.

> This is a tester pre-release from `audit/integr-1828`. It is not merged into `main` and must not
> be marked as the repository's Latest release. `1.7.0` remains the stable release.

## Release safety

**Distributed APKs are release-only.** The release gate now scans every file in every APK,
including native libraries and duplicate ZIP entry names. Missing, unreadable, debuggable or
credential-bearing APKs fail the workflow and return the release to draft. Both beta and stable
Telegram announcement workflows run the same scanner synchronously before posting a download
link, so an unsafe asset is not announced while the quarantine workflow is still running.

## Startup, projection and keyboard

**Session recovery and boot cleanup no longer race.** A pending session resume owns startup and
suppresses the stale-task cleanup. The final move-to-display-zero operation is serialized with
`ClusterService` startup and complete teardown, including synchronous initialization failures, so
cleanup cannot repatriate a task while projection owns it.

**Manual keyboard launches bind their target.** Closing the keyboard clears its relay session by
design. Reopening it from the manual button now resolves the currently focused editable on the
active cluster display and binds its display/package identity before the bridge opens. The direct
launch remains only as the accessibility-settings fallback when the watcher is unavailable.

**Fission resize results are truthful.** Overlay errors, timeouts and VirtualDisplay failures now
return failure. The application commits a new slot rectangle only after daemon acceptance and
best-effort rollback restores the previous overlay geometry after partial failures.

## HUD navigation

**CAN batches stop on native rejection.** The BYD SDK returns non-zero result codes without
throwing. Those codes now flow through the batch writer and only the accepted prefix is reported.
Truthful batching is negotiated as daemon protocol 24; surviving protocol 19-23 daemons use the
existing ordered single-write path, which already preserves each native result.

**AutoContainer activation honors its native result.** Protocol 20+ uses the result-preserving
`sendInfo(5,0)` verb and marks navigation mode active only for result `0`. Transport recovery runs
before protocol selection, while older daemons retain their result-less compatibility path.

**Expanded notification text participates in identity.** A guidance change present only in
`android.bigText` is parsed instead of being discarded as an identical repost. Notification keys
also separate equal Maps and Waze text.

**Navigation-category removals close correctly.** Posting and removal now share the same
`FLAG_ONGOING_EVENT || CATEGORY_NAVIGATION` predicate, while the driving-key check still prevents
unrelated notifications from stopping current guidance.

**Remaining navigation sources are restored.** If Maps and Waze are both active and the current
source disappears, DashCast replays the newest remaining supported notification through the normal
parser before deciding whether to close the HUD.

**Listener reconnects restore the active frame.** Disconnect and teardown clear the driving key
and dedupe identity before closing. Android's active-notification replay after a rebind therefore
dispatches the guidance again instead of treating it as a frame that is still visible.

## Reporting, privacy and storage

**Azure destinations are explicit and HTTPS-only.** Provisioning rejects cleartext, malformed,
credential-bearing and user-info URLs. Confirmation shows the destination host without exposing
the SAS. Upload errors replace the exact SAS before entering logs or callbacks.

**Provisioning is transactional.** Credentials and endpoints are committed before a shared
plaintext source is deleted. Every valid set must persist; an incomplete KeyStore/preferences
write keeps the source for retry. A deletion failure keeps the already durable credentials and is
reported explicitly.

**Azure block-list commits retry transient failures.** Transport errors and HTTP 408, 429 and 5xx
are retried up to three times without re-uploading blocks. Permanent 4xx responses fail once.

**Consumed extraction ZIPs are deleted from their real location.** Successful Azure or Telegram
uploads remove the archive in `ReportStore`, including after a late callback. Archives retained for
local retrieval and in-flight uploads remain available.

**The local ADB identity is excluded from backup.** `files/adb.key` and `files/adb.pub` are excluded
from legacy cloud backup, Android 12+ cloud backup and device-to-device transfer. Backup remains
enabled for ordinary user settings.

## If something goes wrong

Send a bug report and state the car model, DiLink generation and action in progress. There is
currently **no safe public rollback APK** for this release:

- `1.8.46-beta` was withdrawn and must not be reinstalled.
- The only public `1.8.45-beta` asset is a debug APK, so it must not be used as a recovery build.
- Its `versionCode` is 635, below this release's 637; a normal reinstall is rejected as a downgrade.

A recovery build must be rebuilt from the chosen earlier source as a release APK, signed with the
BYD platform key, assigned a `versionCode` greater than 637, and pass the normal release scanner.
Until such a build is published, keep `1.8.47-beta` installed and send the report rather than
uninstalling the app or installing either older public asset.
