# 1.9.62-beta — Guided cluster confirmations

The cluster diagnostic now asks for visual confirmation in a popup as soon as the
current test reaches the relevant step. This fixes the silent wait after native
return 18: the tester no longer needs to discover a separate confirmation button.

Questions cover native projection with the BYD top/bottom bands, return to the
normal BYD layout, RCC marker/test-theme visibility and the original RCC display.
No / not yet, unknown, Back and cancellation retain the relevant recovery block.
**Vérifier de nouveau l’affichage** reopens the question. An RCC test blocked by a
pending native confirmation explains why in a popup; the load must still be
started manually after the native test is closed.

Only one visual question is shown at a time. It is bound to the current nonce or
RCC filename/profile, exact connected Binder and eligible phase. A stale answer is
refused; resuming the cluster page reads passive current status before asking again.
No command, RCC load, OEM query or reconnection is replayed automatically. Prompt
opening, responses and invalidation are included in the diagnostic report.

Build 701; ProxyDaemon protocol **34 unchanged**. The new questions and explanations
are translated in all 13 supported locales. RCC assets and OEM loading/recovery
mechanisms are unchanged. This release improves the test workflow; it does not
remove BYD bands or establish physical cluster compatibility.

Local verification passed: **1,784 JVM tests across 287 suites**, with no failures,
errors or skipped tests, including the visual confirmation/lifecycle tests; debug
and signed release builds; debug/release lint with **0 errors and 29 warnings**
each. Optimized helper/daemon entry points and the native bootstrap pass checks.
The three packaged RCC assets are unchanged; the new mapping is archived and all
71 previous mapping archives retain their hashes. The staged APK passes archive/
credential-pattern, package/version and signer checks. Physical dialogs on the car,
cluster rendering/recovery and Telegram receipt remain untested.

Install this beta over the existing app without uninstalling, open **Diag →
Cluster Full Screen**, and keep the page visible while testing. The connected
protocol-34 daemon can be retained; no new protocol is required. The normal-return
confirmation appears automatically when the current test is ready. Answer from
what you actually see on the physical cluster. After confirming normal return,
start the desired RCC test explicitly; no load is chained automatically.
DashSat remains compatible and stable 1.9.0 is unchanged.
