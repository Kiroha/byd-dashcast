# DashCast 1.9.58-beta

**Diagnostics now opens a menu of dedicated pages.** Choose **ADAS**,
**Cluster Full Screen**, **HUD & navigation**, **Projection & displays**,
**Exports & OEM collection**, **Reporting**, or **Diagnostic log** to find the
relevant tests, options and results. Use the page's Back button or Android Back
to return to the diagnostic menu. The selected page survives Activity recreation.

The original-cluster restoration action remains visible across the menu and pages.
An active export keeps its progress summary and cancellation button visible while
you browse. The journal has its own scrollable page with selectable text. Switching
pages does not start a diagnostic or rebuild its controls.

This release reorganizes the existing tools. Cluster loading, runtime admission,
observations and recovery retain the behavior introduced in 1.9.57-beta, including
ProxyDaemon protocol **32**. The new menu does not establish physical full-screen
control or validate cluster rendering and restoration. See the existing
[cluster test procedure](https://github.com/Kiroha/byd-dashcast/blob/v1.9.58-beta/docs/CLUSTER_FULL_SURFACE_TEST.md)
for the parked-vehicle test and its limits.

**Install the release APK over the existing application without uninstalling.**
The application displays **1.9.58-beta · build 697**.
**DashSat 0.9.9-dev remains compatible and does not need an update. 1.9.0 remains stable.**

Local validation passed: **1,707 JVM tests**, debug and signed R8 release builds,
and debug/release lint with **0 errors and 31 warnings**. Navigation tests cover all
seven destinations, Back, saved-page recovery, unchanged diagnostic instances and
an active export on a 640×360 layout with font scale 1.3. The existing export tests
also verify deferred cancellation and noncancellable local finalization.

A temporary debug copy without ARM native libraries was used only to inspect the
menu, cluster page, scrolling and Android Back on an Android 10 / API 29 emulator
at 640×360dp and font scale 1.3. It is not the release APK and does not validate
native vehicle behavior. The distributed APK retains its native libraries and
cluster carriers, verified byte-identical to 1.9.57-beta.

The signed release APK passed archive/secret scanning, package/version checks,
expected-certificate verification and optimized DEX entry-point checks. Its R8
mapping is archived outside the build directory; all 67 previous mapping archives
retain their verified hashes. No vehicle test was performed for this UI change.
