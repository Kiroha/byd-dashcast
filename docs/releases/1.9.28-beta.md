# DashCast 1.9.28-beta

DIAG **Export system files** adds 52 exact native-library basenames identified as missing from the P7 DiLink3 corpus during acquisition JNI analysis. The existing four partitions and both ABI directories now probe 79 selected basenames, prioritizing `libacquisition.so`, `libdiagnostic.so`, and `libfission_utils.so` within each root. No new scan root or recursive dependency discovery is added; ODM remains limited to auto HAL candidates.

The before/after context now includes `apps.setting.product.inswver`, `ro.build.region`, and `sys.which.rse`. Empty values remain unknown. Discovery retains up to 2,048 issues with an explicit omission marker if that budget is exceeded, so a larger dependency probe cannot silently hide coverage gaps.

The collector uses existing app/ProxyDaemon filesystem rights. It reads selected original firmware and writes the usual local ZIPs, manifests, and temporary inventory snapshots. It adds no permission or vehicle-service calls and does not load or execute the collected libraries. A dependency candidate does not establish linker resolution, effective access, or runtime use.

For collection, use **DIAG → Export system files** while parked, keep DashCast in the foreground, and copy all completed ZIPs together with the final session `manifest.json` beside them into a new `Dilink3-system-P11` folder. Preserve previous collections. The ZIP's `manifest-volume.json` does not contain the completed session context.

Validation: **104 DIAG JVM tests** passed. Debug and release builds, debug and release lint, release signature verification, and the release-asset scanner passed. Lint retains two existing `UsableSpace` warnings per variant. Release APK versionCode **667**. File visibility, duration, and storage on the actual ROM remain to be validated by collection.
