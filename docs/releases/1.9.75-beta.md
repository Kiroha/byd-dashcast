# 1.9.75-beta — Full-screen cluster application experiment

**Install the signed release APK manually over DashCast, without uninstalling or
clearing application data. Version 1.9.75-beta / build 715 retains the startup and
fullscreen mirror improvements from 1.9.74-beta.** The stable release remains
1.9.0. The new diagnostic profile uses ProxyDaemon protocol 44.

## Full-screen application test

The new **Full-screen application** profile in Cluster Diag gives the selected
application, such as Waze, the complete **1920 × 720** surface on the supported
DiLink 3 / Android 10 cluster cohort. This is a manual, stationary experiment;
it never starts automatically.

In this profile, the native header (HIGH, gear, SPORT and other modes), speed and
power instruments, battery/range footer, odometer and small native pictograms are
hidden, including the green OK and speed-limit symbols. Native instruments,
telltales and visual alerts are intentionally absent during this test. After the
application is actually launched, DashCast reuses its existing ADAS masking plan
to hide the complete ADAS pane, including its visual alerts. The previous
dashboard profile and factory resources are retained.

From Cluster Diag: read compatibility, prepare **Full-screen application**, choose
Waze, and open the application. The exact supported artifact cohort and a unique,
active native 1920 × 720 cluster display remain required. Unknown, ambiguous or
smaller displays are refused. Loader or geometry failures retain the native QML
presentation; they do not establish successful physical rendering.

## Closing and factory restoration

Closing or restoring cancels further masking and performs the existing complete
ADAS restoration sequence before native projection close. Recovery remains
available independently of an application teardown that fails or stalls. Failed
or interrupted recovery keeps a durable pending state.

Factory RCC selection now precedes native projection close and is followed by a
fresh query. A factory selection reported with native `source=0` stays pending;
it is not reported as a completed restoration. If needed, the separate manual
**Apply factory selection** action performs one bounded native transition and
queries again without repeating the factory-selection request or retrying
automatically. Visually verify the normal BYD display and confirm restoration in
Diag before ending the experiment.

**Factory restoration does not make an APK downgrade supported.** Versions
1.9.73-beta and 1.9.74-beta cannot read this profile's new recovery journal, even
after a CLEAN restoration. Keep this build or a later build that explicitly
supports the profile; do not clear data or remove recovery state to bypass it.

## Validation boundary

**Validation on the actual car remains required.** Test only while stationary in
a suitable test context. Host and emulator checks do not establish physical
cluster output, firmware compatibility, alert visibility, touch alignment or
successful OEM restoration. No vehicle commands were executed during development
or release preparation. This prerelease is provided for that controlled vehicle
validation.

The interface and test/recovery confirmations are translated in all 13 supported
application languages. Existing dashboard RCC bytes and the 1.9.74 startup
behavior are retained.
