# DashCast 1.6.133-beta

Leaner daemon monitoring and a zero-error, zero-warning lint baseline after 1.6.132-beta.

> This is a tester pre-release from `switch-kotlin`. It is not merged into `main` and is not the repository's Latest release.

## Highlights

- Removes the redundant foreground proxy-monitor thread while the stronger always-on keeper heartbeat is active.
- Preserves automatic daemon recovery by restoring foreground-only monitoring if the keeper stops or never starts.
- Fixes the three correctness errors inherited by the 1.6.132 lint report.
- Removes four low-risk layout measurement/drawing hints without changing the fixed 1920x720 UI geometry or the light/night colors.
- Establishes a clean Android lint baseline of zero errors and zero warnings.

## Full changelog since 1.6.132-beta

### Proxy monitor consolidation

- Re-audited the daemon liveness architecture and found two overlapping monitors:
  - `ProxyKeeperService` already runs continuously, performs a real `pingBinder()` round-trip every 10 seconds, reconnects the daemon, maintains the HUD feedback listener, drives hotspot keep-alive, and schedules cluster screenshots;
  - `ProxyWatchdog` retained a second `HandlerThread` while an Activity was foreground and performed a weaker local `isBinderAlive()` check every 30 seconds.
- `ProxyKeeperService` now marks itself authoritative only after its heartbeat thread and handler are fully initialized.
- Once the keeper is active, `ProxyWatchdog` removes pending callbacks, releases its `proxy-watchdog` `HandlerThread`, and remains installed as a dormant fallback.
- If the keeper stops while an Activity is foreground, `ProxyWatchdog` automatically recreates its thread and resumes foreground-only polling.
- If the keeper never starts, the historical foreground watchdog behavior remains available.
- The keeper continues to use the stronger real Binder ping and the existing 10-second recovery cadence.
- Added `ProxyWatchdogPolicyTest` for keeper ownership, foreground fallback, and background no-op policy.

### Correctness lint cleanup

- Corrected misleading indentation around `FissionOrchestrator.injectSelectedLayoutMotion(mapped)` in `MirrorCoordinator`.
- The injection call remains unconditional inside the existing `try/finally`; mapped `MotionEvent` recycling and touch behavior are unchanged.
- Replaced `android:tint` with `app:tint` on the Layout mirror previous/next `ImageButton` controls, matching AppCompat/Material image-tint handling.
- These changes remove the inherited `SuspiciousIndentation` and two `UseAppTint` errors.

### Low-risk layout measurement cleanup

- Added `android:baselineAligned="false"` to the three weighted horizontal rows identified by lint:
  - the Hotspot hero icon/title row;
  - the Hotspot mini-stat row;
  - the Layout Manager body row.
- No child dimensions, weights, gravity, padding, text, or visibility behavior changed.
- Removed the full-screen `md_background` layer from the Cluster Resize layout root.
- Added a dedicated `ClusterResizeTheme` whose window paints the same `md_background` resource.
- Cluster Resize therefore keeps the exact previous light/night appearance while painting the full-screen color once instead of twice.
- The Bug Report and Bug Wizard semi-transparent root backgrounds remain intentionally unchanged because they provide modal dimming.

### Updated performance audit

- Added `docs/perf/2026-07-17-perf-reaudit.md` as the current optimization baseline.
- Revalidated the high-value findings from the July 5 audit against current source instead of reapplying already-landed work.
- Confirmed that the following earlier hotspots are already closed:
  - DL5 resize capability probing and preference work moved off the main thread;
  - floating overlay startup deferred past the first traversal;
  - Application memory-pressure shedding;
  - CAN navigation batching;
  - exact resource-locale filtering and Jetifier removal;
  - Fission canvas label/executor reuse;
  - flat ONNX mel/embedding output reads;
  - HUD navigation writes off the notification-listener main thread;
  - cluster launch Binder work off the UI thread.
- Ranked the remaining candidates by value and risk:
  - incremental Journal snapshots;
  - shorter wake-word ring locks;
  - cached voice app-label lookup;
  - optional Vosk frame pooling;
  - isolated R8/minification work with a complete reflection/JNI test matrix.
- Explicitly retained the 10-second keeper heartbeat, typed display-state polling, deterministic diagnostic waits, and bounded Vosk frame copying because they serve reliability contracts rather than accidental overhead.

### Lint posture

- `lintDebug` now reports zero errors and zero warnings.
- Informational hints fall from 21 to 17:
  - `DisableBaselineAlignment`: 3 -> 0;
  - `Overdraw`: 3 -> 2, both intentional translucent report windows;
  - `NestedWeights`: 9 informational metrics retained;
  - `TooDeepLayout`: 3 informational metrics retained;
  - `TooManyViews`: 3 informational metrics retained.
- The remaining structural metrics are not treated as release defects. Rebuilding stable fixed-screen layouts solely to satisfy heuristic counts would create more regression risk than measured benefit.

### Compatibility and rollback

- Minimum Android version remains API 28; target SDK remains 29.
- No permission, dependency, user-facing string, locale, daemon protocol, Binder transaction, cluster-routing policy, or D50F diagnostic sequence changed.
- DiLink 3, DiLink 4, DiLink 5, Layout mode, classic projection, HUD, mirror, input, and app-launch behavior retain their existing control paths.
- The proxy optimization is isolated in `dd09f8a` and can be reverted independently.
- The lint/layout cleanup is isolated in `2baaeb6` and can be reverted independently.
- Release metadata and the performance audit are in `50f6f56`.
