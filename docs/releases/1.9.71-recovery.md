# Manual recovery to the 1.9.70 behavior

This package contains the exact functional source of DashCast **1.9.70-beta**
(commit `1e7bcc73dff1cec01245a8d165c7bb767a866937`), rebuilt only with
**versionName 1.9.71-rc1 / versionCode 711** and the usual DashCast signing key.
The newer technical version permits installation over **1.9.71-beta / build 710**
without uninstalling. It does not include the new projection or ADAS orchestration
optimizations. Protocol **41**, the five RCC carriers and their recovery formats
remain the 1.9.70 versions.

## Before installing

Park the vehicle. Stop projection through the normal controls and let restoration
finish. If ADAS masking was used, request the full restoration sequence and
observe that the original pane returns. Complete any outstanding RCC recovery
through its existing controls and confirmations. If closure or restoration fails,
retain the diagnostic report and recovery journal; installing an APK does not
prove or repair the physical OEM state.

## Install without deleting data

1. Download `DashCast-Recovery-v1.9.70-build711.zip` and extract it.
2. Install `DashCast-v1.9.71-rc1-release.apk` over DashCast. **Do not uninstall
   DashCast and do not clear its data.** Preferences and restoration journals must
   remain available. No downgrade flag or root access is required on the car.
3. Open DashCast normally and reconnect. Check **1.9.71-rc1 / build 711** and use
   the existing diagnostics to verify fresh **build 711** for **both ProxyDaemon
   and SurfaceDaemon**. ProxyDaemon must report protocol **41**; SurfaceDaemon
   exposes a separate PID/build marker. Daemons can survive an APK update;
   a successful installation alone does not establish their replacement. If an
   older daemon remains, fully stop the DashCast app through Android settings,
   reopen and reconnect. If freshness is still unconfirmed, export a report;
   do not treat the software recovery as complete. No OEM cluster reset is
   requested by this procedure.

## Update behavior

The recovery APK is distributed only inside this ZIP, not as a separate GitHub
release or the main APK asset. The current OTA selector ignores the ZIP.
`1.9.71-rc1` ranks above `1.9.71-beta`, preventing an immediate offer of the
same experimental beta after recovery. A future normal release must use a new
version (for example **1.9.72-beta**) and **versionCode at least 712**. Build 711
is reserved for this recovery package.

## Limits

This is a software recovery package, not an OEM state snapshot. Existing RCC/ADAS
journals and settings are retained, but native display state, daemon freshness,
physical rendering and suspend/resume still require parked-vehicle validation.
The return package intentionally restores the earlier behavior, including its
earlier limitations. Read `SHA256SUMS` to verify the extracted APK.

The main experimental build 710 cannot be installed over recovery build 711.
Returning to an optimized build requires a later release with versionCode >=712;
do not uninstall or clear data to bypass this version protection.

The actual unmodified ARM APK overlay sequence 709 -> 710 -> 711 was not executed
on this x86 host: its stock x86 emulator rejects ARM-only APKs with
INSTALL_FAILED_NO_MATCHING_ABIS, and the available ARM emulator configuration
could not boot. Source compatibility, package identity, signing certificate and
higher versionCode are checked separately. Preservation of settings/journals is
not claimed as an empirically tested on-device installation result.

## Verified package

The APK is signed with the usual DashCast certificate and is not debuggable. Its
package identity, versionCode711 and functional equality to tag70 outside version
metadata were checked. The recovery baseline ran **1,901 JVM tests / 299 suites**
with zero failures, errors or skips. Debug/release builds and lint passed with
zero errors (32 debug warnings, 34 release warnings).

Stock Android10/API29 ART/TLS and **39 native assertions over three EGL/peer/SDP/
disposal cycles** passed on the optimized recovery DEX. The native check used the
same reviewed AAR's x86_64 library on a stock x86_64 emulator and observed no
hardware H264 decoder; it does not establish ARM decoding or physical rendering.
The original ARM APK overlay installation remains untested on this host.
