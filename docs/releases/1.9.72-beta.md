# 1.9.72-beta — Native cluster dashboard test

**Install the release APK manually over DashCast, without uninstalling or clearing
app data. The application displays 1.9.72-beta / build 712.** This build includes
the new manual cluster dashboard diagnostic, refreshes persistent daemons and
uses ProxyDaemon protocol 42. The stable release remains 1.9.0.

## New dashboard and guided diagnostic

Open **Diag → DashCast dashboard**:

1. Read the current state and compatibility.
2. Prepare the dashboard profile and wait for selection to finish.
3. Choose the application for the centre zone.
4. Open the dashboard.
5. Confirm only the display you actually observe on the instrument cluster.

The experimental dashboard keeps the native BYD instruments, units, gear,
temperature, ranges, odometer, ADAS and all 78 active native warning lamps. It
adds a transparent application zone of 752 × 320 pixels. Day/night decoration,
instrument bounds and warning layout are checked before enabling the custom
layout; an unavailable component or overflowing layout falls back to the native
scene. The 84 factory translation resources are preserved and all new diagnostic
labels are translated into the 13 supported application languages.

The main page shows progress, refusals and user-reported observation separately
from OEM command receipts. Earlier tests remain under folded technical details.
The factory Restore control remains accessible outside the scroll area.

## Compatibility and parked testing

This new experiment is restricted to the observed **Android 10 / DiLink 3,
21f7735c libBydCluster / 02dfc7f5 libBydDataSource cohort** and one currently active,
known **1920 × 720** cluster display. Unknown or ambiguous geometry and the existing
small-panel protection refuse it. A parked checkbox is the user's assertion,
not vehicle movement detection. Perform setup and validation with the vehicle
immobilized. Command success does not establish physical pixels or road readiness.

The experiment does not start at boot or resume after process restart. It has no
automatic session expiry: use Close or factory Restore when finished. Satellite
pairing and guidance protocols are unchanged from 1.9.71-beta; this release does
not require a companion application update.

## Close, factory restoration and older APKs

**Close projection** closes the application projection but keeps the custom RCC
selected and retains diagnostic ownership. Ordinary projection stays blocked
until factory restoration is verified. **Factory Restore** revokes pending
opening and requests remote recovery independently of local application teardown.
A failed native close remains an unresolved debt even if the factory RCC reply
succeeds; it must not be presented as fully recovered. Review the diagnostic
receipts and visually verify the native display.

**Rollback to an older APK is not supported or validated for this experimental
profile.** Restore and visually verify the factory display before any APK
replacement, but do not treat that as older-APK compatibility: the retained
journal uses a profile that older builds cannot recognize even after CLEAN.
The build-711 recovery ZIP from 1.9.71 is not a compatible recovery package for
this profile and is not a forward-install replacement for build 712. APK
installation itself does not restore the OEM display state. Do not uninstall,
clear app data or delete an owned recovery carrier or journal to bypass this
guard. A compatible forward recovery build would be required if replacement is
needed after exercising the new profile.

## Validation boundary

On-car validation remains to be done: opening and closing the selected application,
all instruments and warning states, ADAS visibility, physical factory restoration,
sleep/resume and a complete vehicle power cycle. Host and emulator checks cannot
establish OEM renderer/plugin behavior or live vehicle-data freshness.
