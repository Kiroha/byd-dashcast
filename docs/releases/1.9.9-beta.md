# DashCast 1.9.9-beta — Maps image guidance and Android 10 recovery

Address the two failures found in the October 9 SEAL reports: Maps supplies some
directions only in the large notification image, and the approved Android 10
listener can remain disconnected after the app process restarts. This release
also includes the experimental satellite receiver developed since 1.9.8-beta.

**Pre-release from `feat/hud-2.0`, versionCode 648. `1.9.0` remains stable.**
Physical rendering and recovery on the OEM firmware still need vehicle validation.

## Installation

**Install this validation build manually over the existing application.** Download
`DashCast-v1.9.9-beta-release.apk`; **do not uninstall first**, so settings and
diagnostic pairing are retained. Perform installation while parked.

Manual installation is required from 1.9.4-beta or older. Versions 1.9.5-beta and
newer contain the Android 10 OTA certificate correction, but end-to-end vehicle
installation still needs confirmation. This test should use the APK directly.

## Navigation fixes

- **Maps image guidance:** independently match the actual left-turn image captured
  on the SEAL and its horizontal reflection. Decode bounded bitmap/resource icons
  on the existing serial navigation writer; preserve source bitmaps and reject
  URI icons, logos, unknown or ambiguous shapes. Existing resource and text parsing
  keeps priority, including recognized U-turn and roundabout instructions.
- **Image changes and liveness:** a direction change contained only in the image
  now updates guidance. Fresh identical images maintain an acknowledged route and
  can resume it after expiry. The existing 12-second stale-guidance watchdog remains.
  An obsolete or removed pending image cannot reopen a finished route; source
  handover preserves remaining guidance without clearing another active source.
- **Android 10 listener recovery:** after two unconfirmed public rebind requests,
  the keeper can reassert the exact listener's existing approval through the
  existing shell proxy, at most once every five minutes. The bounded worker checks
  the current approval, owning user, disconnected state and enabled outputs again
  before execution. It does not grant missing permission or revoke/toggle listener
  components. Android lifecycle callbacks alone confirm a connection. Reports now
  include the fallback attempt and result.

**Image recognition covers only the captured left/right turn shape.** The left
image comes from a real report; the right-hand test image is its reflection and
still needs an independent vehicle capture. Other image-only maneuvers need real
captures before support can be added. Text/resource recognition remains available
for the maneuvers it already understands; missing directions are not guessed.

Independent HUD and instrument-cluster settings remain available. Cluster-only
guidance uses AutoContainer without CAN/HUD activation or OEM Amap broadcasts.
The approved-listener fallback's effectiveness on DiLink is a field check, not
a confirmed result from the offline tests.

## Experimental satellite receiver

- **Disabled by default:** Settings adds a satellite receiver and an explicit
  remote-guidance source choice, translated into all **13 app languages**. Normal
  local notification guidance remains the default.
- **Paired local guidance:** protocol v1 uses WSS on port 47832, a per-installation
  token and certificate-pinning metadata. Strict message validation, sequence and
  source-age checks, bounded queues and six-second guidance expiry protect against
  obsolete instructions. Selected remote guidance uses the existing output choices;
  delayed local cleanup cannot clear a satellite route.
- **Video receiver:** a bundled receive-only WebRTC viewer offers preview and
  manual projection onto an already identified secondary cluster display. Hidden
  viewers release their resources and a stalled video is cleared. This does not
  create or unlock a secondary Android display on vehicles that lack one.

**No satellite companion APK is included.** The protocol and separate-app development
plan are in `docs/satellite/`. Actual TLS handshakes, installed WebView codec support,
physical cluster video rendering and coexistence with Overdrive require device
validation. Video decoding still uses head-unit resources; guidance messages are
lightweight. Leave the receiver disabled for the local Maps regression test.

## Vehicle test

1. Install manually, retain notification access and choose the outputs matching
   the vehicle. **SEAL without HUD:** enable guidance and **Instrument cluster**,
   disable **HUD**. Keep the satellite receiver disabled and use local navigation.
2. After a head-unit restart or normal ignition-off/on cycle, start a Maps itinerary
   with DashCast in the background. **Do not open Diag or run a HUD bench first.**
   Check left/right turns, distance updates and clearing at route end. Allow the
   supervised listener retries to run if the first instruction is missing.
3. If guidance is missing, capture a bug report while the route is active **before
   any bench workaround**. Report what actually appeared on each enabled display.
   If a bench restores output, capture a second report afterward.
4. For a missing image-only maneuver, use **Diag → Export Maps icons** while the
   instruction is active, while parked or with a passenger handling diagnostics.
   Include the actual direction/roundabout exit shown by Maps when sharing the ZIP.

Offline tests do not establish physical display output. Background recovery after
OEM sleep and wake-up still needs this cold-start trial. An Android force-stop can
prevent automatic restart, and successful native transport is not proof of rendering.
