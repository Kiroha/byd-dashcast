# DashCast 1.8.10-beta

Tunes the BYD APK Extraction tool to capture the right things: the native **libraries** where the cluster logic actually lives, and only the cluster-relevant apps.

> This is a tester pre-release from `switch-kotlin`. It is not merged into `main` and must not be marked as the repository's Latest release — `1.7.0` remains the stable one.

**Diagnostics-only.** Nothing in the projection, Layout, mirror, HUD, hotspot or daemon path changes. This only refines what the extraction tool collects.

## Why

The 1.8.9 tool pulled the native `fission_*` **programs** from a DiLink 3 car — and reverse-engineering them showed those programs are only thin front-ends. The actual cluster/projection logic (and the manufacturer's activation return code we've been chasing) lives in the **`.so` libraries** they load — chiefly `libfission_services.so` and the bridge `libxdjacontainerservice_jni.so` — which the tool did not collect.

At the same time, the app side was collecting too much: the old sweep matched the generic term "byd" and dragged in dozens of unrelated system apps (file manager, Android Auto, media player, network settings, emergency call, …). Reverse-engineering confirmed none of them touch cluster projection.

## What changed

- **Native libraries are now pulled too.** The tool collects the named and matching `.so` from the firmware library folders (`/system/lib64`, `/vendor/lib64`, …) through the privileged helper, alongside the programs. The projection libraries are named explicitly so they come first.
- **The app selection is narrowed to what matters.** It now keeps only the container service, the manufacturer's navigation (and its projection-manager parts), `clusterdebug` (the reference client of the channel we use), the cluster launcher-map, and anything whose name or path contains a cluster/projection term. The unrelated apps are no longer collected.
- **The budget was rebalanced.** Shrinking the app set frees space, and a reserved slice now guarantees the native libraries always have room — the previous build came back with 40 MB of apps and no libraries because the apps had used the whole budget. The bundle still stays under the messaging size limit, and every item left out is listed with its reason.

## Compatibility

- Minimum Android remains API 28; target SDK 29; compile SDK 33.
- No production path touched; no daemon protocol change; no user-facing string changed.
