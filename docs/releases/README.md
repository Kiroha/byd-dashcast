# Release notes

Release titles, public release notes, and changelog assets must be written in English. When a note refers to a product UI label, retain the exact label shown in the app and quote it as needed; do not imply that the UI changed unless it did. When updating notes for a release that has already been published, keep the attached changelog and checksum manifests consistent with the edited notes.

## Commit messages

Write commit messages in English. Use a concise subject that identifies the change, followed by an informative body for substantive changes. Explain the problem or trigger, the reason for the change, and its implementation scope or resulting behavior. Record the checks that were actually run and their results; if relevant checks were not run, say why. Mention material limitations or risks when they affect review. Scale the detail to the size of the change, and omit filler, invented results, secrets, and conversational history.
