# DashCast 1.6.134-beta

Full-application runtime optimization after 1.6.133-beta, based on an exhaustive review of approximately 51,000 production Java/Kotlin lines and the complete startup, lifecycle, projection, IPC, voice, storage, reporting, and UI paths.

> This is a tester pre-release from `switch-kotlin`. It is not merged into `main` and is not the repository's Latest release.

## Highlights

- Runs startup storage hygiene once per process instead of once per `MainActivity` recreation.
- Reduces normal launcher shortcut discovery from one Binder query per app to one global query, with vendor-safe fallback.
- Uses the existing typed daemon ActivityTaskManager lookup before either dumpsys task-search fallback.
- Makes the Journal append only verified source deltas instead of repeatedly copying and filtering up to 5,000 entries.
- Shortens wake-word ring-buffer lock time, removes nested ONNX output materialization, and demand-gates high-frequency diagnostic telemetry.
- Removes one redundant screenshot-prune shell round trip per capture round and approximately 22 temporary objects per Cluster Resize drag event.
- Adds 15 focused unit tests and a complete application-wide performance and regression audit.

## Full changelog since 1.6.133-beta

### Process-once startup hygiene

- Added a process-wide `AtomicBoolean` gate to `AppStartupTasks`.
- Log/report pruning and orphan-sniffer inspection now run once during the process lifetime, matching the class's existing one-shot contract.
- Recreating `MainActivity` no longer creates another `storage-hygiene` thread or rescans application storage.
- All filesystem and shell work remains off the main thread.

### Vendor-safe shortcut discovery

- Reworked `AppRepository` to request all accessible dynamic, manifest, and pinned shortcuts in one `LauncherApps.getShortcuts()` call and group them by package locally.
- The previous path issued one Binder call per launchable application.
- A thrown exception, null result, or empty global result activates the historical per-package query path.
- Treating an empty result as unsupported preserves behavior on vendor launchers that silently require `ShortcutQuery.setPackage()`.
- App labels, icons, favorites, auto-launch state, launch counters, categorization, and sorting are unchanged.

### Typed task lookup before dumpsys

- Added `TypedProxyTaskFinder`, backed by the daemon's existing `ProxyClient.findTaskIdForPackage()` ActivityTaskManager verb.
- `ClusterService` now resolves tasks in this order:
  1. app-process `ActivityManager` lookup;
  2. typed daemon ActivityTaskManager lookup;
  3. daemon-side dumpsys parsing;
  4. local ADB dumpsys parsing.
- Positive typed task IDs return immediately; zero and negative IDs normalize to `NOT_FOUND`.
- Any Binder, protocol, or firmware failure is wrapped as a finder failure and continues through both historical fallbacks.
- No daemon protocol or transaction code changed.

### Generation- and eviction-safe Journal updates

- Every `AppLogger.Entry` now carries a monotonic source sequence.
- The logger tracks a generation that changes on `clear()` and exposes an atomic `EntryUpdate` snapshot containing entries, retained head/tail sequences, generation, level counts, and total count.
- A Journal update is append-only only when:
  - the logger generation is unchanged;
  - the first retained source sequence is unchanged;
  - the previous tail still lies inside the current retained range.
- This detects clears and eviction caused by either the 5,000-entry limit or the two-million-character budget.
- `LogActivity` filters only the verified suffix during normal streaming and performs a full replacement after filter changes, clears, or eviction.
- `LogAdapter.setEntries()` is now always a full replacement; the old size heuristic could misclassify a larger post-filter result as an append. Verified deltas use the dedicated `appendEntries()` path.
- Normal Journal streaming therefore changes from O(retained entries) work every 500 ms to O(new entries), while level totals remain O(1).

### Wake-word PCM and ONNX hot paths

- Added `CircularPcmCopy` for chronological reads from and writes into the 40,000-sample circular PCM buffer using at most two `System.arraycopy` calls.
- AudioRecord writes no longer perform one modulo operation per sample.
- Wake-window reads no longer perform up to 40,000 modulo/index operations while holding `mRingLock`.
- Int16-to-float normalization now runs after releasing the ring lock, reducing contention with the microphone capture thread.
- Reference embedding output is copied from `OnnxTensor.floatBuffer` directly into the existing wake input buffers.
- Reference and streaming wake scalar outputs use `floatBuffer.get(0)` instead of materializing nested Java arrays.
- The existing openWakeWord model files, thresholds, cadence, silence gate, streaming cache, reference self-check, and ONNX thread counts are unchanged.

### Demand-gated voice diagnostics

- Added a reference-counted `VoiceTelemetry` gate tied to the Diagnostic Voice tab's receiver registration.
- With no visible Voice diagnostic subscriber:
  - `VoiceService` skips RMS/peak/clip sample scanning and its 20 Hz `ACTION_LEVEL` broadcasts;
  - ordinary wake scores skip their roughly 6 Hz `ACTION_WAKEWORD` allocations and broadcasts.
- Wake detections are still published even without a diagnostic subscriber.
- Voice state changes, errors, Vosk transcripts, LLM/command results, microphone capture, pre-roll, and sample-consumer delivery are unchanged.
- Overlapping Activity subscribers are supported, and excess release calls cannot make a future subscriber invisible.

### Screenshot cleanup consolidation

- Removed the app-side ADB shell prune that ran immediately after every 15-second screenshot capture round.
- The uid-2000 daemon still enforces the hard global count and age bound immediately after every JPEG write.
- The app still performs its periodic 30-second per-tag prune and retains all existing clear, consent, pull, and send-time behavior.
- Capture cadence, JPEG quality, display selection, privacy controls, and report attachments are unchanged.

### Allocation-free Cluster Resize exclusions

- `ResizeFrameView` now preallocates and reuses its fixed 12 system-gesture exclusion rectangles.
- Each drag event previously created eight center arrays, one outer array, an `ArrayList`, and 12 `Rect` instances.
- Handle geometry, edge strips, snapping, minimum size, cluster-coordinate mapping, and commit callbacks are unchanged.

### Build and API warning hygiene

- Renamed the `VoiceCommandReceiver.Host.startActivity` implementation parameter to match the interface contract, removing the Kotlin named-argument compatibility warning.
- Added local deprecation suppressions to three intentional API 28/29 PackageManager overloads in Bug Wizard, Hotspot Keeper, and voice app resolution.
- No API 33-only branch was introduced, preserving the Android API 28 minimum and API 29 runtime behavior.

### Complete application audit

- Added `docs/perf/2026-07-17-full-app-audit.md` with the review method, applied changes, refuted concerns, deferred candidates, and vehicle validation matrix.
- Rechecked main-thread work, lifecycle symmetry, recurring pollers, task and package IPC, mirror/input ownership, voice allocation, log retention, screenshot storage, APK/Dex composition, translations, and build health.
- Confirmed balanced ownership for reviewed `MotionEvent`, `Parcel`, `Surface`, SurfaceControl transaction, display token, image, bitmap, stream, and executor paths.
- Confirmed that normal proxy monitoring remains consolidated under `ProxyKeeperService`, with `ProxyWatchdog` retained only as the foreground fallback introduced in 1.6.133.
- Confirmed that the typed task verb already existed; this release only wires it into the general finder chain.

### Focused regression coverage

- Added `TypedProxyTaskFinderTest` for positive task IDs and non-positive normalization.
- Added `LogUpdatePolicyTest` for append, clear, eviction, empty-buffer transition, and cursor-ahead behavior.
- Added `CircularPcmCopyTest` for contiguous, wrapped, full-window, undersized-destination, and writer-wrap behavior.
- Added `VoiceTelemetryGateTest` for overlapping subscribers and excess-release safety.
- The full JVM suite grows from 70 tests in 1.6.133-beta to 85 tests in this release.

## Deliberately deferred work

- R8/minification and resource shrinking remain disabled. DashCast relies on hidden-API reflection, BYD SDK reflection, JNI through ONNX/Vosk, Parcelable Binder contracts, and several `app_process` entry points; this requires a dedicated release and vehicle matrix.
- The unminified debug Dex remains approximately 8.37 MB; `com.google` contributes approximately 2.34 MB and Tink approximately 1.27 MB through `security-crypto`.
- Main, Settings, and Hotspot layout flattening remains deferred until inflation is measured with FrameMetrics or Perfetto. Rewriting stable fixed-screen layouts only to reduce informational lint counts would increase regression risk.
- Hotspot's visible-screen stats and watchdog probes remain independent because sharing them safely requires single-flight callback fan-out while preserving restart cooldown and labels.
- Process-wide app Drawable caching, adaptive screenshot cadence, cached voice-label indexing, and Vosk frame pooling remain profiling-led candidates.

## Compatibility and rollback

- Minimum Android version remains API 28; target SDK remains 29.
- No permission, dependency, user-facing string, locale resource, daemon protocol, Binder transaction, AutoContainer sequence, display-routing policy, D50F probe, wake-word model, or projection cadence changed.
- Classic projection, Layout mode, HUD, mirror, tactile input, app launch, and teardown retain their established control paths.
- Every new fast path retains its conservative fallback or full-refresh path.
- Runtime optimizations and tests are isolated in commit `cbe82f8` and can be reverted independently.
- Version metadata and the complete audit are isolated in commit `c4e7492`.
