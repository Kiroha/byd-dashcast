# DashCast 1.8.46-beta

This pre-release contains twelve fixes found by an adversarial security, architecture and
multi-display review of the current source. Every candidate was checked again against its real
call path before code was changed; historical findings already fixed in newer code were discarded.

> This is a tester pre-release from `audit/integr-1828`. It is not merged into `main` and must not
> be marked as the repository's Latest release. `1.7.0` remains the stable release.

## What stays available

This release does not add a driving-state restriction, an application allowlist or a reduced
feature mode. Arbitrary app projection, cluster auto-start, Layouts, the non-TRUSTED
VirtualDisplay compatibility fallback, automatic cluster IME, custom HTTPS report relays and
rolling diagnostic screenshots remain available.

The fixes below reject only an identity, display target, input destination or parsed value that
could not be verified. Working paths retain their existing behavior.

## Privileged daemon boundary

**Binder authorization now fails closed.** Both uid-2000 daemons previously treated an unresolved
DashCast UID as permission for every caller. A transient PackageManager failure could therefore
open shell execution, task control, display capture and input injection to any process able to
reach the Binder. System and the daemon's own UID remain available during bootstrap; application
calls are accepted as soon as UID resolution succeeds, and resolution is retried after a transient
failure.

**Daemon Binder broadcasts authenticate their sender.** When ServiceManager registration was not
available, the application accepted the Binder carried by a broadcast without authenticating its
sender. Both receivers now require the shell-held `android.permission.DUMP`; the existing
ServiceManager Binder-identity comparison remains as a second check when available.

## Displays, Layouts and input

**Fission slots now belong to the application process.** The persistent surface daemon used to
retain Layout overlays and VirtualDisplays after an application crash. Each new slot now carries a
process-owned Binder token and is released automatically when that owner dies. The wire extension
is additive: old daemons ignore it and new daemons still accept old clients.

**An unknown cluster is no longer silently treated as display 1.** A real field fixture proves that
display 1 can instead be another application's private, powered-off PiP display. The live daemon
and the dumpsys parser now share one selection policy: display 0, private displays, ordinary
third-party owners and powered-off fallbacks are rejected; known BYD cluster names retain their
existing generation-specific priority. If a display disappears during a user action, DashCast
restarts cluster activation instead of moving a task to a guessed destination.

**Cluster IME sessions stay attached to the field that opened them.** Delayed accessibility work
previously rescanned every secondary display and could retarget typed text or Enter to another
application after a focus or projection change. The session now records and rechecks the active
display and package before every action. Valid DL5 keyboard behavior is unchanged.

**Input is injected only after its display ID was actually applied.** On firmware where the hidden
`setDisplayId` method was absent or threw, touch and key events were still injected and could follow
the global head-unit focus. Both the application fallback and uid-2000 daemon now drop only those
untargeted events. Supported display-aware injection uses the same coordinates, key codes and
asynchronous InputManager path as before.

## HUD navigation correctness

**An unknown maneuver is no longer invented as "straight ahead".** A positive distance with an
unrecognized icon or language used to become a straight arrow on the instrument cluster. Partial
frames still prove that a route is active for diagnostics, but a driver-facing frame now requires
both a recognized maneuver and a parsed distance. Real "continue" and "straight" instructions
remain mapped exactly as before.

**Arrival time is no longer confused with a duration.** The parser took the first `HH:MM` token, so
`1:20 remaining - arrive 15:45` displayed an arrival time of 01:20. Multiple clocks are now
disambiguated using an ETA/arrival marker; single-clock and AM/PM formats retain their previous
behavior.

**Route broadcasts are scoped to the verified OEM package.** The next road and route progress were
sent with an unrestricted implicit broadcast. The retained OEM APK proves that
`com.example.amapservice.AmapService` dynamically registers this exact action, so guidance and stop
frames now target that package explicitly. CAN and AutoContainer delivery are unchanged.

## Reporting and privacy

**Shared provisioning files are confirmed and consumed.** Manual pairing from Download used to
store credentials and a custom relay immediately, then deliberately leave bot tokens and Azure SAS
values in shared storage. Diagnostics now shows only the source, credential types and relay host,
waits for confirmation, and deletes a shared plaintext file before storing anything in encrypted
preferences. Custom HTTPS relays and the no-computer Download workflow remain supported. The
maintainer path under `/data/local/tmp` remains automatic and reusable after reinstall.

**Large diagnostic text is redacted while streaming.** Text above 8 MiB previously bypassed every
redaction rule and was copied byte-for-byte into an archive; an outer redaction exception did the
same. Large text is now processed one line at a time with bounded memory and a stable per-file salt.
If redaction itself fails, the affected text is omitted with an explicit marker rather than copied
in clear. Binary APK, image and native payloads remain byte-identical.

## Post-crash recovery

**Boot cleanup now works through the privileged daemon paths.** The former application-process
reflection used APIs stripped or UID-filtered on DiLink 3, so stranded tasks could never be moved
home. Cleanup now obtains an explicit task location from the proxy daemon and asks the surface
daemon's established direct/stack/root-task fallback to move only tasks proven to be on a
non-default display. No package is cold-launched. Recovery state is cleared only after the task is
observed on display 0 or confirmed absent; unknown outcomes remain pending.
