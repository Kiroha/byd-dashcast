# DashCast 1.8.43-beta

One fix repairs a car. The other nine repair the thing we use to understand your car — and one of
them is a privacy matter you should read even if you never send a bug report.

> This is a tester pre-release from `audit/integr-1828`. It is not merged into `main` and must not be marked as the repository's Latest release — `1.7.0` remains the stable one.

## Android Auto no longer keeps the centre screen after you stop

**Before.** Project Android Auto onto the cluster, press Stop, and the centre screen became
unusable. Open the BYD app drawer and it showed for a third of a second before Android Auto came
back in front. Same for the home screen. The only way out was to switch the car off and on.

**What was happening.** To make Android Auto reachable again on the centre screen we relaunch it
there. We then try to close it, and that always fails — Android Auto is a system process the car
does not let us stop. Since 1.8.30 we deliberately leave its window in place, because destroying it
is what made the app permanently unreachable in an earlier release. That part was right. What was
missing is that we left it in *front*, awake, with your phone still connected — and the car's own
Android Auto service simply took the screen back, every time, because we had handed it a foreground
to take.

**Now.** We leave its window where it is and bring the home screen up in front of it.

**One thing will look different.** Where this applies — in practice Android Auto and Apple CarPlay —
pressing Stop now leaves you on the car's home screen instead of back in DashCast's app list. For
every other app nothing changes at all.

**And it is not proven.** We cannot tell from the code alone whether the home screen reliably wins
that moment. If Android Auto still comes back over the launcher, this is not enough and the next fix
is a bigger one. **If you can reproduce this, please send a report while it is happening** — this
release also makes the car able to record who is taking the screen, which it could not before.

## Wi-Fi network names were leaking out of bug reports

Bug reports remove your position, your car's identity and hardware addresses before they are sent.
They were **not** removing Wi-Fi network names. One report carried 39 of them — the tester's own and
their neighbours' — while, on the very same line, the hardware address next to each name was
correctly hidden.

The rule expected the car to write `SSID:` and this car writes `SSID` followed by a space. One
character. Every test we had was written against the form the car never produces.

Fixed, and the reason it went unnoticed for 178 reports is fixed too: the report's redaction line
used to name only the rules that removed something, so "no Wi-Fi names here" and "the Wi-Fi rule is
dead" printed identically. Every rule now reports itself, including the ones that found nothing.

**If you have sent bug reports before**, they may contain network names from around where you were
parked. Nothing else was affected — position, VIN and addresses were being removed correctly.

## Screenshots attached to a report are not filtered, and it now says so

If you let a report attach screenshots, those images go out exactly as captured. They can show a map
with street names, a destination, a saved Home pin, or a dashcam view. That has always been true and
the consent screen warns you, but the report's own privacy line described only its text — so it read
as more thorough than it was. A report that carries images now says how many, and says they are not
filtered.

Nothing changed about what is attached, only about what the report admits to. If you would rather
not send images, the toggle is in Settings.

## The rest: reports that answer the question

Six smaller fixes, all the same shape — a section that looked complete and contained nothing.

- The HUD event recorder kept the **oldest** thousand events instead of the newest, so it stopped
  listening 36 seconds into a session and never said so. It now keeps the most recent and reports
  what it dropped.
- One sensor pushing 25 times a second was taking 903 of those 1000 lines. It is now sampled once a
  second, carrying a count, which turns a 36-second window into roughly four and a half minutes.
- The cluster watchdog wrote its whole story to a log this car does not carry, so the 90 seconds
  after every launch were blank. This is the one that makes the Android Auto question answerable.
- Two screen-layer sections never reached the cluster, both stopping on the main display first.
- The report header said "unknown application" about sessions where the projected app was obvious.

## Validation

504 unit tests, all green. Lint unchanged: 14 warnings, all of them pre-existing in files this
release does not touch, and none on any file it does.

Every fix was checked by removing it again and confirming its test fails — several tests that looked
convincing passed either way and were rewritten. The redaction fix was verified end to end by
running a real report through the shipped code: 59 network names removed, none left.

An adversarial review of the Android Auto fix found three real defects in the first version,
including one where two parts of the code decided the same thing from two different observations and
could disagree. All three were fixed before this release.

**Nothing here has run in a car.**

- Version code `633`, version name `1.8.43-beta`.
- APK: `DashCast-v1.8.43-beta-debug.apk`, `16,881,079` bytes.
- APK SHA-256: `e2ebf717d2b349ea3e9d8250e717b39abd632bf8fe84ecbba5f920581727db8e`.
- Signing certificate SHA-256 (bydPlatform): `c8a2e9bccf597c2fb6dc66bee293fc13f2fc47ec77bc6b2b0d52c11f51192ab8`.
- `assembleDebug` and `assembleRelease` (R8) both green. The release APK was scanned for credential
  patterns: the only match is a PEM header literal belonging to a library, with no key material
  anywhere in the file.

**The version number itself matters this time.** Three of these fixes run inside the privileged
helper process, which only replaces itself when the version code changes. Installing a build that
still said `632` would have quietly kept the old helper running.

## If something goes wrong

Send a bug report from the app and say what the car was doing. Reinstalling 1.8.42-beta is safe.
