# DashCast 1.9.56-beta

**Keep the reason a cluster experiment was refused.** Previously, early refusal could
have empty raw output and leave no useful trace in a later bug report. DashCast now keeps
bounded historical status receipts and local failures in app-private storage, including
failures before IPC and valid replies arriving after Diag closes or its pinned daemon
reference changes. A late receipt remains evidence of that earlier call; it does not
confirm the current daemon or physical display.

Normal and fallback bug reports include this local history without querying the cluster,
reconnecting or sending another command. History is limited to 24 events and 48 KiB;
unchanged polls and countdown changes do not refresh receipt timestamps. Raw response
payloads are represented by a change digest. Writes are asynchronous and best effort, so
immediate process death can lose the latest events. Missing, corrupt or unavailable
history is reported as **NOT_RECORDED/UNKNOWN**, never successful loading or restoration.
Receipt age is separate from source freshness; current pixels and movement remain unknown.

The **Change physical cluster — passive TEST marker (experimental)** and **Restore original
cluster selection** controls keep their existing behavior. This release changes diagnostic
evidence only: proxy protocol **31**, OEM requests, recovery, bundled carrier and firmware
admission remain unchanged. The marker experiment is still bound to the researched SX326
firmware **13.1.33.2602030.1**. It adds no SX361 support, concept dashboard or exclusive
cluster control. Reboot alone is still not assured rollback; the 30-second restoration
request depends on the daemon remaining alive. See the [experiment procedure and
limitations](https://github.com/Kiroha/byd-dashcast/blob/v1.9.56-beta/docs/CLUSTER_LIVE_MARKER_TEST.md).
