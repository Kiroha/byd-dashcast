# DashCast 1.8.48-beta

**Projection ownership, daemon recovery and bug-report delivery were re-audited after 1.8.47.**
This beta contains the 138 post-1.8.47 audit commits completed before the version bump. The work
is mostly about races and failure paths that a normal successful run does not expose.

> This is a tester pre-release from `audit/integr-1828`. It is not merged into `main` and must not
> be marked as the repository's Latest release. `1.7.0` remains the stable release.

## Release safety

**The published APK is a release build, never a debug build.** It is platform-signed, not
debuggable, minified by R8 and resource-shrunk. The matching R8 mapping is published alongside it
so a field stack trace can be retraced after later builds replace the local mapping.

The release scanner rejects malformed or oversized APK/ZIP structures before native Android tools
run. It now validates raw central-directory records, ZIP64 offsets, compression methods, non-empty
directory entries and every APK Signing Block pair, in addition to package identity, version,
debuggability, signer and credential patterns.

## Projection, daemon and session ownership

**Projection commands now have process-wide ordering.** Stop/restore barriers cannot be overtaken by
a later start, callbacks from an older generation are discarded, and a timed-out transport cannot
return after newer work has taken ownership. Display-ready callbacks are tied to the binder and
activation generation that issued them.

**Proxy daemon identity is durable and race-safe.** Protocol 25 adds a per-process instance nonce to
WHOAMI. PID and instance markers are published atomically, self-healed if removed, and checked again
before a hung daemon is killed. A daemon that restarted during recovery is therefore not mistaken
for the failed process it replaced.

**Task eviction is serialized from decision through completion.** Every matching non-default task is
considered, move callbacks are bounded, stale launches are fenced, persisted session ownership is
updated under one serialized workflow, and a newer launch cannot be repatriated by an older cleanup.
Failures retain ownership so a later cleanup can retry instead of declaring the cluster empty.

## Layouts, Fission, split mode and input

**Layout activation is transactional.** Active state is committed only after all required slots are
accepted. Partial activation rolls back, free zones survive a failed switch, unacknowledged releases
become retryable debt, and that debt blocks unsafe slot reuse. Global purge, ordinary teardown and
headless orchestrator replacement are serialized.

**Tactile mirror state is now truthful.** Surface-binder death is recovered on focus/start, and Stop
clears local touch ownership only after the daemon accepts the stop or the physical owner is proven
gone. A rejected Binder transaction can no longer leave input active while the UI claims it stopped.

**Split replacement state follows verified tasks.** The latest replacement intent wins; a failed or
time-limited eviction cannot silently advance to full screen, callbacks after Activity destruction
are ignored, and stopped occupants are removed only after the stop is verified.

**Resize Cancel is dispatched before the editor exits.** The restore command is queued before
`finish()`, preserving the initial rectangle even when lifecycle teardown follows immediately.

**IME work retains its original target.** Queued text and Enter operations are generation-gated,
manual launches bind the current cluster field, stale touch probes are cancelled, and Android 10
accessibility nodes continue to be recycled at every ownership boundary.

## Reporting, privacy and storage

**Completed reports now have durable, per-file ownership.** Wizard state survives recreation and
process death across screenshot consent, bundling, delivery and retry. Concurrent wizard and legacy
reports no longer overwrite one global journal entry. Pruning protects every in-flight, failed or
ambiguous artifact, while confirmed delivery or an explicit share clears only the exact file handed
off by that callback.

**Ambiguous delivery stays ambiguous end to end.** A relay timeout or uncertain Telegram response is
not flattened into failure and automatically resent. The file remains available for an explicit
retry, preventing both silent loss and duplicate reports.

**Direct and relayed uploads are bounded.** Telegram multipart bodies stream instead of being copied
whole into memory; the relay enforces media type, canonical Base64/UTF-8 captions, exact content
length and a cancellable deadline. Azure closes every connection, retries transient block-list
commits, and does not retry permanent HTTP rejection.

**Capture staging is collision-resistant and reclaimed.** Concurrent captures use unique names, raw
Android 13 staging files are removed on every terminal path, and successful extraction uploads delete
the real source ZIP while retained or in-flight artifacts remain available.

## OTA and lifecycle

**OTA candidates are selected and verified before install.** The beta channel remains opt-in,
versions are compared semantically, the selected release APK must carry the published SHA-256, and
completed source files are removed only after PackageInstaller or the daemon no longer needs them.
The durable relaunch marker remains available across package replacement.

**Late Activity callbacks are lifecycle-gated.** Receiver teardown, restore callbacks, HUD diagnostic
updates, report capture/upload callbacks, mirror IME probes and Split callbacks no longer mutate a
destroyed host or abort the rest of cleanup.

## HUD and user interface

**HUD state advances only after delivery is known.** Complete CAN frames and next-road writes retain
the native result; rejected writes do not update the acknowledged frame. Diagnostic callbacks are
also discarded after their Activity is destroyed.

User-facing manifest labels are localized, the app-list mode toggle exposes the correct accessibility
description, compact-panel and filter preferences remain synchronized, and shortcuts issue one
launch to the selected display.

## Build status

Kotlin production/test compilation, detailed Java deprecation compilation and Gradle configuration
are clean. Android release lint reports no issues. The retained Kotlin 2.4 / AGP 8.13.2 toolchain
still makes embedded R8 8.13.19 print 63 repeated Kotlin-metadata warnings during release shrinking.
This warning is not hidden: Android requires R8 9.1.29+ for Kotlin 2.4, while tested standalone R8
9.1 builds expose a separate AGP 8.13 provider warning. Changing that version set was deliberately
left for a dedicated, vehicle-qualified migration.

## What to test in the car

**At publication, nothing in this release had run in a car.** Post-release testing on 2026-09-03
completed successfully on one vehicle. The checks below remain the regression checklist for other
models and DiLink generations; run them only while parked.

1. Upgrade from 1.8.47 and confirm DashCast reopens as 1.8.48, then cold-start it once so the v25
   proxy daemon replaces the previous instance.
2. Project an app, switch apps rapidly, press Stop while another launch is starting, and verify no
   task remains stranded or returns to the wrong display.
3. Resume a previous cluster session after an app/ACC restart and confirm boot cleanup does not move
   the newly resumed task back to display 0.
4. On DiLink 5, create/switch/stop Layouts with bound apps and free zones; resize then Cancel; verify
   touch stops immediately. If the helper restarts naturally or after a parked head-unit reboot,
   reopen DashCast and verify touch works again; do not force a daemon kill while driving.
5. Type and press Enter through the cluster keyboard, close/reopen it, and verify text never reaches
   a centre-screen field or a previously focused app.
6. Run Maps/Waze guidance and confirm the HUD frame and next-road name update and clear normally.
7. Send wizard and legacy bug reports with screenshots, rotate/close during capture, and repeat once
   while parked with the active internet link disconnected after capture starts. Reconnect it and
   verify the exact report remains available for retry and is not duplicated.
8. Smoke-test Main, Settings, Hotspot, Layout Manager, Log and System Info in day/night modes after
   resource shrinking. Look for missing icons, wrong colours, clipped text or shifted controls, and
   attach a screenshot of the affected screen to the report.

State the car model, DiLink generation and exact failed step in every report.

## If something goes wrong

Do not reinstall `1.8.46-beta` or `1.8.45-beta`: their public assets are platform-signed debug APKs.
`1.8.47-beta` is a valid release APK but has versionCode 637, so Android normally rejects it as a
downgrade from 638. Keep `1.8.48-beta` installed and send a report. A safe recovery must be rebuilt
from the chosen earlier source as a release APK, signed with the BYD platform key, assigned a
versionCode greater than 638, scanned, and published as a new pre-release.
