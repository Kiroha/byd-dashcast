# 1.9.76-beta — Cluster loading safeguards and recovery

**Install the signed release APK manually over DashCast, without uninstalling or
clearing application data. This prerelease is version 1.9.76-beta / build 716.**
It supersedes the withdrawn 1.9.75-beta experiment. The stable release remains
1.9.0. ProxyDaemon protocol 44 is retained; the higher build number refreshes
persistent daemons. Before any cluster diagnostic test, verify that the running
ProxyDaemon reports build **716**: protocol 44 alone does not distinguish the old
unsafe daemon from this build.

## Retired full-screen profile

The former **full-screen application** RCC profile is now **recovery-only**.
New loading, reopening, successful-display confirmation and new ADAS masking for
that profile are refused in the interface, application session and daemon. The
profile identity, bundled legacy bytes and journal schema are retained so that
an existing 1.9.75 recovery state remains recognizable. Closing, read-only status,
factory restoration and the existing bounded carrier-preservation recovery stay
available. No recovery debt is discarded to make the interface look successful.

An authenticated negative factory-restoration result now retains its
`retirementEligible` metadata through dashboard recovery accounting. This keeps
the failure and quarantine state; it can authorize only the separately guarded
preservation step, with its existing exact-file and selection checks. It is not
reported as successful restoration, and restarting requires fresh authorization.

The Diag page labels the new prototype as **PC only**, disables its load action
and explains that the former full-screen profile is reserved for restoration.
The updated guidance is translated in all 13 supported application languages.

## What this prerelease can test

Normal projection, startup, navigation and existing media behavior remain on the
current baseline. DashCast Satellite pairing and guidance compatibility are
unchanged; this release adds no Satellite protocol or pairing change. The earlier
native-dashboard profile remains available with its existing experimental limits;
this release does not make every cluster diagnostic safe or fully validated.

The rewritten full-screen QML candidate is an **offline development artifact**.
It is not included in the APK and has no vehicle load path. Its isolated Loader
checks handle construction errors and retain the original BYD presentation and
instruments, but PC fixture results do not establish Android pixels, native layer
composition or recovery after an OEM process crash. No new cluster dashboard
appearance is shipped in this build.

**This APK does not enable a new full-screen Waze test.** First verify the updated
application and daemon versions, the disabled full-screen action, read-only state
and any already-needed restoration. Any sensitive vehicle check must be performed
while stationary in a suitable test context, with normal BYD instruments and
alerts visually verified. No commands were sent to a car during release preparation.

## Recovery limits

A QML fallback is not an independent recovery mechanism if the native cluster
engine fails before constructing its root. This release cannot guarantee that
"Simple mode running" will never occur. Vehicle validation and an independently
proven recovery procedure remain necessary before admitting the offline candidate.

If a recovery state from build 715 exists, keep this build or a later build that
explicitly understands it. Older versions cannot read that journal: do not
uninstall, clear data or downgrade as a recovery shortcut. An accepted command or
resource-selection receipt does not replace visual confirmation of the normal
BYD display.

## Verification

- **2,024 JVM tests across 312 suites** passed with no failures, errors or skipped
  tests. A pre-existing test race between releasing the diagnostic claim and
  publishing its UI result was corrected without changing application behavior;
  the 17-test UI class passed three consecutive runs before the full suite.
- All **36 cluster Python checks**, **44 release-tool Python checks** and **13
  isolated Qt 5.15.14 fixture cases** passed. The Qt fixtures do not execute the
  proprietary OEM root or establish graphical vehicle recovery.
- Debug and release lint completed with **zero errors**, with 49 debug warnings
  and 52 release warnings. The optimized release build, reviewed WebRTC archive
  gate and actual APK JNI-bootstrap definition gate passed.
- The actual optimized release DEX passed Android 29 ART checks for pinned WSS,
  wrong-pin/token rejection, reconnect and control shutdown. A separate probe
  initialized WebRTC, EGL and a peer connection, then disposed them, using that
  same release DEX and the SHA-pinned AAR's **x86_64** native library. This does
  **not** execute the shipped ARM libraries or validate car decoding/rendering.
- Package identity, version **1.9.76-beta / 716**, non-debuggable state, the pinned
  platform signer and release credential scan were checked. The seven bundled RCC
  files are unchanged, and the new offline candidate is absent from the APK.
- The exact release R8 mapping is archived privately for crash diagnostics.
  Graphify was refreshed with AST extraction; its existing partial-parser warnings
  remain a coverage limitation, not a Kotlin/QML build result.
