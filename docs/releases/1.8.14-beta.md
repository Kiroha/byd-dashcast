# DashCast 1.8.14-beta

Fix: the new HUD-bench tool from 1.8.13-beta was unreachable from inside the app.

> This is a tester pre-release from `switch-kotlin`. It is not merged into `main` and must not be marked as the repository's Latest release — `1.7.0` remains the stable one.

**Diagnostics-only.** Nothing in projection, Layout, mirror, hotspot or the production HUD/CAN path changes.

## Why

1.8.13-beta added a fourth test tool inside `HudDiagActivity` (the `sendInfo2` NaviInfo-injection bench), but that screen was only ever registered in the manifest — nothing in the app's own Diagnostics screen actually opened it. A tester could only reach it by being handed an exact `adb shell am start` command, which doesn't scale and is easy to get wrong.

## What changed

`Diagnostics` (rewritten in Kotlin, previously a single **BYD APK Extraction** button) gets a second button, **"HUD bench (DL3) — sendInfo2 NaviInfo test"**, that opens the existing HUD-bench screen. Nothing inside that screen changed — this is purely a missing entry point, now added.

## Compatibility

- Minimum Android remains API 28; target SDK 29; compile SDK 33.
- No production path touched; no daemon protocol change; no user-facing string changed (Diagnostics is English-only by project rule).
