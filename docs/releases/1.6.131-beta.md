# DashCast 1.6.131-beta

Visible Layout activity state and switchable tactile mirrors after 1.6.130-beta.

> This is a tester pre-release from `switch-kotlin`. It is not merged into `main` and is not the repository's Latest release.

## Highlights

- Applications launched by a Layout now show the same green active indicator in the Favorites strip as they already did in the main grid/list.
- Main's live preview can mirror and control a headlessly launched Layout slot without depending on the classic `ClusterService` projection.
- Tapping a running Layout application selects it as the tactile mirror target instead of launching a competing classic projection.
- Previous/next controls above the preview switch efficiently between Layout applications and remain available in fullscreen mode.
- Touch, drag, and multi-touch coordinates are mapped to each slot's actual dimensions and injected into that slot's VirtualDisplay.

## Full changelog since 1.6.130-beta

### Field evidence and root causes

- Analysed `INC-20260717-153708`, captured after a successful hard restart of the vehicle tablet with automatic Layout enabled.
- The report proved that the 1.6.130 automatic Layout path was working end to end:
  - cluster projection was activated;
  - the Waze slot was attached to the cluster surface;
  - Waze was launched successfully on slot `displayId=2`;
  - Waze owned a visible `1011x400` window;
  - `dashcast_fission_overlay` produced buffers continuously.
- Despite the successful launch, the green bar under the Waze favorite tile remained hidden.
- The main app preview could not become a tactile Waze mirror because headless Layout startup calls `doStartSlot(..., surfaceHolder=null)`. The old Fission preview therefore never issued `MIRROR_START`.
- Main's existing `MirrorCoordinator` only understood the classic cluster display. It mirrored and mapped touches as a `1920x720` cluster projection, while each Layout application runs in its own slot-sized VirtualDisplay.
- `MirrorDaemon` routes injected input to the display selected by the latest `MIRROR_START`. With no headless Layout mirror start, there was no correct slot display target for touch injection.

### Consistent active indicators

- Added one shared active-state policy covering:
  - the classic cluster package;
  - the main-display package;
  - every package currently projected through the headless Layout orchestrator.
- Applied that policy to both app list/grid rows and Favorite-strip tiles.
- Favorite indicators now refresh whenever Layout membership changes.
- Existing classic cluster/main-display indicators and green styling are unchanged.

### Selected tactile Layout target

- `FissionOrchestrator` now tracks one selected mirror package among its running slots.
- Selection order follows the saved Layout's zone order, not map iteration order.
- The first running slot is selected automatically.
- An explicit user selection remains selected across UI refreshes.
- Previous/next selection wraps at both ends.
- If the selected slot is removed, selection falls back deterministically to the next available running slot.
- The selected target is exposed as immutable package, label, display ID, layer stack, width, and height data.

### Efficient app switching

- Tapping an application that is already running in the active Layout now selects its tactile mirror target.
- The tap no longer enters the normal `ClusterService` launcher, preventing a competing classic projection.
- Added a compact preview overlay containing:
  - the selected Layout app/zone label;
  - a previous-app arrow;
  - a next-app arrow.
- The overlay is visible only while Layout slots are active.
- Previous/next arrows are hidden when there is only one running slot.
- The selector lives inside the preview frame, so it remains usable when fullscreen mode hides the app list.
- Previous/next accessibility labels were added in all 13 supported resource sets.

### Headless Layout mirror

- Main can now mirror a selected Layout slot directly through the Binder held by the headless orchestrator.
- This path does not require `ClusterService`, which makes it compatible with automatic Layout sessions created before MainActivity is opened.
- The slot's actual hidden `Display.getLayerStack()` value is resolved reflectively, with `displayId` retained as a conservative fallback.
- Video source and input target are deliberately distinct:
  - SurfaceFlinger mirror source = the slot's resolved layer stack;
  - input injection target = the slot's Android display ID.
- Starting a new selected mirror synchronously replaces the previous daemon mirror token.
- The selected slot task receives a best-effort focus request before mirroring.
- Added additive `MirrorDaemon` transaction 17 for focus-by-package. Failure or an older live daemon cannot block video or touch startup.

### Tactile and multi-touch routing

- Added a shared aspect-preserving projection model for slot content.
- Main computes the exact letterbox scale and offsets used for the selected slot.
- Every touch pointer is mapped from preview coordinates back into slot coordinates and clamped to valid slot bounds.
- Mapped `MotionEvent` instances preserve:
  - action and action index;
  - pointer IDs and tool properties;
  - pressure and size data;
  - down/event timestamps;
  - button/meta/edge/flag state.
- Multi-touch events are injected through the exact Binder that owns the Layout slots, eliminating MainActivity Binder-arrival timing as a failure mode.
- MotionEvent and Parcel wrappers are recycled deterministically.
- Before mirroring a newly selected app, the daemon's focus verb uses the existing `setFocusedRootTask` / `setFocusedTask` compatibility path.

### Mirror lifecycle and coexistence

- Layout mirrors reuse Main's existing TextureView and fullscreen layout rather than creating a second preview surface.
- A target change stops the old mirror before rebinding the same Surface to the newly selected layer stack.
- Duplicate target notifications do not restart an already-correct mirror.
- The selected Layout mirror remains active while the user browses the app list.
- Main stops the Layout mirror when the Activity goes to the background or is destroyed, and restores it when Main returns to the foreground.
- Outside an active Layout, `MirrorCoordinator` retains the existing classic cluster mirror behavior.
- Normal mirror cleanup and Layout mirror cleanup remain isolated from persistent slot lifetime.

### Diagnostics

- `launchAndForce` output is now classified by its authoritative terminal verdict.
- A cascade containing `FINISH: launchAndForce complete.` is treated as successful even when best-effort resize or already-on-current-display operations produce diagnostic `ERR` lines.
- `FAIL: no task discovered` and terminal exceptions still classify the launch as failed.
- Successful Layout launches no longer produce the misleading `FISSION launchAndForce non-OK` warning in incident reports.

### Regression coverage

- Added `AppProjectionIndicatorTest` for Layout, classic cluster, main-display, and unrelated packages.
- Added `LayoutSlotSelectionTest` for default selection, explicit preservation, wrapped previous/next, and empty Layout behavior.
- Added `MirrorProjectionTest` for slot letterboxing, inverse coordinate mapping, edge clamping, and invalid dimensions.
- Extended `TaskLaunchRecoveryTest` with successful completed-cascade classification despite best-effort diagnostic errors.

### Compatibility and rollback

- Minimum Android version remains API 28; target SDK behavior remains unchanged.
- No permission, dependency, manifest entry, or main proxy protocol version changed.
- `MirrorDaemon` transaction 17 is additive; transactions 1-16 are unchanged.
- Focus transaction failure is best-effort and never blocks the tactile mirror.
- Classic projection, automatic Layout startup, slot rendering, and Layout teardown behavior remain available independently.
- Functional commits:
  - `4cbd05b` — `fix(ui): show Layout apps as active in Favorites`;
  - `e7a61bf` — `feat(fission): add switchable tactile mirrors for Layout slots`.
- Release metadata commit: `5e3aa11` — `chore(release): bump to 1.6.131-beta`.

## Suggested tester checks

- Hard-restart the vehicle tablet with a favorite Layout containing Waze and NewPipe and verify both apps receive green active bars, including in Favorites.
- Open DashCast after the headless Layout starts and verify the first running slot appears automatically in the live preview.
- Tap Waze and NewPipe tiles and confirm the preview switches without restarting either application or creating classic projection.
- Use previous/next controls repeatedly in normal and fullscreen preview; verify wrapping and no black-frame accumulation.
- Test tap, drag, long drag, and pinch gestures in each selected application.
- Confirm touch acts only on the selected slot and does not affect the other Layout application or display 0.
- Kill the selected Layout app and verify selection moves to the remaining slot and its green indicator is removed.
- Stop projection and verify the selector disappears and all slots follow the existing ordered teardown.
