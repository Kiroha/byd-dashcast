# DashCast 1.8.12-beta

Marks DiLink 3 and DiLink 5.0 as fully reverse-engineered: on those platforms the BYD APK Extraction button now says so and sends nothing.

> This is a tester pre-release from `switch-kotlin`. It is not merged into `main` and must not be marked as the repository's Latest release — `1.7.0` remains the stable one.

**Diagnostics-only.** Nothing in projection, Layout, mirror, HUD, hotspot or the daemon changes.

## Why

After several extractions from DiLink 3 and DiLink 5.0 — the container service, the OEM navigation, the reference `clusterdebug` app, and the full native firmware stack (including the projection library) — those two platforms are exhausted. Running the extraction again there would only re-upload material we already have and analysed.

## What changed

On **DiLink 3** and **DiLink 5.0**, the **BYD APK Extraction** button now shows *"Reverse engineering complete for this platform — nothing to collect or send"* and does not extract or upload anything.

Extraction stays fully available on the platforms we still need data from — **DiLink 5.1** (to confirm one native library is genuinely absent there) and **DiLink 4**. The distinction is made by Android version (DiLink 5.0 runs Android 12, DiLink 5.1 runs Android 13), chosen so that DiLink 5.1 is **never** blocked by mistake. If platform detection ever fails, the tool errs on the side of keeping extraction available.

## Compatibility

- Minimum Android remains API 28; target SDK 29; compile SDK 33.
- No production path touched; no daemon protocol change; no user-facing string changed (Diagnostics is English-only by project rule).
