# DashCast 1.9.0

**The first stable release since 1.7.0.** DashCast 1.9.0 consolidates the complete 1.8.x
series: more than 400 commits of projection, Layout, HUD, reporting, privacy, OTA, lifecycle,
build and release hardening.

The 1.8.48 release notes correctly stated at publication that it had not yet run in a car. The
published candidate was then tested successfully on one vehicle on 2026-09-03. The 1.9.0 binary
has not separately run in a car, but its application logic is unchanged: only the version metadata
(`639 / 1.9.0`) differs. The additional changes are tests, documentation and release-security
policy.

DashCast 1.9.0 is the stable successor to 1.7.0 and the recommended installation.

## What changed since 1.7.0

### Projection that owns its work

Projection start, stop and native-dashboard restore now run through a process-wide ordered queue.
A stop barrier cannot be overtaken by a later start, a callback from an older generation cannot
commit state over a newer session, and timeout recovery keeps the queue closed until the old daemon
is physically unable to return.

Task cleanup follows the same ownership rule. Every matching non-default task is considered,
evictions are serialized through their callbacks and watchdogs, and failed or stale operations
retain ownership for a later retry instead of declaring the cluster empty. Session resume and boot
cleanup no longer move a newly restored app back to the centre display.

The uid-2000 proxy protocol is now version 25. Its WHOAMI response includes a per-process nonce;
PID and instance markers are published atomically, repaired if removed, and checked again before a
hung daemon is killed. A replacement daemon is no longer mistaken for the process that timed out.

### Layouts, Split and input

Layout activation is transactional. DashCast commits the active layout only after all required
slots are accepted; partial activation rolls back, free zones survive a failed switch, and a slot
whose release was not acknowledged becomes retryable debt that blocks unsafe reuse. Ordinary
teardown, global purge and headless orchestrator replacement are serialized.

Split and fullscreen replacement state now follows verified physical tasks. A timeout or failed
eviction cannot silently advance the UI, late callbacks cannot overwrite a newer choice, and
stopped occupants are removed only after their stop is confirmed.

Cluster touch and keyboard ownership were hardened across daemon death and Activity recreation.
The tactile mirror reports Stop only after the daemon accepts it or its physical owner is proven
gone. Queued keyboard text and Enter operations retain their original generation and focused
cluster target, while stale touch probes and abandoned drafts are discarded.

Small-panel geometry is protected. Real cluster dimensions drive the resize editor, Cancel queues
the restore before leaving, and 1280x480 panels are not sent incompatible large-cluster geometry.

### HUD navigation

Google Maps and Waze guidance can drive the windshield HUD on supported DiLink 3 cars through the
BYD instrument CAN interface. The production path covers maneuver arrows, distance and next-road
text, while notification identity, source failover, removal and listener reconnects prevent stale
or missing guidance.

HUD state advances only after native delivery is known. Rejected CAN writes no longer update the
acknowledged frame, batches stop at the first rejected operation, activation keeps retry state
separate from session ownership, and stale guidance is cleared by the watchdog.

The feature remains platform-specific: windshield HUD injection is a DiLink 3 path, and current
production navigation sources are Google Maps and Waze notifications. Other navigation apps and
other HUD architectures are not claimed as supported by this release.

### Reporting and privacy

Diagnostic delivery now starts with explicit consent in every supported language. Text reports and
diagnostic bundles pass through shared redaction for vehicle identifiers, Wi-Fi names and hardware
addresses, account data and position-bearing formats. Screenshots remain visually unredacted and
are attached only after a separate per-send choice.

Upload credentials no longer live in the APK. The normal path uses an HTTPS relay; optional direct
Telegram and Azure credentials are provisioned on the device into encrypted preferences. Logs and
callback errors remove exact token/SAS values before they can enter a later report.

Completed reports have durable per-file ownership. Wizard state survives recreation and process
death across consent, bundling, delivery and retry; concurrent legacy and wizard reports cannot
overwrite one global record. Pruning protects in-flight, failed and ambiguous artifacts, and only
confirmed delivery or an explicit share clears the exact file handed off by that callback.

Ambiguous delivery remains distinct from failure. A timeout after the body may have reached the
relay does not trigger an automatic duplicate send; the file stays available for an explicit retry.
Multipart upload, relay request parsing, Azure block commits and response reads are bounded and
cancellable.

### OTA, lifecycle and recovery

OTA selection distinguishes stable and opt-in beta channels, compares versions semantically and
verifies the downloaded package, SHA-256 and signer before installation. The preferred uid-2000
path stages under `/data/local/tmp`; PackageInstaller remains the fallback where the daemon or ROM
cannot install silently. A durable marker lets either the install callback or package-replaced
receiver reopen DashCast without a duplicate launch.

Late callbacks throughout Main, HUD diagnostics, reports, IME and Split are tied to their owning
lifecycle or generation. Receivers, display listeners, handlers, executors, Parcels, Surfaces,
MotionEvents, streams and temporary artifacts were re-audited for symmetric teardown.

### Smaller, clearer and easier to support

The release APK is about 6.76 MB, compared with 17.67 MB for 1.7.0. The unreachable voice proof of
concept and its microphone permission were removed, and R8 resource shrinking now removes unused
library resources. The application retains thirteen locale sets: French as the base plus Arabic,
Belarusian, German, English, Spanish, Italian, Kazakh, Polish, Russian, Turkish, Ukrainian and
Uzbek translations, with corrected RTL behavior, labels and accessibility descriptions.

Diagnostics and bug reports contain more actionable daemon, display, task and delivery evidence,
while bounded logs and cleanup keep old captures from accumulating indefinitely.

## Release and audit quality

The 1.8.x series was repeatedly reviewed against reachable execution paths, then contradicted by
independent passes after each group of fixes. The final fresh audit found no confirmed application,
security, privacy or resource defect. It found one nondeterministic shell-timeout test fixture; the
fixture was corrected without changing production code.

- 738 JVM tests pass across 158 suites, with no failures, errors or skips.
- Android release lint reports no issues.
- Kotlin production/test compilation, detailed Javac deprecation compilation and Gradle
  configuration are clean.
- Release scanner and workflow-policy tests pass; relay tests pass; dependency audits report no
  vulnerability.
- Release builds are minified, resource-shrunk, non-debuggable and signed with the BYD-compatible
  AOSP platform certificate.
- The published APK is scanned before announcement and the matching R8 mapping is retained for
  field stack traces.

The retained Kotlin 2.4 / AGP 8.13.2 combination makes embedded R8 8.13.19 print metadata warnings
during shrinking. This is documented rather than hidden; changing Kotlin, R8 and AGP is deferred
until that set can be vehicle-qualified together.

## The road to 2.0.0: HUD first

With projection, Layouts, reporting and release safety stabilized, development toward 2.0.0 will
now focus on the HUD.

The direction is:

- strengthen Google Maps and Waze behavior for rare maneuvers, roundabouts and source transitions;
- investigate additional navigation sources, including OEM and regional apps, without claiming
  support until their data path is proven;
- improve roundabout exit/handedness and secondary-maneuver information where source data and BYD
  registers permit it;
- expand parked-car validation across DiLink 3 models and HUD firmware variants;
- explore a cluster-only guidance fallback for cars whose display architecture differs from the
  supported windshield HUD path;
- improve privacy-preserving HUD diagnostics so missing or rejected frames can be explained from a
  field report rather than guessed.

These are roadmap goals, not promises that every navigation app or BYD platform will work in 2.0.0.
Each new path will remain gated by measured device evidence.

## Upgrade and recovery

Install `DashCast-v1.9.0-release.apk` directly over any recent `com.byd.dashcast` build. Do not
uninstall first: uninstalling removes settings, consent and update state. Only users of the obsolete
pre-0.2 package name (`com.byd.myapp`) need the historical uninstall step.

This stable build uses versionCode `639`, so Android normally rejects 1.8.48 (`638`) as a downgrade.
If a vehicle-specific regression is found, keep 1.9.0 installed and send a diagnostic report with
the car model, DiLink generation and exact failed action. A recovery release must use a versionCode
greater than 639.

Never install a debug APK on a vehicle. Published DashCast releases are release variants only.
