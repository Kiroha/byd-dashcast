# DashCast 1.6.145-beta

Fixes the experimental **CarPlay** diagnostic tool so it no longer fights the head unit's own system-bar setting, and adds a read-only **Dump state** button to diagnose why a mirror app still shows black bands.

> This is a tester pre-release from `switch-kotlin`. It is not merged into `main` and must not be marked as the repository's Latest release.

The CarPlay tool first shipped in the **published `1.6.144-beta`** in a broken form. This fix was committed after that release was built, so `1.6.144-beta` reached testers with the clobbering version; installing `1.6.145-beta` is required to get the corrected tool and the new button.

## Highlights

- The CarPlay "hide bars" action no longer re-shows the top and bottom system bars. It used to overwrite the OEM "hide bars" setting; now it uses the same mechanism the OEM does.
- New read-only **Dump state** button captures display, window and surface geometry so we can tell whether remaining black bands are the CarPlay adapter's own fixed render size — which no Android setting can change.
- Fully reversible; diagnostic-only; no change to projection, mirroring, CAN, or the HUD.

## The bug

`policy_control` is a single global string, read by WindowManager and evaluated per-window against each window's package. On these head units the OEM "hide status/navigation bar" toggle stores its state in that string as a wildcard — `immersive.full=*` — which forces the bars hidden for every app.

The CarPlay tool's "fullscreen" button wrote `settings put global policy_control "immersive.full=<carplay-package>"`. That **overwrote** the whole string, replacing the wildcard `*` with a single package. Every window whose package was not that exact string — the launcher, and often the CarPlay mirror surface itself, whose window package frequently differs from the adapter package — no longer matched, so its forced-immersive state was cleared and **the bars reappeared globally**. CarPlay did not go fullscreen either. The reappearance is itself the proof that the OEM toggle's state lived in `policy_control`: overwriting it would have had no effect on the bars otherwise.

## The fix

- The action now hides the bars for **all** apps via the same `immersive.full=*` wildcard the OEM toggle uses, instead of scoping to one package. That matches the user's intent (bars hidden everywhere, CarPlay included) and no longer depends on guessing the mirror surface's exact package.
- If `policy_control` is already global-immersive (`isOemGlobalImmersive`: it already contains `immersive.full=*`, `immersive.full=apps`, or both `immersive.status=*` and `immersive.navigation=*`), the tool **leaves it untouched** and says so — a tester who already hid the bars via the OEM toggle sees no change, which is the correct behavior.
- The previous value is still read and saved before any write, and **Restore** replays it exactly, so the OEM setting is always recoverable.

## New: read-only Dump state

A fourth button dumps, in one pass, the OEM `policy_control` value, display-0 geometry, the focused CarPlay window, system-bar visibility, and — the decisive field — the AutoKit layer's `activeBuffer` and `crop` from SurfaceFlinger. It uses only `settings` and `dumpsys` (no `wm` verb), so it trips neither the display-0 guard nor the DiLink 2 resize guard, and it never writes anything.

## Honest verdict on "true fullscreen"

`policy_control` can only toggle the status and navigation bars; it cannot enlarge a mirror. A CarPlay/AutoKit adapter streams the phone at a **negotiated fixed resolution and aspect** into a surface. If that aspect differs from the panel's bar-free aspect, or the adapter letterboxes rather than stretches, black bands remain no matter how many bars are hidden — hiding them only frees the two bar strips. If **Dump state** shows the adapter's `activeBuffer` smaller than the panel, those bands are the adapter's own render size and can only be changed inside the CarPlay adapter app's resolution setting, not by DashCast. This release makes the tool stop breaking the OEM setting and gives us the data to confirm that limit; it does not claim to force a fixed-render mirror fullscreen.

## Compatibility and preserved behavior

- Minimum Android remains API 28; target SDK remains 29; compile SDK remains 33.
- No daemon protocol change, and no change to any CAN write, HUD rendering path, projection, mirroring, or Layout behavior.
- The change is confined to the CarPlay diagnostic panel in `DiagActivity`. The HUD imperial-distance and route-gate work from `1.6.144` is untouched.

## Suggested tester checks

- **CarPlay tab → ③ Hide system bars (all apps):** with CarPlay open, confirm the top and bottom bars are hidden and, crucially, that they no longer come *back*. If you had already hidden them via the OEM toggle, the tool should report "OEM already hides the bars globally" and change nothing.
- **CarPlay tab → ④ Restore previous state:** confirm it returns the head unit to exactly the bar state you had before.
- **CarPlay tab → ② Dump state:** with CarPlay open, run it and send the output — especially the `== policy_control ==` and `== surfaceflinger ==` sections. This tells us whether the remaining black bands are the AutoKit adapter's fixed render.
- Confirm the rest of the head unit is unaffected: classic projection, Layout teardown, mirror video, tactile input, OTA, Hotspot, HUD arrows, and voice.
