# DashCast 1.9.39-beta (678)

The DIAG menu adds **“QR développeur : relevé local”** (“QR developer: local capture”) to prepare analysis of the QR flow in BYD developer and diagnostic tools. This button collects current metadata needed before any attempt to access the tools; it does not validate the QR code or demonstrate a bypass.

- The closed profile `QR_DEVELOPER_DIAGNOSTIC_METADATA_V1` contains exactly **16 reads**: daemon identity, current Android user, clock, seven targeted properties (country, build type, Android API, OEM version, region, language, and time zone), then APK paths and metadata for two OEM packages (`com.byd.byddevelopmenttools`, `com.byd.authservice`) and the Android package `com.android.shell`.
- Progress shows the command, completed reads, and incomplete results. Denied, absent, truncated, or unknown outputs remain identified as such; an interruption preserves results already received. Transport uses only the already-connected PROXY Binder, with no startup, reconnection, or retry. A Binder call that is still pending blocks diagnostics until it returns.
- The ZIP `qr-diagnostic-001.zip`, plan, results, manifest, and integrity file are kept in DashCast's emulated internal storage at `Android/data/com.byd.dashcast/files/qr-diagnostic-exports/`. No SD or USB choice and no automatic upload are provided. To transfer it, use **“Fichiers du relevé → Lister / partager”** (“Files from capture → List / share”) and select the ZIP. If sharing is denied, the local file is retained.

These commands read system metadata. They do not open any OEM tool, enter a code, request a QR code or remote approval, or change the country, settings, permissions, DNS, or certificates. DashCast writes its capture files; the existing transport may create its temporary PID file. An APK's presence, declared components, and `User n` status lines do not prove launch permission. The current Android user is captured separately; results are not an atomic snapshot.

The existing 14-read context plan remains available to its current consumers. **“Export complet accessible”** (“Full accessible export”) keeps its current global collection; the new button does not scan the disk or start another full export.

Local checks cover fixed commands, the profile and counters, denials and interruptions, archives and their hashes, sessions, and sharing in an Android 29 fixture. The FileProvider mapping uses an explicitly modeled primary root in the fixture; this does not prove the BYD ROM's mount layout. On-vehicle validation remains to be done with the vehicle parked and DIAG visible.
