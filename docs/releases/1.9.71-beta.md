# 1.9.71-beta — Projection reliability with a manual recovery package

This prerelease keeps the RCC fixes, five resource carriers, recovery formats and
**daemon protocol 41** from **1.9.70-beta**, and integrates the reviewed projection
and ADAS orchestration improvements.

On DiLink 3, a display is not announced ready until the current activation command
16 completes successfully. Early display discovery keeps waiting; a failed command
16 cannot be replaced by success of command 35. Old queued stops, delayed callbacks
and service destruction are tied to their projection owner, so they cannot clear
a replacement session's geometry or ADAS state. Current Stop retains the native
`18 -> 0` sequence and full ADAS restoration. Already admitted operations remain
serialized and the existing typed-transaction recovery is preserved.

ADAS masking follows projection activation without its own close/reopen commands.
Complete passes are serialized, with one confirmation five seconds after success.
Full restoration starts the OEM service, waits one second, then sends 40 restore
frames followed by command 12, a 1,200-ms wait and command 53. The existing
firmware-restricted, off-by-default masking option and its whole-pane impact
(including distance and lane alerts) are unchanged. No new vehicle command,
privilege, transport or RCC apply/reset operation is introduced.

**Install the main APK manually over DashCast, without uninstalling or clearing
data. The app displays 1.9.71-beta / build 710.** Satellite pairing and guidance
protocols remain unchanged. The stable release remains 1.9.0.

## Ready-to-install recovery

`DashCast-Recovery-v1.9.70-build711.zip` contains the exact functional 1.9.70
source rebuilt as **1.9.71-rc1 / build 711**, signed with the same key. Extract
and install its APK over the beta if the optimizations fail; **do not uninstall
or erase settings**. The higher build allows replacement without a downgrade
flag. It is an auxiliary ZIP and is not selected as the OTA APK. The recovery
version ranks above this beta, so OTA will not immediately offer it again.
Future normal releases must use **versionCode >=712**.

Before replacement, park, stop projection and let full restoration finish through
the existing controls. APK installation does not restore the physical OEM state.
After recovery, open/reconnect and verify build 711 for **both persistent daemons**
using existing diagnostics; if freshness is not established, recovery is not
validated. The included recovery README gives the complete procedure.

## Validation boundary

Command completion and VirtualDisplay presence are host checks, not confirmation
of physical pixels or vehicle movement. Repeated launch, immediate Stop/restart,
application replacement, sleep/resume, native return and ADAS restoration remain
to be validated on the parked SEAL Android 10 / DiLink 3 / SX361 vehicle.
Isolation between consecutive live SurfaceDaemon previews is not established by
these tests. The exact verification results and artifact hashes are recorded below.

The original ARM-only APK overlay sequence could not be exercised on this host.
Recovery package identity/signature/version and unchanged persistent formats are
verified separately; actual installation, daemon freshness and physical OEM state
remain to be validated on the parked vehicle. After recovery build 711, the main
build 710 cannot be reinstalled; a later optimized release requires code >=712.
