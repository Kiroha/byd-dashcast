# DashCast 1.8.5-beta

Names the two privileged helpers apart, and stops one of them being handed the other's instructions.

> This is a tester pre-release from `switch-kotlin`. It is not merged into `main` and must not be marked as the repository's Latest release — `1.7.0` remains the stable one.

**Nothing changes for the driver.** This is a structural clarification plus one leak fix. Projection, Layout mode, mirroring, touch, HUD, hotspot and OTA all behave exactly as in 1.8.4. It is worth shipping because the confusion it removes had already produced two real defects.

## Two helpers, one name, two bugs

DashCast drives the cluster through **two** uid-2000 processes, and the code never said which does what:

- the **proxy daemon** *does* things — shell commands and one-shot verbs: activation, launching an app on the cluster, resizing, force-stopping. If it dies, you retry the command.
- the **surface daemon** *holds* things — the in-app preview mirror, and on the cluster the Layout slot windows with their virtual displays, plus touch injection. If it dies, the graphical state is gone and must be rebuilt.

It was called "MirrorDaemon", which hides the second half: it owns **cluster** surfaces, not just the preview. Twice, that misunderstanding led to the same mistake — sending the surface daemon's instructions to the proxy daemon's connection. The receiving side rejects them and the operation silently does nothing:

- **on stopping projection**, the surface daemon was never told to release its display token, so it kept compositing the cluster after the stop;
- **in the resize editor**, its live preview has never worked at all.

## What changed

The class is now called **SurfaceDaemon**, and the boundary is written down where both sides can find it.

More importantly than the class name: three different accessors were all called `getDaemonBinder()` and returned **two different helpers**. That is the name through which the mistake was actually made — someone copying a correct line into a new screen reaches for the identically-named method and lands on the bug. They are now `getProxyDaemonBinder()` and `getSurfaceDaemonBinder()`, so a missed call site is a compile error rather than a silent no-op.

The stop-projection leak is fixed. The duplicated service lookup in the Layout subsystem now goes through the single resolver, and the boundary documentation was corrected: the first version claimed a "single accessor" rule that was not true, and an auditor trusting it would have missed the whole Layout subsystem, the main preview and every touch.

**Every identity that crosses a process boundary or is persisted is byte-identical** — the service name, the interface descriptor, the transaction codes, both process names, the temporary-file paths, the broadcast, the bug-report section title and the log tag. A helper spawned by an older build keeps running across an app update and must still be recognised, and support triage greps historical reports. This was verified against the shipped APK's compiled code.

## Noise removed

Two fallbacks exist for when the surface daemon is unreachable: an in-app mirror and in-app touch injection. Across the whole bug-report archive they show **235 failures and zero successes** — an unprivileged app cannot hold the permission they need, which is precisely why the daemon exists.

They now run **once** per session and are then skipped, and report at warning level instead of error. The previous error line named a permission and read like a security regression; it sent several investigations down a false trail. They are **not** deleted: there is no formal proof the permission is denied, only 235 failures, and removing them would break any unit where they do work.

## One fix was deliberately reverted

Pointing the resize editor at the correct connection was implemented, reviewed, and **taken back out**.

The surface daemon holds exactly **one** mirror. While the editor's call was broken it touched nothing; made to work, it takes the mirror away from the main preview, and on closing the editor nothing gives it back — the main preview stays frozen on its last frame. Trading a preview nobody has ever had for a broken one is a bad deal.

The editor keeps today's behaviour, the wrong pairing is gone from the code, and the correct implementation is written down for whenever it is worth doing.

## Compatibility

- Minimum Android remains API 28; target SDK 29; compile SDK 33.
- **No daemon protocol change.** DiLink 3, 4 and 5 behave identically.
- No user-facing string changed.
