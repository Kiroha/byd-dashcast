# 1.9.63-beta — Android IVI RCC diagnostic

The RCC buttons now use a separate, researched Android IVI transport instead of
requiring the host `qtandroidnative` process to be visible from Android. That
requirement blocked the 14:52/14:55 tests before any OEM RCC load was sent.

Start with **Diag → Cluster Full Screen → Test RCC marker (recommended)**, while
parked. The existing marker and Full + night theme are unchanged. The new route
checks the exact installed Java bridge, default selection/UI contract, fixed
carrier hash and primary-user-0 storage mapping. It sends one load and separately
records native reply, owned-file ACK, queried selection and visual confirmation.
Native host identity and physical compatibility remain unknown.

RCC recovery remains available in the header, with guided confirmation popups.
The test also authorizes one bounded watchdog recovery request; its success must
be queried and visually confirmed. A restart does not guarantee recovery. RCC
and native mode tests keep separate persistent recovery blocks. No automatic
load, mode 16/18, generic fallback or replay after restart is added.

Build **702**, ProxyDaemon **35**: install over the current beta, then reconnect
the daemon. New confirmations and explanations are translated in all 13 locales.
Detailed bounded traces, including timeout phases, are included in **Send a
diagnostic report**. DashSat remains compatible; stable 1.9.0 is unchanged.

See the [Android IVI RCC contract](https://github.com/Kiroha/byd-dashcast/blob/v1.9.63-beta/docs/CLUSTER_ANDROID_IVI_RCC_TEST.md) for firmware
REA evidence, admission checks and recovery limits. Vehicle loading, telltales,
rendering/recovery and Telegram reception remain unvalidated.

Independent local verification passed: **1,811 JVM tests / 290 suites**, no
failures, errors or skips; debug and signed release builds; debug/release lint
with 0 errors and 29 warnings each. The optimized helper entry points and native
WebRTC bootstrap remain executable. The three packaged RCC files and all 72
previous mapping archives are unchanged. Local release-asset scanning passed.
