# DashCast 1.8.15-beta

HUD bench: show only the experimental `sendInfo2` tool, and make it actually conclusive.

> This is a tester pre-release from `switch-kotlin`. It is not merged into `main` and must not be marked as the repository's Latest release — `1.7.0` remains the stable one.

**Diagnostics-only.** Nothing in projection, Layout, mirror, hotspot or the production HUD/CAN path changes.

## Why

The HUD bench had four tools. Three of them — HUD-control confirmation, the raw-logcat recorder, and the CAN→HUD arrow bench — are already proven, so they only distract testers now. The fourth, the `sendInfo2` NaviInfo injection added in 1.8.13-beta, is the one still to validate. This release focuses the screen on that single tool — and fixes it so a tester result can be trusted, because an adversarial review found it could produce a false "nothing on HUD".

## What changed

The `HudDiagActivity` screen now shows **only Tool ④ (`sendInfo2` NaviInfo test)**; Tools ①–③ are hidden (their code paths are kept, just not exposed). Tool ④ itself is corrected on three points:

- **Adds the missing container nav-mode enable.** The OEM nav app calls `sendInfo(5,0,"")` on the AutoContainer service to switch the 1for2 container into navigation mode *before* pushing `sendInfo2(4, NaviInfo)`. The bench omitted it, so the container could accept every payload and render nothing. It is now sent once before the loop. This is an AutoContainer call, not a CAN write, so the tool still isolates `sendInfo2`.
- **Fixes the straight-ahead icon id.** `nextTurnIcon` in the FlatBuffer is the raw AMap `NEW_ICON` id (the OEM passes it un-remapped; the CAN-side `TurnIdMapToCAN` mapping does not apply here). Straight is `9`, not `1` — AMap id `1` means "none", which renders no arrow. Left (`2`) and right (`3`) were already correct.
- **Re-frames the target.** `sendInfo2(4, NaviInfo)` is the OEM's 1for2 **instrument-cluster** content path (`sendNaviInfoTo1for2Clster`), not a windshield-HUD channel — the windshield HUD is CAN-driven and already proven. The bench now asks the tester to watch **both the cluster and the windshield** and note **where** guidance appears, so a result can tell the two apart instead of conflating them.

## Compatibility

- Minimum Android remains API 28; target SDK 29; compile SDK 33.
- No production path touched; no daemon protocol change; no user-facing string changed (Diagnostics is English-only by project rule; the bench's own French hints are unchanged in spirit).
