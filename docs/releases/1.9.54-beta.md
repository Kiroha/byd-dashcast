# DashCast 1.9.54-beta

Fix Stop completion when returning to the original BYD cluster. DashCast previously reported
success after the native refresh, while the final cluster-size command was still waiting
three seconds in the background. ADAS restoration could overlap that later command and
leave the pane hidden. Stop now remains in progress until the final size command completes
on either transport, before releasing the existing ADAS recovery sequence.

Stop also cancels pending ADAS hiding before app eviction. A newer projection invalidates
the old Stop's remaining native commands and UI callbacks. Final-command errors and
interruptions complete recovery once; a callback failure cannot replay native closure or
deliver a second result. An operation already admitted can still finish after its owner
is replaced because the ownership check and native call are separate operations.

The existing native command sequence, ADAS restore frame counts and delays are unchanged;
this fix adds no OEM write command. ADAS pane control remains off by default and restricted
to the researched **BYD SEAL, Android 10 / DiLink 3, SX361** firmware
`6125f_1for2_USER_SIGN_SX361_202606100404_Q2700` and its exact captured Android fingerprint.
Other fingerprints remain refused. **Hiding the entire pane also hides its distance alerts
and lane warnings.** Command 53 still forces ancillary ADAS type 0 rather than restoring
a captured prior type; the manual restoration actions remain available.

**The corrected Stop sequence still requires parked-vehicle validation.** Native command
delivery does not confirm that the pane is visible or establish all firmware effects.
While parked on the researched firmware, test hide → Stop, then repeat after manual full
restoration and with closely spaced Stop requests. Confirm the ADAS pane returns under
its normal OEM conditions.

The passive **Inspect existing OEM ADAS logs** diagnostic from **1.9.53-beta** is retained
with **proxy protocol 30**. It remains a manual historical log inspection, without live
target or sensor-freshness guarantees. No satellite protocol or guidance listener changes
are included.

**Install the APK manually over the existing DashCast application without uninstalling.**
The application displays **1.9.54-beta · build 693**. The new build number makes normal
startup replace older persistent daemons. **DashSat 0.9.9-dev remains compatible and does
not need an update. 1.9.0 remains stable.**

Local validation passed: **1,653 JVM tests / 268 suites**, with no failures, errors or
skipped tests; debug and R8 release builds; the optimized APK's native WebRTC bootstrap
declaration check; and release lint with **0 errors and 20 warnings**. The 44 release-tool
fixtures passed. The matching R8 mapping is archived outside the build directory, and all
63 previously archived mapping files were preserved with verified SHA-256 hashes.

The final APK passed the release archive/secret scanner, package/version checks and
verification of the expected platform signing certificate. A warm software-emulator run
on Android 10 / API 29 x86_64 passed ART/TLS checks, including pinned WSS authentication
and reconnection. An initial cold run failed a diagnostic fixture's text-frame assertion,
and a separate optional peer/EGL lifecycle probe failed by timing out after 100 seconds
without completing. Their causes remain unconfirmed; full peer/EGL validation is not claimed.
Native initialization and **56 optimized-wrapper assertions**
passed using the final optimized DEX with the same pinned SDK's x86_64 library substituted
for the production ARM64 library. These checks do not validate the shipped ARM64 native
binary, hardware decoding or vehicle behavior.
