# DashCast 1.9.12-beta — Native guidance distances and Satellite pairing

DashCast keeps the temporary Satellite pairing code usable when its dialog is
hidden while the user switches to the Carlinkit interface. In 1.9.11-beta, a
dialog dismissal before the settings activity stopped could cancel the session
and close the pairing endpoint. Returning to DashCast then required a new code.

**Vehicle APK: versionName `1.9.12-beta`, versionCode `651`.** Install manually over the
existing DashCast application without uninstalling, preserving settings and
credentials. The application displays this version and build in Settings.
This prerelease continues the `feat/hud-2.0` publication branch; **1.9.0 remains
the stable release**. Build 651 is newer than builds 648, 649 and 650.

This build is compatible with DashCast Satellite
[0.2.0-dev](https://github.com/Kiroha/dashcast-satellite/releases/tag/v0.2.0-dev)
and [0.3.0-dev](https://github.com/Kiroha/dashcast-satellite/releases/tag/v0.3.0-dev).
The fix is in the vehicle application; no companion update is
required for this pairing correction.

## Pairing behavior

- In **Settings → Navigation guidance → Satellite device**, enable the receiver
  and choose **Pair a device** to obtain a temporary six-digit code.
- **Continue on Tbox** hides the code. Switch to CarPlay/Tbox manually and open
  Satellite's **Pair with DashCast** screen to enter it. Both devices must share
  the local network provided by the vehicle hotspot.
- Back, an outside tap and app switching also hide the dialog without cancelling
  the session. The status refresh does not reopen a deliberately hidden dialog.
- **Pair a device**, or returning to the settings page, shows the same code and
  remaining time. Neither action restarts the original two-minute countdown.
- **Cancel** still invalidates the code immediately. Expiry, receiver disable,
  token revocation, successful advanced profile copy, receiver service destruction
  and authenticated WSS connection retain their existing termination behavior.
- Codes remain in memory only. Process restart does not restore them. The wire
  protocol, authentication, attempt limits and LAN transport are unchanged.

The Continue action and instructions are localized in all thirteen app languages.

## Also included since 1.9.11-beta

Native instrument-cluster guidance now includes the formatted maneuver distance,
remaining route distance and remaining time alongside their numeric values
(`648d153e`). Missing values remain unavailable, and route stop clears the text.
This existing fix still needs confirmation of physical rendering on the vehicle;
it does not change Satellite source parsing or the protocol.

The native Diag bench and icon sweep send these formatted values as well. Test
normal guidance first without opening Diag. If distances are missing, run the
bench while parked: it sends a maneuver distance from 300 to 100 m, a route
distance of 1.2 km and a remaining time of 5 min. Complete its result dialog to
clear the test guidance. Real route totals depend on what the source supplies.

## Validation

The new regression cases reproduce the original dismissal failure before the
fix. They cover background pairing over real loopback sockets, dismissal during
the pause/stop transition, Back and outside dismissal, explicit cancellation,
screen recreation, returning to an existing code and expiry without renewal.

All **963 JVM tests in 180 suites** pass, with no failures, errors or skipped
tests, including the **22 pairing server/lifecycle tests**. The **10 JavaScript
receiver scenarios** pass. Release lint reports **zero errors and warnings**,
and **35 release-scanner tests** pass. Debug assembly and signed release assembly
succeed. Pairing labels are present in all thirteen
locales. The graph is updated; its existing parser warnings remain.

The prepared APK and R8 mapping match the final build byte for byte. The APK
passes the trusted default-branch scanner for package/version identity,
non-debuggable release configuration, expected signature and credential patterns.
**Vehicle validation remains pending.** Automated lifecycle tests do not emulate
every OEM CarPlay transition or establish hotspot reachability on the car.

On the Carlinkit Tbox Ultra 1 / Android 15:

1. Connect to the vehicle hotspot. In DashCast, open **Pair a device**, note the
   code and choose **Continue on Tbox**. Switch to CarPlay and complete pairing
   from Satellite before the countdown expires.
2. In a separate uncompleted pairing window, return to DashCast before expiry:
   the same code must appear with less time remaining. Repeat with Back and the
   vehicle's normal app switcher.
3. Check that Cancel and expiry invalidate the code, then confirm Satellite's
   authenticated connection and valid guidance on the vehicle after pairing.

The APK is a non-debuggable release signed with the existing DashCast certificate.
