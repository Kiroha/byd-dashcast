# DashCast 1.6.129-beta

Reliable Layout-mode projection teardown after the 1.6.128 hardening release.

> This is a tester pre-release from `switch-kotlin`. It is not merged into `main` and is not the repository's Latest release.

## Highlights

- Layout tasks now return to display 0 through a DiLink 3-compatible stack move when the direct task API is unavailable.
- Every Layout package is cleaned up in a strict move -> remove task -> verified force-stop -> release slot sequence.
- Force-stop success now means that process death was verified; surviving PIDs are escalated with `kill -9` and checked again.
- Native BYD/original-cluster restoration waits for the complete Layout teardown instead of racing it.

## Full changelog since 1.6.128-beta

### Field evidence and root cause

- Analysed `INC-20260716-215316` and `INC-20260716-215226`, captured while stopping a Layout containing Waze and NewPipe.
- Confirmed that the Layout stop command reached `FissionOrchestrator.stopAll()` and that both applications were eventually force-stopped.
- Confirmed that both task moves failed before the fix because this DiLink 3 ROM does not expose a compatible `moveTaskToDisplay(int,int)` method.
- The same framework method inventory showed that `moveStackToDisplay(int,int)` is available on the affected ROM.
- The previous teardown released virtual-display slots and dispatched asynchronous shell force-stops without awaiting their callbacks. MainActivity continued native-cluster restoration at the same time, so task cleanup, slot destruction, and projection shutdown raced each other.
- The final incident snapshots showed no surviving Waze/NewPipe process, but only after slot destruction had hidden the failed moves. That outcome did not guarantee clean task affinity or a clean next launch.

### DiLink-compatible task movement

- Added a compatibility move that first tries the existing direct task API.
- When the direct API fails, the daemon locates the task's containing stack/root task and uses:
  - `moveStackToDisplay(int,int)` on Android 10/DiLink 3;
  - `moveRootTaskToDisplay(int,int)` on newer framework variants.
- A task already on display 0 is treated as a successful no-op.
- Direct and fallback diagnostics are normalized into one explicit success/error result.
- `FissionClient.moveToDisplay0()` now returns the daemon result to the orchestrator instead of logging and discarding it.
- The existing Fission Binder transaction and wire format are preserved; no proxy protocol bump is required.

### Ordered Layout teardown

- Added a small, testable teardown plan that processes every Layout package serially.
- The required order for each package is now:
  1. move the task to display 0;
  2. remove its task and force-stop the package;
  3. wait for process-death verification;
  4. release the package's virtual-display slot;
  5. continue with the next package.
- A failure in one step is logged without skipping force-stop or the remaining packages.
- The package snapshot is captured on the serialized Fission worker after previously queued slot operations. A stop requested during Layout startup can no longer observe an empty pre-launch snapshot and allow an app to appear after restoration.
- When slot pre-creation is enabled, virtual displays remain allocated as before, while their applications are still moved and force-stopped.
- Mirror cleanup and the final completion callback run only after every package has been processed.

### Verified task and process cleanup

- The typed cleanup path now performs `findTaskIdForPackage` -> `removeTask` -> `forceStopPackage(package, user 0)`.
- After force-stop, DashCast queries the daemon for surviving package PIDs.
- If PIDs remain, DashCast sends `kill -9`, waits briefly, and verifies the package again.
- The legacy ADB fallback now enforces the same postcondition with `pidof`, including escalation and a second PID check.
- `AdbLocalClient.forceStopApp()` reports success only after process death is confirmed. Verification failures are surfaced through the existing error callback instead of being reported as successful cleanup.
- The shared verification also hardens normal-mode callers that use the same force-stop helper.

### Restoration ordering

- Added completion-aware `stopAll(onComplete)` and `stopAutoOrchestrator(onComplete)` entry points.
- `MainActivity.restoreBydDashboard()` now waits for Layout teardown before moving or evicting classic-session packages, sending BYD restore commands, and calling `stopProjectionNoAdb()`.
- `MainActivity.originCluster()` follows the same ordering before restoring the configured original cluster mode.
- The old no-callback entry points remain available for existing callers such as the Layout activity.

### Regression coverage

- Added JVM coverage proving that a failed direct move invokes the stack fallback exactly once.
- Added coverage proving that a successful direct move does not invoke the fallback.
- Covered failed direct and stack strategies, plus the already-on-display-0 result.
- Covered the Waze/NewPipe operation order and completion after both packages.
- Covered pre-created-slot preservation, per-package failure isolation, and unverified force-stop reporting before slot release.

### Compatibility and rollback

- Minimum Android version remains API 28; target SDK behavior remains unchanged.
- No permission, dependency, manifest, resource, or user-facing string was added.
- No Binder transaction number or proxy protocol version changed.
- Non-Layout projection behavior is unchanged apart from the stronger shared force-stop success contract.
- Functional fix commit: `7778278` (`fix(fission): serialize layout projection teardown`).
- Release metadata commit: `fb71998` (`chore(release): bump to 1.6.129-beta`).

## Suggested tester checks

- Start a favorite Layout containing Waze and NewPipe, then stop projection from the main DashCast screen.
- Confirm that the native BYD cluster appears only after both Layout applications have been cleaned up.
- Confirm that neither application survives in the process list or leaves a ghost task in Recents.
- Relaunch Waze and NewPipe on the head unit and verify that each opens cleanly on display 0 rather than a stale hidden virtual display.
- Repeat with Layout slot pre-creation enabled and disabled.
- Repeat stop/start several times to check that no stale slot, process, or task accumulates.
