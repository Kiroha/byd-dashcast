# 1.9.61-beta — Test the native BYD Full mode

Diagnostic → Cluster Full Screen now separates **Mode Full natif BYD** from
**Ressources RCC**. **Tester le mode Full natif BYD** requests the researched native
mode with one fixed command 16; **Demander le retour BYD** separately requests normal
mode with command 18. This does not load a theme or remove the OEM telltales.

The test waits a quiet interval, uses the pinned Java OEM service once, and records
admission, helper/Java identity, attempted delivery, native result and cleanup.
Zero does not prove Qt delivery, animation acknowledgment or a rendered Full layout.
No debug/QML acknowledgment is forced and no command is replayed automatically.

Operational debt and recovery are separate from RCC loading. Projection/ADAS and
RCC work are excluded during the test. A manual return and fresh normal-display
observation close the operational debt; exact previous-mode restoration and physical
return remain unverified. The app and daemon retain negative admission gates across
restarts. The normal request is available in the fixed diagnostic header.

**Envoyer un rapport de diagnostic** is at the top of the cluster page. Reports
include bounded detailed stage traces and separate essential 16/18 receipts, including
partial helper output after a timeout. New controls and explanations are translated
in all 13 locales; the old theme test is explicitly labeled as RCC loading.

Build 700; ProxyDaemon protocol 34. Install over the current app without uninstalling,
then explicitly reconnect the updated daemon. DashSat remains compatible. Stable
1.9.0 is unchanged. Positive DiLink 3 / API 29, exact researched Java APK and parked/
firmware assertions are required. No vehicle command or deployment was performed
during development. See [the diagnostic contract](https://github.com/Kiroha/byd-dashcast/blob/v1.9.61-beta/docs/CLUSTER_NATIVE_FULL_DIAGNOSTIC.md).

Local verification passed: **1,771 JVM tests across 286 suites**, with no failures,
errors or skipped tests; debug and signed release builds; debug/release lint with
**0 errors and 30 warnings** each. The native WebRTC bootstrap check passes.
The three packaged RCC assets are byte-identical to the preceding beta. The new
mapping is archived and all 70 prior mapping archives retain their hashes. The
staged APK passes archive/credential-pattern, package/version and signer checks.
Physical cluster rendering, OEM telltale visibility, successful physical return and
Telegram receipt on the car remain untested.
