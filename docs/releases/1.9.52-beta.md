# DashCast 1.9.52-beta

Improve Waze recovery after an ACC OFF/ON cycle. DashCast now checks the actual task
location before trusting a remembered cluster session: a confirmed missing task can be
launched again, and a task found on another display can be brought back without killing
its navigation. Unknown task state preserves the session. Late polling or launch results
cannot overwrite a newer selection or projection session.

Add one narrowly gated recovery attempt for the empty split-screen primary stack seen
in the October 20 Waze report. After the known framework exception and a confirmed missing
task, DashCast can reuse that empty stack on the original cluster display. Recovery requires
Android 10 / API 29, the exact captured SX361 fingerprint, an eligible launcher activity,
native split-screen support and fresh, readable display/task metadata. It adds no extra
force-stop, requires verified placement on the original display and stack, and preserves
that placement without subsequent automatic resizing or movement. Uncertain placement
stops destructive fallback attempts.

Proxy protocol 29 carries a validity token for each eligible request, so a canceled or
superseded request is checked again immediately before recovery. Missing or unreadable
validity disables this additional recovery. Direct layout launches do not use it. The
final check and Android launch remain separate operations; a launch already admitted can
still complete after cancellation.

Add **Diag → ADAS targets (read-only snapshot)**. Each manual capture requires a stationary
test acknowledgment and reads a fixed list of candidate properties through the connected
daemon. There is no automatic capture when opening the screen or generating a bug report.
The latest retained snapshot and its outcomes are included in normal and fallback bug
reports. Optional schematic points use an explicitly selected decoder hypothesis and are
not verified live surroundings or a driving aid. This diagnostic does not change ADAS
settings or extend the existing ADAS pane masking behavior.

**The new Waze recovery and ADAS diagnostic still require parked-vehicle validation.**
The Waze recovery was checked against the matching SX361 framework, but static analysis
and local tests do not establish reliable ACC OFF/ON behavior on the car. ADAS property
access, decoding and data freshness also remain unverified on the vehicle.

Local validation passed: **1,632 JVM tests / 264 suites**, with no failures, errors or
skipped tests; debug and R8 release builds; the optimized APK's native WebRTC bootstrap
declaration check; and release lint with **0 errors and 20 warnings**. The release's
matching R8 mapping is archived independently of the build directory.

Independent release checks passed **44 tooling tests**: 35 release-scanner fixtures and
9 native-bootstrap fixtures. The final APK also passed ART/TLS checks on a stock Android
10 / API 29 ARM64 emulator, including pinned WSS authentication and reconnection. Its
production ARM64 WebRTC library passed JNI bootstrap, peer/EGL lifecycle and **63 optimized
wrapper assertions**, without substituting another ABI. These emulator checks do not
validate hardware video decoding or vehicle behavior.
