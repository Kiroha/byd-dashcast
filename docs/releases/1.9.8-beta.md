# DashCast 1.9.8-beta — Navigation recovery and Maps diagnostics

Improve background navigation recovery and instrument-cluster channel activation,
and collect the evidence needed for Maps maneuvers whose direction is absent from
notification text. This follows the October 9 SEAL and SEAL U DM-i reports.

**Pre-release from `feat/hud-2.0`, versionCode 647. `1.9.0` remains the stable release.**
This exact build still needs vehicle validation. A successful native send does not
prove that either display rendered the guidance.

## Installation

**Manual installation is recommended for this validation and required if the
installed version is 1.9.4-beta or older.** Download
`DashCast-v1.9.8-beta-release.apk` and install it over the existing application.
**Do not uninstall first:** keep settings and diagnostic pairing. Perform the
installation while parked.

Versions 1.9.5-beta and newer contain the Android 10 OTA certificate correction.
Their end-to-end vehicle installation still needs confirmation; if downloading
does not start the installer, install the APK manually.

## Changes

- **Background listener recovery:** the existing keeper checks the navigation
  listener at service startup and on its heartbeat. With guidance enabled and
  notification access granted, it requests reconnection and waits for Android's
  actual connection callback. Unconfirmed requests retry after 30, 60, 120 and
  then 300 seconds. It resumes the existing scan of active navigation notifications
  on reconnection. No route is required to keep a healthy listener connected.
- **Instrument-cluster activation recovery:** the activation cache follows the
  live proxy. Send errors invalidate it; the next fresh instruction reactivates
  navigation mode. A proxy replacement during delivery permits one reactivation
  and resend of that fresh frame. Activation results are retained in the report
  journal. This covers reproduced cache failures; it does not yet identify which
  operation made the SEAL U DM-i bench workaround succeed.
- **Correct Maps Morphe report status:** the report form uses the same exact
  official/ReVanced/Morphe package filter as guidance. An undecodable Morphe
  notification can be reported as a parse failure instead of absent navigation.
  The existing recent-status window remains; counters expose newer rejections.
- **Navigation evidence in reports:** bug reports include listener supervision,
  effective output choices and pipeline counters. HUD bench archives include
  `06_navigation.txt` with the same snapshot and the DashCast journal. Rejection
  diagnostics retain reason, icon resource and text lengths without route text;
  repeated journal entries are bounded. Counters reset with the app process.
- **Explicit Maps icon export:** **Diag → Export Maps icons** captures the available
  small/large icons from up to four active Maps navigation notifications. PNGs are
  bounded to 256 pixels per dimension. The manifest includes version, source,
  timestamps and icon metadata without notification text. Capture requires
  confirmation, creates a local ZIP, and offers keeping it, system sharing or
  consented support submission. URI icons are not opened. This new interface is
  translated into all **13 app languages**.

The icon export prepares a real-image corpus. **Automatic recognition of maneuvers
present only in a large icon is not implemented in this release.** A notification
without a recognized maneuver can still be rejected, even after a successful bench.
Incomplete instructions are not guessed as straight ahead.

Independent HUD/cluster settings remain available. Cluster-only uses AutoContainer
without CAN/HUD activation or OEM Amap broadcasts. The SOME/IP transport remains
inactive; this beta does not establish support for a new vehicle profile.

## Vehicle test

1. Install over the current version, retain notification access, and select the
   outputs that match the vehicle. **SEAL without HUD:** enable navigation guidance,
   disable **HUD**, and enable **Instrument cluster**.
2. After a head-unit restart or the normal ignition-off/on cycle, start an itinerary
   in Maps with DashCast in the background. **For this first test, do not open Diag
   or run a HUD bench beforehand.** Check a maneuver currently recognized, such as
   a U-turn, as well as distance changes and clearing at route end.
3. If guidance is missing, capture a bug report while the route is active and
   describe separately what appeared on the cluster and windshield HUD. Capture
   this report before any bench workaround; if a bench restores guidance, provide
   a second report afterward.
4. For missing Maps maneuvers, use **Diag → Export Maps icons** while the relevant
   instruction is active. Send the ZIP if desired and describe the actual icon
   shown by Maps. Repeat for different directions and roundabout exits.

Background recovery, physical wake-up behavior and rendering after a cold start
remain field checks. An Android force-stop can prevent automatic app restart.
A silent OEM reset that retains the same proxy and returns no error is not detected
by the activation cache alone. The image export itself issues no OEM guidance or
activation command.

## Validation and assets

skips; release lint reports **0 issues**. Regression coverage exercises listener
lifecycle/backoff, proxy replacement and bounded recovery, Morphe reporting,
pipeline counters, and bounded PNG exports that preserve the source bitmap.
These are offline checks, not a vehicle rendering result.
