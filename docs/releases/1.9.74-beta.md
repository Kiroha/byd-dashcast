# 1.9.74-beta — Unified cluster startup and fullscreen mirror

**Install the signed release APK over DashCast without uninstalling or clearing
app data. This prerelease is version 1.9.74-beta / build 714.** It retains the
cluster cold-start and manual dashboard recovery fixes from 1.9.73-beta, with
ProxyDaemon protocol 43. The stable release remains 1.9.0.

## One startup choice

Cluster startup now has two independent settings:

- **Projection at startup** activates the cluster projection without launching
  applications when no application startup source is selected.
- **Applications at startup** selects exactly one source: no applications, the
  last real projection session, a chosen application, or a chosen layout.

The last-session choice remembers a single application, split-screen applications
and their bounds, or the actual multi-application layout. A fixed application or
layout deliberately replaces last-session replay; it is not combined with it.
Deleted or unavailable fixed targets do not silently select another source.
An independently requested projection-only startup remains available.

Long-press an application and choose the startup action to open the central
selector with that application preselected. No preference changes until the
selection is confirmed. The old per-application and favorite-layout automatic
switches no longer act as competing startup rules. Layout favorites still work
for manual use. Returning from Settings or opening DashCast does not itself
launch startup applications.

Migration is conservative: an enabled previous restore setting becomes last-session
replay; a disabled restore setting becomes no applications. An old per-app or
favorite choice cannot silently enable vehicle-boot application launching.

## Restoration and mirror reliability

Startup has one projection owner and waits for both a resolved display and the
successful terminal activation command before launching applications. Repeated
ACC-on events do not relaunch an already active session. Stop, disconnect and
source changes reject obsolete callbacks. Temporary fixed-application launch
failures preserve the last real session rather than saving an unconfirmed launch.

The floating remote is now a rounded dark control with a vector icon, accessible
actions, bounded dragging and a remembered position. Tapping it opens the tactile
mirror in fullscreen, including when the activity must first adopt a headless
projection. Back and the existing exit control leave fullscreen.

The new startup choices, summaries and accessibility labels are translated into
all 13 supported application languages.

## ADAS and vehicle validation

The existing guarded ADAS behavior is unchanged. Projection-only startup does not
force ADAS masking on an empty projection: masking still requires the existing
verified projected-application and platform conditions. This release does not
add movement detection or establish that the vehicle is parked.

Complete validation on a stationary supported vehicle remains required for actual
boot/ACC sleep and wake, physical cluster output, OEM indications, overlay
placement and fullscreen touch alignment. Host tests do not establish firmware
compatibility or physical rendering. No vehicle commands were executed during
development or release preparation.

The manual native-dashboard restrictions and recovery boundaries from 1.9.73-beta
still apply. Restore and visually verify the factory display before replacing an
APK after using that experimental profile. Downgrading older diagnostic journals
remains unsupported; do not clear data or delete recovery state to bypass it.
