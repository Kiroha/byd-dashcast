# Physical cluster marker experiment

DIAG now contains **Change physical cluster — passive TEST marker (experimental)**, separate from the existing local fixture verification. This sends a real type-8 OEM RCC selection request when every gate passes. It does not implement the supplied concept dashboard or establish total/exclusive cluster control. No vehicle test, deployment or hardware validation was performed during development.

The separate [native full-surface test theme](CLUSTER_FULL_SURFACE_TEST.md) uses
the same recovery lane with a distinct compiled profile and hash at protocol 32.
The marker asset and its protocol-31 start/observation wire format remain unchanged.

Use the existing controls to explicitly connect the current ProxyDaemon first (protocol 31). The primary mechanism is that pinned daemon and an owned `app_process64` helper under its existing UID, normally shell 2000. There is no automatic daemon bootstrap/reconnect, UID switch, namespace fallback, permission alteration, generic shell mutation, replay or SurfaceDaemon modification. The OEM Java/native permission checks remain effective. Before every helper operation the installed Java APK is hashed through its running process namespace, its PackageManager UID/source path and mapped APK device/inode are bound, and PID/start/mount identity is pinned. Callback delivery requires UID 1000 and the exact callback descriptor. A positive Binder caller PID must match the pinned process; PID 0 is accepted only for the researched oneway callback ABI, while that process remains identified. Unknown/inaccessible Java identity refuses admission.

The load dialog requires the tester's parked assertion; this is not movement detection. Restore remains above the scrolling controls, outside the shared diagnostic busy gate, and uses a separate UI request lane. Its action cancels a not-yet-transmitted local start and requests serialized server restoration after an already-begun operation. A dialog, cancellation, timeout or missing marker is never evidence that physical pixels were restored.

Before staging, the daemon identifies one readable live `qtandroidnative`, records PID/start time/mount namespace, binds its executable and mapped library device/inodes to exact paths, and hashes the original renderer, Qt engine, business libraries, both stock theme RCCs and common translation RCC through that process's `/proc/PID/root`. Expected bytes are bound to the extracted SX326 firmware **13.1.33.2602030.1**. Unreadable/mismatching files, missing maps, changed renderer, inaccessible carrier directory, unavailable API, denied callback registration, missing native result or non-default/ambiguous baseline query refuse the test. The user supplied the firmware version; the live target has not been observed here.

The fixed 2,141,359-byte carrier contains the 84 original stock translation resources, preserving stored and decoded bytes and locale metadata, plus the two original OEM root QML files with one bounded passive marker insertion. All original functions, children, bindings, transforms and warning code bytes remain. The marker has no input, timer, backend call or animation; its z=-1 is below default-z functional children and warning layers. Visual preservation is unvalidated. Stock opaque content can hide it; absence is **inconclusive**. Build it only from the identity-matched corpus with `tools/cluster/build_live_marker.py`; `tools/cluster/test_live_marker.py` independently checks resource bytes and removal of the insertion against the known original hashes. Neither executes Qt/QML.

The app streams an asset into its own temporary external-files source and passes a read-only descriptor. The daemon rejects non-regular/empty/oversized sources, journals before creating an exclusively named nonce carrier, syncs ownership and content, verifies its fixed hash, and sends at most one load. It never overwrites an existing OEM/user file. Partial cleanup requires a successful exclusive creation and the same owner/device/inode, not just a matching pathname. The journal is synced before native admission.

Each helper has a self deadline, a parent authorization pipe and a durable PID/start/token handshake before OEM calls. Parent death before GO cannot admit a request. After GO, helper/daemon death or a lost response still leaves remote completion **UNKNOWN**. A recovered daemon never replays a load. It verifies/reaps a positively identified previous helper before any newer native operation; corrupt journals or unverified identities remain quarantined. Killing a helper does not cancel an OEM request already admitted. Deadlines use elapsed time including suspend and fire after wake; they are not an independent hardware watchdog and do not survive daemon death as a timer.

Raw native integers and bounded raw asynchronous responses are retained in daemon status. Transmitted, configuration ACK4, registration ACK2, selected-path query and tester-observed marker are different evidence. Mutation responses are bound to the owned nonce path; selection queries are accepted after the helper's query boundary. ACK2 is not guaranteed by the OEM path. Explicit user observation buttons record what the tester saw; they do not detect pixels automatically.

The app records bounded status receipts and local failures in an app-private historical cache, including refusals before any OEM exchange when `raw` is empty. Receipt capture does not depend on the Diag screen still being alive. Stable state/detail/identity changes are recorded; unchanged polls and countdown changes do not refresh receipt time or flood the cache. Raw response payloads are represented only by a SHA-256 change digest. Retention is at most 24 events and 48 KiB, with individual text limits; SharedPreferences writes are asynchronous and best effort, so immediate process death may lose the newest entries. Normal and fallback bug reports read this local cache without requesting cluster status, reconnecting or sending any new cluster command. Each entry has its historical receipt timestamp and age; current physical state and movement remain UNKNOWN. A local Binder reference token identifies only an app-local connection reference, never a verified daemon process. The original status `identity` field describes the renderer and is labelled accordingly. Empty/corrupt/unavailable cache means NOT_RECORDED/UNKNOWN, never a successful test or restoration. This evidence never controls admission, busy ownership, acknowledgements, recovery or success.

The daemon requests restoration after 30 seconds, including app death while the daemon remains alive. Before restoring it queries the current selection and refuses to overwrite a different actor's custom selection. Restore uses the discovered OEM default request (`cmd=5,intParam1=1`) followed by a query; reported default selection is not physical recovery proof. Only the owned carrier is eligible for cleanup, after known load settlement, queried default, a reaped helper and no uncertain completion. Its removal is separate from visual recovery: the session remains blocked until the tester confirms the OEM display. Missing quiescence or lost IPC means quarantine and no new test. A default query while an unresolved load may arrive later is not restoration evidence; late load remains possible. A retained carrier in quarantine is intentional evidence/recovery state, not an assured rollback failure or success. Removing a file does not unmap an RCC already registered.

RCC selection writes the OEM `translate_rcc_path` configuration through `/collect2/byd_datasource_config.xml`. Reboot alone is **not** an assured rollback. Missing/invalid-file fallback exists in the researched code, but its runtime behavior and filesystem persistence remain unvalidated. Inspect the physical instruments and use the central Restore control; an unresolved quarantine requires investigation before another experiment, not a forced new load.

Development checks are local JVM/resource/build checks only. They are not the requested physical vehicle test. The button is capable of making the real request on a matching, admitted runtime, and reports concrete prerequisite failures otherwise. No concept-dashboard replacement is claimed.
